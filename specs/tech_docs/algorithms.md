# 核心处理算法与任务工作流

> 本文描述 2026-09-30 工作树的代码路径。它记录“现有实现如何判断”，不把原型阈值写成永远不变的产品规则。总览见[架构](../ARCHITECTURE.md)，人物识别的详细算法见[说话人和全局人物](speaker-identity.md)。源码含未提交的 Batch 6 修改；安装版与质量验收状态见 [plan.md](../../plan.md)。

## 1. 两层音频处理与虚拟事件

真实轴由 `source + recording_session + sample_start + [started_ms, ended_ms)` 组成。麦克风和电脑声音各自连续推进，可以并行。原声封块及粗转是**发生过什么**；候选、命名事件、未整理块是**如何组织它**。候选不是事件，精转任务也不是事件。任何处理都不能倒改采集时钟或把两段之间的静默时间抹掉。

```text
设备回调 → 真实时刻/来源 → 约 5 秒封块 → 原声落盘
                                    ↘ 保留判定
                                    ↘ VAD → 本地粗转 → 候选区间
                                                       ↘ LLM 拟合 → 命名事件 → ASR
未被命名事件覆盖的有效时间轴 ──────────────────────────→ 未整理块
人工圈选连续区间 ───────────────────────────────────→ 独立未命名精转事件 → ASR
```

### 不变量

- 原声音频有文件内相对偏移；产品对象有真实 UTC 毫秒。供应商相对时间只有通过任务输入的真实时间映射后才能入库。
- 某时间段没有文件可以是**确认静音/无人声而省写**，也可以是**采集失败缺口**；两者分开记录。无文本不等于无人声。
- 事件范围可以包含大量没有句子的静默间隔。一场两小时会议应是一个大块虚拟范围，而非若干发言片段拼凑的列表。
- LLM 的密度/语义决定是否形成命名事件和自动精转，不决定底层原声留存。手动请求可直接走 ASR，不依赖新的 LLM 判断。

## 2. 采集、封块与时钟

每路录音由 [`record.rs`](../../crates/hear-core/src/record.rs) 独立组装。回调带单调时刻和墙钟锚点；核心把输入混为单声道、重采样到 48 kHz，再按 `BLOCK_FRAMES = 48_000 × 5` 封成约五秒 Opus 块。连续文件封口、媒体持久化和 SQLite 清单使用固定顺序；回调队列溢出、采样率突变、顺序倒退、长时间无回调等都会中止该来源并记录缺口，不继续声称完整录制。

`ClockAnchor` 将来源内采样位置映射到真实毫秒。中断后另起 session；大于 250 ms 的回调空档被写成 `callback_gap`，首包明显晚于启动意图写 `source_start_gap`。来源失败的重试由 [`capture_supervisor`](../../crates/hear-core/src/main.rs) 管理，两路独立；睡眠/唤醒与设备异常不会把采样序号和文件时长硬接成“连续音频”。当前重试参数和来源实现应直接看代码，仍需真实故障回归。

## 3. 独立声音保留判断

[`retention.rs`](../../crates/hear-core/src/retention.rs) 是单独策略边界，不读取 LLM 事件价值或粗转文本质量。**当前工作树含尚未安装版验收的 `pending_vad_v2` 候选：**

1. 全零数字静音直接记 `discard_digital_silence_v1`，不编码原声；非零音频先封口持久化，记 `pending_vad_v2`。
2. VAD 回写该封块的 `speech_active` 并先提交区间 `coarse_jobs`，策略在同一事务查看当前块与最多 6 个连续已完成且保留媒体的前块。有人声检测、重叠粗转任务或已发表句段则转为 `retain_speech_v2`，不等待识别文字。
3. 确认无人声时先在数据库撤销媒体引用、持久登记 `media_deletion_jobs`，再由后台删物理文件，状态为 `discard_no_speech_v2`。worker 的 `speech_pending` 表示仍有未结束话语；此时前块即使尚未检测到人声也延后负判断，完整区间发布后再裁决。当前边界块在未 flush 时仍暂缓决定，避免跨块句首被提前回收。
4. 同一回复可以关闭上一话语并开始下一话语。已发布 `coarse_jobs` 的样本终点允许其之前的连续前块结束等待，不把 `speech_pending=true` 误当成所有前块都仍未定。
5. 已完成块若已有 7 个更晚的已完成块（已退出 6 块回看），或来源已关闭、journal 已排空且无本地待分析块，旧的 `pending_vad_v2` 已无可等待的上下文。maintenance 每批最多 128 个改为 `retain_unresolved_v2`：只保留原声，不改 `speech_active`，不排物理删除；现有 ASR 规划包含所有保留媒体。这是失去判定依据后的保守留存，可能多保留噪声，不能称为检测到了语音。未完成分析、未排空 journal 与仍在上下文内的活动尾块继续等待。
6. 策略升级不回溯删除旧版已保留原声。

这段代码回应了“不保留无说话环境噪音”的产品选择，但**实际误删/误留率、弱语音和安装版落盘效果尚未验收**。不能仅凭单元测试宣布全天声音保留正确。

## 4. VAD 与本地粗转录

[`analysis_loop`](../../crates/hear-core/src/main.rs) 从已封口待分析块读取音频，经 [`AnalysisClient`](../../crates/hear-core/src/analysis.rs) 逐块重采样到 16 kHz，按来源、session 与采样号送给轻量 `hear-worker vad`。**Silero VAD** 模型与阈值不变，仍以 512 样本小窗输入、约 20 秒主动 flush。非连续坐标或新 session 重建对应状态；核心分别为两条来源回放最近最多 6 个连续已完成、仍保留媒体的人声或 `pending_vad_v2` 尾块，不能用“进程已重启”替代另一条流的恢复。

VAD 主动 flush 后，底层可能排出 `n=0` 的空片段；worker 在 drain 时消费它但不作为语音区间返回。核心继续拒绝非正时长区间。`vad_nonempty_regions_v1` 复用现有迁移机制，仅一次将仍保留媒体、处于 `pending_vad_v2` 的失败本地块重新入队并清零本地尝试数；之后仍按 3 次上限失败，不重置任何云任务或远端请求 ID。

VAD 返回样本区间、`speech_active` 与未结束话语标志 `speech_pending`，核心在同一事务写入 `coarse_jobs` 并完成原有保留判定。未处理/失败保守保留，句尾晚到时由已提交任务保护所有相交封块；仍在话语内的未确认起点暂不回收，无人声回收不等待重型识别。粗转由独立 `coarse_loop` 调度 `hear-worker recognize`：从已有 Opus 封块按原逐块重采样重建完全相同的输入，使用 **SenseVoice INT8**，发布到原 `coarse_segments`，模型/阈值未替换。

`coarse_jobs` 持有稳定任务身份；重复回放按已持久化样本区间去重，后面的成功不能掩盖早先失败留下的空洞。每个新 VAD 区间扣除已有 `coarse_jobs` 覆盖及无对应 job 的旧 `coarse_segments` 覆盖，只补未覆盖部分；旧毫秒时间仍按原采样坐标换算。不再用整个 session 的最大结束点代表所有前缀成功。回放如确认了先前范围之前的一小段，也可新增该未覆盖片段，已有区间及身份不改写。来源交替且定期服务最老待办，资源延期不消耗错误次数，异常失败有上限退避。清理使任务失效，迟到 VAD 与识别结果重新校验墓碑或任务状态。空文字/粗转失败不改变已确立的人声事实，worker 永不直接写数据库。进程与 IPC 有输入上限、统一请求截止时间、取消及父进程生命周期绑定。

## 5. 从粗转到候选，再到事件

### 5.1 候选粗切

[`events::evidence`](../../crates/hear-core/src/events.rs) 组合两类证据：已有粗转句段，以及检测到人声却没有可用粗文字的块。候选生成器按真实时间排序；当前 `candidate-v1` 的**策略参数**是“相邻证据相隔超过 15 分钟”或“候选跨度超过 30 分钟”时新开计算窗。已清除全部数据的区间也可成为切点。参数只控制送 LLM 的计算批次，不强制最终事件在这里断开。[`build_candidates_with_cuts`](../../crates/hear-core/src/events.rs)。

候选输入的 ID、时间、来源与文字形成哈希版本。晚到的本地分析可改变候选；大幅重叠时复用既有候选身份，旧版本云任务失效。扫描有持久游标和最近两小时回看，不因应用停机很久就永久跳过旧声音。[`refresh_candidates_in`](../../crates/hear-core/src/events.rs)。

自动入队条件是距离最后证据已满 15 分钟，或从候选起点到当前墙钟已满 30 分钟；后者不以首尾证据跨度判定，避免句段恰好结束于 30 分钟之前时额外等待。扫描每约 15 秒检查一次，处理时间仍受队列、网络与资源准入影响。未整理卡片保留相交候选的失败/重试事实，不让较新已完成候选覆盖旧积压错误；录音状态与整理状态独立展示。

### 5.2 LLM 拟合

LLM 收到粗文字、真实时间、来源、人声但无文字的标记，以及邻近上一命名事件的有限上下文。固定系统约束要求输出 JSON 事件范围、标题、内容摘要（`summary`）、来源及是否延续上一事件；持续会议应保持大范围，零散低密度句子留在未整理。模型输出只是**候选提案**。[`llm_input`、`FIT_SYSTEM`](../../crates/hear-core/src/events.rs)。

核心在 [`publish_fit`](../../crates/hear-core/src/events.rs) 检查 schema、数量、范围、来源证据、同源事件不重叠、前一个事件 ID、清理范围及任务版本；有效命名事件才进入当前事件轴并排队精转。人工修改边界/标题优先于迟到 LLM 返回。被跳过的候选内容仍在未整理时间块和底层粗转中。

事件边界始终是当前 candidate 内的绝对毫秒，延续上一事件时也只返回当前候选内的延续部分与 `merge_with_event_id`；核心保留前一事件起点并完成合并。提示词不能授权模型直接返回候选外的合并起点。同源重叠校验与返回数组顺序无关，不能把倒序但互不重叠的事件判成时间错误；保留原 slot 顺序以维持已有候选修订关联。真正越界、倒置或同源重叠仍使整次发布回滚。

摘要和标题在同一次 LLM 调用中生成：基于粗转中可确认的含义，中文一至两句、最多 240 字符；无法可靠概括时返回 null。`named_events.summary` 由 Core 与事件一起保存；前一事件及本候选已关联事件的摘要随输入提供，让跨窗延续生成整个事件的摘要。发布时重新核对实际发送的上下文；用户改边界/来源、纠正文稿或清除全部数据时失效摘要，迟到结果不得恢复。清除文字按实际删除的整句范围失效相邻事件摘要，来源保持隔离；只清原声保留文本摘要。精转完成不另调 LLM 自动改写摘要，摘要仍是基于粗转的概括，不代表精转准确性。

命名事件列表优先显示摘要并标注“内容摘要”，无摘要显示“暂无内容摘要，打开查看转录”；实时/未整理素材继续显示摘录。迁移旧记录为 null，不修改候选策略哈希、不自动付费回填。新增 `TimelineItem.summary` 是版本 16 下的可选兼容字段；旧响应缺失/null 均可读取。跨窗前文缺少摘要时不把局部概括冒充整个事件摘要。

### 5.3 时间线投影与人工边界

[`timeline`](../../crates/hear-core/src/events.rs) 以当天真实时间范围查询命名事件，再按来源从有效素材范围减去已被命名覆盖的范围，形成未整理块；静默间隔可以包含在大块中。用户对未整理区间手动精转时，`manual_ranges` 为该**连续真实时间范围**建立独立、可追踪的未命名精转事件，前后剩余部分继续显示粗转未整理块。手动新建/调整命名事件会更新 ASR 待办，不改写原声。日期列表的“隐藏粗转”仅影响 UI 投影，不删除数据。[`transcribe_range_in`、`timeline`](../../crates/hear-core/src/events.rs)；[日期界面](../../src/TimelineView.tsx)。

## 6. 两条云队列与精转

LLM/ASR 各有配置、暂停开关和持久 `cloud_tasks`，可单独继续。取任务时手动任务优先；任务绑定 `target_kind + target_id + target_version`，发布前再次确认仍指向当前事件/范围。[`take_task` / `task_current`](../../crates/hear-core/src/events.rs)。暂停队列不影响采集和粗转；已经外发的请求可以完成并经版本校验保存。

ASR 默认由 LLM 命名且判断值得精转的事件触发。自动请求等待事件末尾 15 分钟且相关本地分析/候选拟合已完成；后续同源事件可提前关闭观察范围。调度和事件卡片共用 `asr::settling_state` 的范围及阻塞查询，观察范围为当前开始到 `min(结束+15分钟,下一同源事件开始)`；范围外的失败不会污染当前卡片。处理中持续显示粗转，失败显式显示异常。人工建事件、改范围、明确“重新精转”或“选择范围精转”可立即规划。

`events/asr.rs` 在排队事务内保存不可变 `asr_inputs`：来源封块、原始时间范围、上传偏移与编码时长。封块路径是输入来源记录；实际上传经当前音频清单定位相同原始范围，允许清理其他时段时封块被重写，不改变持久输入和时间映射。普通短停顿保留；超过 3 秒且完全被无语音保留决策覆盖、没有采集缺口或清理记录的空档，在上传副本压至 1 秒。未知长缺口分开请求，原声/回放/真实时钟不变。同一来源按压缩后最多 20 分钟拼 Ogg/Opus，编码后仍检查 10MB 上限；两路来源分别提交。使用有界 10 秒 slab，内存不随整场 PCM 增长。事件可以比上传时长长得多。

`event_asr_refs` 记录事件对物理请求的有效范围；`event_asr_state` 仅保存当前范围是否已规划。`transcript_tasks` 统一投影当前事件归属，网络和用量继续使用物理 `cloud_tasks`。拆分继承完整识别历史，当前视图才按子事件裁剪，日后延长可复用原范围。自然续接、裁剪、拆分与合并复用已提交/已完成输入，按输入覆盖范围补新增音频，空结果和失败也不自动付费重送。完整旧句段、纠错和向量保留原 ID；跨人工边界的整句隐藏并显示部分精转，不猜字时间。显式重新精转才退出旧引用、生成新运行。界面在增量处理中同时显示旧精转和未覆盖粗转。

火山标准版使用 `submit/query`、固定资源 `volc.seedasr.auc`，请求 `enable_speaker_info`、`show_utterances` 与当前 `ssd_version=300`。物理任务 ID 也是远端请求去重 ID；未知提交结果应先查询而非直接付费重送。[`cloud.rs`](../../crates/hear-core/src/cloud.rs)。若供应商把长停顿合为一句，适配器仅在词列表完整、文字可顺序对齐且时刻有效时按超过 3 秒的词间停顿拆句，保留原文、标点和 speaker；不完整/无效的词元数据保持原句交由严格覆盖校验，零时长重复句仍拒绝。供应商 `utterances` 的相对毫秒通过持久输入映射还原；跨压缩接缝的句子必须用完整且顺序对齐的词级时间拆开，不能把一个句子拉过原始长空档。任何无法映射的返回令本请求整体失败，不发布部分结果、不自动新建付费请求。核验区间确有对应编码输入后，作为精转事实存入 `precise_segments`；speaker 标签的作用域是物理任务 ID。[`publish_asr`](../../crates/hear-core/src/events.rs)。空结果可为已完成但“无可识别文字”，不冒充配置失败。升级前已经提交的任务保留原请求 ID 和旧线性映射，已完成历史任务只建有效引用；只有尚未提交的 pending 任务按新规则规划。

云 ASR 完成之后才进入本机说话人观察和人物匹配。精转重跑创建新运行版本；旧任务与句段保留作纠错锚点、退出当前投影。人工逐句文字修正独立保存；来源与时间能唯一对应时迁移到新句段，否则进入待核对，不能由新结果静默覆盖。[`retranscribe_event_in`](../../crates/hear-core/src/events.rs)、[`reconcile_corrections`](../../crates/hear-core/src/knowledge.rs)。

火山查询适配器把 `45000092`（2026-10-17 实测响应为当前应用下找不到任务）和旧的 `45000000 + cannot find task` 都解释为任务不存在，由既有任务 owner 按提交次数决定提交、等待或终止。其他参数错误不作不存在处理。已失败的历史任务不在升级时自动重送，沿处理队列的显式重试恢复；先前已提交过的请求仍先查原请求 ID。

## 7. 说话人、人物与可见文本

这里有三个不同的判断：

1. **云端分句/临时编号**：同一物理 ASR 请求里的 `speaker_label`。可能误拆或误并，不是跨事件身份。
2. **本机同场匿名合组**：使用当前事件/来源/版本中合格句段的本机声音向量，谨慎合并被云端拆开的标签；仍只是本场“说话人 1/2”。
3. **本机全局人物匹配**：与用户确认的 `Person + VoiceSample` 库比对，满足门槛才在该句显示人物名；人工确认可作用于单句或用户明确选择的本场组。

算法、样例、阈值、撤销与已知质量风险统一见[说话人和全局人物](speaker-identity.md)。当前 UI 用事件内首次出现顺序生成“说话人 1/2”；这个数字不能跨事件查同一个人。[`speakerLabels`](../../src/DetailDrawer.tsx)。

## 8. 时刻动作与截图

Mark、评论和主动截图是独立的 `moments`，按用户触发或选择的真实 `anchor_ms` 保存；事件边界改变只改变它们在详情中的显示归属，不改原始时刻。评论要求非空文字，Mark 不隐式截图。截图先记触发时刻，再截取当前操作屏幕；私有暂存 PNG 经过文件类型、大小、签名和落盘检查后发布，并单独记录实际捕获时刻。本机 Vision OCR 的文字及完成/失败状态写回截图对象供找回，失败不冒充“截图里没有文字”。[`moments.rs`](../../crates/hear-core/src/moments.rs)、[macOS 原生桥接](../../crates/hear-core/native/moments.m)。

## 9. 读取、清理与恢复算法

回放按真实时刻从有效封块切片，静音或真实缺口不制造伪音频；搜索读当前有效粗/精转、修订文字、笔记和截图 OCR 的派生索引，GUI 0.1 暂不显示搜索页，CLI 可搜索。导出按所选范围冻结对象身份、分页读取并在发布前复核清理状态，只有完整文件同步/发布后报告成功。[`playback.rs`](../../crates/hear-core/src/playback.rs)、[`knowledge.rs`](../../crates/hear-core/src/knowledge.rs)、[`archive.rs`](../../crates/hear-core/src/archive.rs)。

清理使用“范围 + 声音来源 + 模式”的预览及内容签名；执行时先校验预览仍代表当前数据，再提交 `clear_ranges` 墓碑，使查询、回放、云任务与导出立刻服从清理范围，随后重写共享封块并后台删除旧媒体。`raw_audio` 保留文字和既有声纹特征；`all_data` 还使关联内容与范围贡献的声纹样例失效。清理、供应商迟到结果和人工修订都通过当前版本/范围复核，避免被旧任务复活。[`cleanup.rs`](../../crates/hear-core/src/cleanup.rs)。

恢复不是重跑全天录音：核心启动时核对封块/暂存与数据库清单，恢复队列、声纹 `processing` 和未完成物理删除；无法恢复的采集尾部记录真实缺口。处理任务可重试，用户手动暂停意图保持。日志仅辅助定位，不参与事实重建。[`main.rs`](../../crates/hear-core/src/main.rs)。

## 10. 策略与验收分界

| 当前策略点 | 源码位置 | 性质与未关闭风险 |
| --- | --- | --- |
| 五秒物理封块、48 kHz | [`record.rs`](../../crates/hear-core/src/record.rs) | 存储/采集策略；需测不同设备回调和睡眠恢复。 |
| VAD 512 样本输入、约 20 秒主动 flush | [`hear-worker`](../../crates/hear-worker/src/main.rs) | 控制推理资源；需测长连续语音召回。 |
| `pending_vad_v2` 保留判断 | [`retention.rs`](../../crates/hear-core/src/retention.rs) | 工作树候选；安装版误删/误留未验收。 |
| 15 分钟候选静默切点、30 分钟计算窗 | [`events.rs`](../../crates/hear-core/src/events.rs) | 只切计算输入，不决定用户事件边界。 |
| 同源 ASR 编码时长最多 20 分钟、Ogg/Opus、SSD 300 | [`events.rs`](../../crates/hear-core/src/events.rs)、[`cloud.rs`](../../crates/hear-core/src/cloud.rs) | 真实双人案例改善误拆；公开多人反例显示仍会误并。 |
| 本机匿名合组及全局人物门槛 | [`knowledge.rs`](../../crates/hear-core/src/knowledge.rs) | 小样本原型值，跨设备误认/漏认尚未冻结。 |

这些参数的改变须同时检查输入/模型版本、旧任务与修订重放、真实时间对齐、用户可见结果和代表性音频质量。单个案例的说话人组数吻合，不等于逐句分段准确，也不等于跨事件人物识别准确。

恢复重放输出并非全是旧结果：20秒硬分段在新起点上可能包含尚未提交的区间。core 对重放和当前结果使用同一持久 coarse_jobs 区间覆盖去重/清理裁决；升级前无对应 job 的 coarse_segments 也按已发表毫秒范围参与覆盖扣除。仅补实际未覆盖的区间，逐补段检查清理墓碑，不覆盖已完成块的 VAD/保留事实。

## 本机失败的诊断边界

`coarse_failed` 用 `job_id` 关联音频块，`capture_span_id` 关联录制 session；错误码区分解码、worker 启动/调用、上下文回放、回放发布与当前发布。采集错误保留有限阶段码、原生整数码、子进程退出码/信号及各类超时。`ingestion_retry` 标明列举、读/写、准备媒体、提交、确认或 journal 收尾阶段。只发布固定错误码或解析后的整数，不将任意异常文本、路径、转录、云响应或凭据写入结构化日志。

ASR `provider_unmapped_timing_*` 区分词缺失、文本对齐、接缝、词序、首尾范围及实际音频覆盖；LLM `invalid_fit_boundary_*` 区分倒序、越界、同源重叠，JSON 解析保留错误类别。旧错误码和新子码使用相同用户文案。严格校验与云任务重试策略不变；增加诊断不等于修复了历史供应商返回错误。回归证据与复现方法见 [本机可靠性验证](local-processing-verification.md)。
