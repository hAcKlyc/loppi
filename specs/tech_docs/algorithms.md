# 核心处理算法与任务工作流

> 本文描述 2026-09-30 工作树的代码路径。它记录“现有实现如何判断”，不把原型阈值写成永远不变的产品规则。总览见[架构](../ARCHITECTURE.md)，人物识别的详细算法见[说话人和全局人物](speaker-identity.md)。源码含未提交的 Batch 6 修改；安装版与质量验收状态见 [plan.md](../../plan.md)。

## 1. 两层音频处理与虚拟事件

真实轴由 `source + recording_session + sample_start + [started_ms, ended_ms)` 组成。麦克风和电脑声音各自连续推进，可以并行。原声封块及粗转是**发生过什么**；候选、命名事件、未整理块是**如何组织它**。候选不是事件，精转任务也不是事件。任何处理都不能倒改采集时钟或把两段之间的静默时间抹掉。

```text
设备回调 → 真实时刻/来源 → 约 5 秒封块 → 原声落盘
                                    ↘ 保留判定
                                    ↘ VAD → 本地粗转 → 候选区间
                                                       ↘ LLM 拟合 → 命名事件 → ASR
未被命名事件覆盖的有效时间轴 ──────────────────────────→ 未整理块
人工圈选连续区间 ───────────────────────────────────→ 独立未命名精转事件 → ASR
```

### 不变量

- 原声音频有文件内相对偏移；产品对象有真实 UTC 毫秒。供应商相对时间只有通过任务输入的真实时间映射后才能入库。
- 某时间段没有文件可以是**确认静音/无人声而省写**，也可以是**采集失败缺口**；两者分开记录。无文本不等于无人声。
- 事件范围可以包含大量没有句子的静默间隔。一场两小时会议应是一个大块虚拟范围，而非若干发言片段拼凑的列表。
- LLM 的密度/语义决定是否形成命名事件和自动精转，不决定底层原声留存。手动请求可直接走 ASR，不依赖新的 LLM 判断。

## 2. 采集、封块与时钟

每路录音由 [`record.rs`](../../crates/loppi-core/src/record.rs) 独立组装。回调带单调时刻和墙钟锚点；核心把输入混为单声道、重采样到 48 kHz，再按 `BLOCK_FRAMES = 48_000 × 5` 封成约五秒 Opus 块。连续文件封口、媒体持久化和 SQLite 清单使用固定顺序；回调队列溢出、采样率突变、顺序倒退、长时间无回调等都会中止该来源并记录缺口，不继续声称完整录制。

`ClockAnchor` 将来源内采样位置映射到真实毫秒。中断后另起 session；大于 250 ms 的回调空档被写成 `callback_gap`，首包明显晚于启动意图写 `source_start_gap`。来源失败的重试由 [`capture_supervisor`](../../crates/loppi-core/src/main.rs) 管理，两路独立；睡眠/唤醒与设备异常不会把采样序号和文件时长硬接成“连续音频”。当前重试参数和来源实现应直接看代码，仍需真实故障回归。

暂停、定时停止、容量暂停及关闭来源先记录停止意图，采集随后封存尾块。意图缺口通过现有 `source_session_id` 关联该来源的录音 session；创建时考虑已确认尾部，`ingestion::commit` 在录音块与回执同一事务中，按本 session 的确认边界缩短意图缺口。清理分片保留归属，迟到封块仍走原入口；关闭缺口不产生反向区间，回调与失败缺口不受影响。旧版本无归属的意图缺口只在同源封块明确覆盖起点且 session 唯一时关联、校正；升级时已有封块和之后到达的旧 journal 均适用，不复活清理范围。

## 3. 独立声音保留判断

[`retention.rs`](../../crates/loppi-core/src/retention.rs) 是单独策略边界，不读取 LLM 事件价值或粗转文本质量。**当前工作树含尚未安装版验收的 `pending_vad_v2` 候选：**

1. 全零数字静音直接记 `discard_digital_silence_v1`，不编码原声；非零音频先封口持久化，记 `pending_vad_v2`。
2. VAD 回写该封块的 `speech_active` 并先提交区间 `coarse_jobs`，策略在同一事务查看当前块与最多 6 个连续已完成且保留媒体的前块。有人声检测、重叠粗转任务或已发表句段则转为 `retain_speech_v2`，不等待识别文字。
3. 确认无人声时先在数据库撤销媒体引用、持久登记 `media_deletion_jobs`，再由后台删物理文件，状态为 `discard_no_speech_v2`。worker 的 `speech_pending` 表示仍有未结束话语；此时前块即使尚未检测到人声也延后负判断，完整区间发布后再裁决。当前边界块在未 flush 时仍暂缓决定，避免跨块句首被提前回收。
4. 同一回复可以关闭上一话语并开始下一话语。已发布 `coarse_jobs` 的样本终点允许其之前的连续前块结束等待，不把 `speech_pending=true` 误当成所有前块都仍未定。
5. 已完成块若已有 7 个更晚的已完成块（已退出 6 块回看），或来源已关闭、journal 已排空且无本地待分析块，旧的 `pending_vad_v2` 已无可等待的上下文。maintenance 每批最多 128 个改为 `retain_unresolved_v2`：只保留原声，不改 `speech_active`，不排物理删除；现有 ASR 规划包含所有保留媒体。这是失去判定依据后的保守留存，可能多保留噪声，不能称为检测到了语音。未完成分析、未排空 journal 与仍在上下文内的活动尾块继续等待。
6. 策略升级不回溯删除旧版已保留原声。

这段代码回应了“不保留无说话环境噪音”的产品选择，但**实际误删/误留率、弱语音和安装版落盘效果尚未验收**。不能仅凭单元测试宣布全天声音保留正确。

## 4. VAD 与本地粗转录

[`analysis_loop`](../../crates/loppi-core/src/main.rs) 从已封口待分析块读取音频，经 [`AnalysisClient`](../../crates/loppi-core/src/analysis.rs) 逐块重采样到 16 kHz，按来源、session 与采样号送给轻量 `loppi-worker vad`。**Silero VAD** 模型与阈值不变，仍以 512 样本小窗输入、约 20 秒主动 flush。非连续坐标或新 session 重建对应状态；核心分别为两条来源回放最近最多 6 个连续已完成、仍保留媒体的人声或 `pending_vad_v2` 尾块，不能用“进程已重启”替代另一条流的恢复。

VAD 主动 flush 后，底层可能排出 `n=0` 的空片段；worker 在 drain 时消费它但不作为语音区间返回。核心继续拒绝非正时长区间。`vad_nonempty_regions_v1` 复用现有迁移机制，仅一次将仍保留媒体、处于 `pending_vad_v2` 的失败本地块重新入队并清零本地尝试数；之后仍按 3 次上限失败，不重置任何云任务或远端请求 ID。

VAD 返回样本区间、`speech_active` 与未结束话语标志 `speech_pending`，核心在同一事务写入 `coarse_jobs` 并完成原有保留判定。未处理/失败保守保留，句尾晚到时由已提交任务保护所有相交封块；仍在话语内的未确认起点暂不回收，无人声回收不等待重型识别。粗转由独立 `coarse_loop` 调度 `loppi-worker recognize`：从已有 Opus 封块按原逐块重采样重建完全相同的输入，使用 **X-ASR中英离线Zipformer Transducer INT8（2026-06-03）**，发布到原 `coarse_segments` 并写入准确model_version，历史结果不改；VAD、切分与资源阈值保持原值。[固定权重与评测依据](local-asr-benchmark.md)。

X-ASR 编码器不接受过短特征矩阵。合法 VAD 尾段/覆盖扣除可能只剩 1～几十毫秒；worker 只在推理缓冲区右侧补零到 200 ms，空输入直接返回空文字。原媒体、任务样本范围和时间均不补长，也不把短段判成无语音。正常长度复用原切片，不能通过丢弃短段或反复重启模型回避输入契约。父进程消失或原生调用超时时，helper 使用 `_exit` 强制终止，避免另一线程仍在 ONNX/HAL 中时执行全局 C++ 析构；正常停止仍走原封块和回收流程。

`coarse_jobs` 持有稳定任务身份；重复回放按已持久化样本区间去重，后面的成功不能掩盖早先失败留下的空洞。每个新 VAD 区间扣除已有 `coarse_jobs` 覆盖及无对应 job 的旧 `coarse_segments` 覆盖，只补未覆盖部分；旧毫秒时间仍按原采样坐标换算。不再用整个 session 的最大结束点代表所有前缀成功。回放如确认了先前范围之前的一小段，也可新增该未覆盖片段，已有区间及身份不改写。来源交替且定期服务最老待办；成熟候选仍等待粗转时，八轮中的最新优先份额从六轮降为两轮，让旧输入更快补齐；没有此类等待时恢复六轮。资源延期不消耗错误次数，异常失败有上限退避。清理使任务失效，迟到 VAD 与识别结果重新校验墓碑或任务状态。空文字/粗转失败不改变已确立的人声事实，worker 永不直接写数据库。进程与 IPC 有输入上限、统一请求截止时间、取消及父进程生命周期绑定。

## 5. 从粗转到候选，再到事件

### 5.1 候选粗切

[`events::evidence`](../../crates/loppi-core/src/events.rs) 组合两类证据：已有粗转句段，以及检测到人声却没有可用粗文字的块。候选生成器按真实时间排序；2026-10-23 起**策略参数**是“相邻证据相隔超过 5 分钟”或“候选跨度超过 15 分钟”时新开计算窗。已清除全部数据的区间也可成为切点。参数只控制送 LLM 的计算批次，不强制最终事件在这里断开。[`build_candidates_with_cuts`](../../crates/loppi-core/src/events.rs)。

候选输入的 ID、时间、来源与文字形成哈希版本。已有候选继续作为计算切点：优先由候选 ID 找到原首条证据的排序位置，保留两路同起点、不同终点之间的旧切分；原证据已被粗转替换或起点修订时才按持久起点定位。同时保留已有候选的持久终点以内的证据分组，避免缩短窗口后拆散已付费输入。这样既不吞并下一已持久化候选，也不因策略变化重跑旧结果；超出旧终点的新证据采用当前策略。沿用 `candidate-v1` / `fit-v3` 输入哈希前缀，不因本次 prompt 文案或窗口大小调整自动付费重跑未变化的历史输入。晚到的本地分析可改变候选；大幅重叠时复用既有候选身份，旧版本云任务失效。扫描有持久游标和最近两小时回看，不因应用停机很久就永久跳过旧声音。[`refresh_candidates_in`](../../crates/loppi-core/src/events.rs)。

候选成熟条件是距离最后证据已满 5 分钟，或从候选起点到当前墙钟已满 15 分钟；后者不以首尾证据跨度判定，避免句段恰好结束于 15 分钟之前时额外等待。成熟候选先持久保存；自动 LLM 排队还需等待对应粗转和 VAD 本地待办完成。检查范围包括尚未出现在文字证据中的计算窗尾部（到当前时刻或起点后 15 分钟），已有证据超过该界限时仍完整检查；终态失败不阻塞，失败的人声仍通过无可用文字标记参与整理。等待期间更新同一候选输入，补齐后汇合为一次待办；尚无对应云任务的 pending 候选持续纳入扫描，不受两小时回看限制，保证无新文字的完成或终态失败也能解除等待；已排队但新增本地待办的自动任务也暂缓领取。显式“立即处理”可强制提前排队/提升现有 pending 任务；不因策略更新重跑已完成、不变的历史输入。扫描每约 15 秒检查一次，处理时间仍受队列、网络与资源准入影响。连续活动首次自动命名通常在起点后约 15 分钟进入队列，不是精转完成时限，本地粗转与未整理展示继续更新。未整理卡片保留相交候选的失败/重试事实，不让较新已完成候选覆盖旧积压错误；录音状态与整理状态独立展示。

### 5.2 LLM 拟合

LLM 收到粗文字、与当前 candidate 相交的真实时间、来源、人声但无文字的标记，以及邻近前序自动命名事件的有限上下文（真实起点更早，结束距当前起点不超过 30 分钟，允许跨来源句段造成的计算窗交叠）。`context.previous_events` 按 source_mask 分别选最新一个，最多三项；每项含标题、摘要、结构化理解、修订号、人工边界锁，以及末尾 3 分钟内最多 24 条同属其来源的非空粗转 `tail`，每条最多 400 字符并标记截断。独立并行活动可分别续接各自的 ID，同一旧 ID 可继续接纳有效续接片段，重复声明不拒绝整窗。当前候选已经关联的事件只出现在 linked_events，不再重复作为前序。前文只辅助判断延续/结束，不能作为候选外新事件的输出范围；原始粗转不被截断改写。粗转没有 speaker 或人物字段，麦克风/电脑声音不能当作说话人身份。

固定系统约束要求按**真实连续活动**输出 JSON 事件范围、标题、内容摘要（`summary`）、结构化理解（`understanding`）、来源及是否延续上一事件。会议中的多个议题、连续日常聊天中的家务/育儿/工作等小话题、换人发言、短暂停顿和计算窗口边界都不是单独拆分理由；活动层级标题保持稳定，子议题进入摘要。明确散会后另打电话、另一场会议开始、同时发生的独立来源活动仍应拆开，不能仅凭话题相同或时间相近硬合并。不设置最小事件时长、固定数量或整批数量拒绝规则。零散低密度句子可留在未整理；不要求模型输出未整理观察下标，旧响应中的 `unorganized` 被忽略。同场短问题、回应和开场收尾语仍属于所在活动；“我没别的了”“还有一个事”等单句不足以证明整场结束。模型输出只是**候选提案**，有限合成样本验证不保证真实语音上的每次判断正确。[`llm_input`、`FIT_SYSTEM`](../../crates/loppi-core/src/events.rs)。

粗转句子可能跨越计算窗。`llm_input` 以 `{start_ms,end_ms,source,text,evidence_index}` 对象传递 observations，时间仅取与 candidate 的交集，明确文字可能跨窗；不改写原粗转时间或回放依据。输入和输出因此使用同一个可归属区间，发布仍拒绝候选外边界。

核心在 [`publish_fit_with_input`](../../crates/loppi-core/src/events.rs) 逐事件、逐字段接纳结果，不再校验观察是否完整覆盖，也不再让未整理下标决定发布。摘要缺失、类型异常、空白或含 NUL 时保留有效旧摘要；无有效历史才为空，不限制保存长度；标题异常沿用已有标题，新事件用“普通会话”；无效或冲突的续接建议作废，仍尝试保存当前独立范围。可选元数据和来源异常不改变后续项的原 slot；非法时间按下述规则在写入前拒绝。

事件仍需要 candidate 内正向绝对毫秒、已知且有证据的来源；时间缺失/类型错误、倒序、越界和同一响应内同源区间重叠在事务写入前拒绝整窗，不能静默丢事件后标为complete；旧结果保持不变。无效来源、与已保存同源事件冲突的提案仍只跳过该条，遵守人工优先级。任务当前归属、清理墓碑和人工修改优先级不变；真正数据库错误仍回滚事务，不作为模型质量问题吞掉。模型未覆盖、跳过的内容继续由底层原声、粗转和未整理时间线保留。时间结构合法的 events 数组完成本次计算，包括零条可用事件；完成表示本次处理已结束，不保证模型语义完整。

延续上一事件时返回当前候选范围和 `merge_with_event_id`，核心保留前一事件起点，结束取最大值，不能因相交计算窗缩短旧活动。原 slot 用于关联旧事件，不排序或压缩。响应少写、漏写或含无效条目均不构成删除指令，已发布事件与精转引用保留；人工编辑/删除和清理仍由原入口负责。过期摘要继续按实际发送上下文失效。

原始 JSON 在转为 Value 前递归拒绝重复键（包括同值和转义等价键），避免后值覆盖前值。整份 JSON 无法解析/重复键、不完整输出、缺失 events 数组及非法时间复用原有至多三次格式重试；其他可选字段质量不扩为重试原因。用量在解析前记录，诊断只记录错误分类/位置，不含正文和键名。网络、限流与凭据重试策略不变；不新增队列、状态或恢复器，也不自动重跑历史失败。

摘要和结构化理解在同一次 LLM 调用中生成。窗口文字分析对当前配置模型启用 `thinking=enabled, reasoning_effort=low`，以支持同次调用中的事实修订和全场归纳；截图请求继续禁用推理。仍用既有超时、用量统计与有限重试，不新增调用层。推理可能增加输出 token 和时延，真实质量与耗时单独记录。参数依据 [DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)。摘要用总分段落保留可辨认的具体对象、例子、方案与进展，长场目标800–1000字符、容差1100，短场不凑字；这是合并后整场预算；存储与读取不作字数截断。key_points 保存可独立引用且带限定条件的事实/观点，topics 为开放主题，mentioned_objects 保存有辨识意义的对象及本次语境，entity_id 一律 null。`named_events.summary` 和可空 `understanding_json` 与事件原子更新；结构单独变化递增 revision，不重排精转。无旧快照时缺失/坏结构置空；已有有效快照时缺失/坏增量不删除旧内容。非法引用的新增/修订整条拒绝，不能连带删旧条目，不影响合法事件范围。

模型输出 `understanding` 是增量，数据库仍保存完整快照。Core 保留未修改的旧条目与主题；模型新增条目直接加入，修订/合并使用该条的 `replaces:[0,2]` 指向实际续接目标对应旧数组的零基下标，输入显式标记为 item_index，不是 evidence 下标。只有明确更正/撤回同一事实或等价重复合并才替换；补充动因、举例、回应质疑和不同观点应新增。替换必须带当前窗口的合法证据，每个旧条目在本次请求最多消费一次；任一坏下标/引用导致整条更新拒绝，原条目保留。撤回通过“此前方案已撤回”等最新状态替换，不增加删除日志。完全相同的要点文本或对象 name/type/context 合并引用；语义去重由模型显式修订。topics 累计去重，保留已经讨论过的主题。`replaces` 仅请求内使用，不持久化，不改 schema_version=1。summary 在同次调用返回 null 或句子增量数组，每项为 mode/text/replaces/evidence_indices；输入 summary_sentences 从现有摘要按中文句末标点生成请求内 item_index。Core 保留未改句子、修订放回首个被替换位置、新句追加，最终仍保存一个完整文本字符串。mode=update新增可补充旧要点已有证据支持的遗漏；事实替换必须有本窗证据，越界/重复消费/坏引用不得删旧句。不同观点不能合并成共识。mode=compress可合并/缩短指定旧句，仅引用目标旧理解证据、无需本窗证据；要求非空替换且字符数确实减少，不能改事实或添加新结论。缺mode的旧提案按update，未知mode拒绝该项不删旧句。summary_chars和summary_budget从现有字符串与固定生成目标派生，不持久化；同次请求可同时对互不重叠旧句压缩和纠正，同句两者兼有时使用update。模型须估算合并后的整场长度，不将预算当本窗配额；超长仍保存完整值、不追加模型调用，实测单列超标。缺失/坏增量保留有效旧摘要；旧整段string仅在当前窗覆盖完整活动时可接纳，不能覆盖窗外历史。无新持久分段状态、不增设总结请求或全量原文重送。真实模型语义质量需单独验证，不能由格式合法推定。

`events/understanding.rs` 负责单次输入映射、增量合并和规范化，没有独立任务/缓存。输入 `evidence` 目录包含当前非空粗转与旧理解引用；observations 的 evidence_index 及旧理解的 evidence_indices 都是本次目录下标。持久化转换为 `evidence_refs`（segment_id、source、原句绝对起止），保存 schema_version=1；跨窗句仍引用原句，不伪造词级时间。仅接受当前观察或实际续接目标已有引用，且必须相交最终范围/来源；其它并行事件的继承引用不能借用。读取旧理解先核对引用行存在且来源/时间一致；下一窗口重新编号。发布重新比较完整实际输入（观察、目录、旧快照和 revision），变化后不恢复旧摘要/结构；如果实际观察及锚点、最终事件范围/来源未变，只是标题修订或已有更新的快照，则保留数据库中的当前有效值，不能用迟到结果或空值覆盖。

标题编辑保留理解；边界/来源编辑、人工 active/pending_review 纠错、全部清理通过 `invalidate_event_understanding` 同时清空摘要与结构。清理按实际删除整句范围连带失效相邻事件，来源隔离；仅清原声保留粗转引用与理解。基于粗转的理解不得覆盖人工纠错；精转重跑和人物修改不触发重算。旧事件/已失效事件的窗口外历史缺少有效快照时，该字段保持 null，不能用局部窗口冒充全事件；摘要与结构各自判断。迁移只加可空列，不修改候选哈希、不自动付费回填历史。GUI 沿用摘要两行省略，本次不提供结构化字段展示、引用跳转或新增 IPC 字段。初始存储契约见 [事件理解 PRD](../prd/prd_0.1.6_event-understanding.md)，增量更新覆盖原全量替换契约，见 [续接修复](../prd/devplan_261024_event-understanding-accumulation.md)。

命名事件列表优先显示摘要并标注“内容摘要”，无摘要显示“暂无内容摘要，打开查看转录”；实时/未整理素材继续显示摘录。迁移旧记录为 null，不修改候选策略哈希、不自动付费回填。新增 `TimelineItem.summary` 是版本 16 下的可选兼容字段；旧响应缺失/null 均可读取。跨窗前文缺少摘要时不把局部概括冒充整个事件摘要。

### 5.3 时间线投影与人工边界

详情顶部「确认事件结束」支持人工确认：不改时间时直接确认当前LLM结果结束；改任一端时以用户调整的时间作参考，复用事件重整生成新组织与摘要，成功产出/更新的所有事件一律确认结束。完成状态在 `named_events.completed_ms`，处理状态仍来自既有任务。自动拟合输入按来源扣除已确认范围，保持原证据引用；这些事件不进入previous/linked续接，发布也不能改回已确认事件。后续独立尾部可以重新命名，已确认占用范围仍参与冲突检查。显式人工编辑/重新整理保留纠正能力。

改时完成任务的目标修订只在用户显式重试时更新到存活目标的当前修订；自动执行不重设，发布继续校验完整输入快照，旧结果与已删除目标不能通过重试复活。


用户主动`ReorganizeEvents`走既有LLM队列和FIT_SYSTEM，带本次user_instruction、相关旧事件完整范围与有限前后文。新增一次性请求载荷，不建立长期指示或另一队列。模型通过event_id明确更新及retire_event_ids退役，遗漏仍不删除；发布事务复用事件、摘要、理解规范化及ASR引用。模型决定语义，Core校验结构、音源/对象归属、修订和最终非重叠；此模式可以调整相关人工事件且不新增人工锁。它与固定边界的RebuildUnderstanding、原人工CreateEvent/拆合命令语义不同，GUI新建表单改用此模式，CLI提供event reorganize。原声/句段/人物和笔记事实不因重组改变。

[`timeline`](../../crates/loppi-core/src/events.rs) 以当天真实时间范围查询命名事件，再按来源从有效素材范围减去已被命名覆盖的范围，形成未整理块；静默间隔可以包含在大块中。用户对未整理区间手动精转时，`manual_ranges` 为该**连续真实时间范围**建立独立、可追踪的未命名精转事件，前后剩余部分继续显示粗转未整理块。手动新建/调整命名事件会更新 ASR 待办，不改写原声。日期列表的“隐藏粗转”仅影响 UI 投影，不删除数据；失败、重试和凭据受阻的素材仍显示时间和状态入口，粗转正文继续遵守隐藏设置。命名事件的整理异常与精转进度并列显示，不覆盖已有精转完成状态。[`transcribe_range_in`、`timeline`](../../crates/loppi-core/src/events.rs)；[日期界面](../../src/TimelineView.tsx)。

## 6. 两条云队列与精转

LLM/ASR 各有配置、暂停开关和持久 `cloud_tasks`，可单独继续。取任务时手动任务优先；任务绑定 `target_kind + target_id + target_version`，发布前再次确认仍指向当前事件/范围。[`take_task` / `task_current`](../../crates/loppi-core/src/events.rs)。暂停队列不影响采集和粗转；已经外发的请求可以完成并经版本校验保存。

LLM 拟合按时间顺序取候选，不使用 ASR 的“优先最新”轮次；存在距离当前候选起点 30 分钟以内的更早、仍有效且 pending/processing 的候选时，先等待前文（包括粗转尚未齐、未创建云任务及退避期间）。不相邻的其它工作和截图仍可处理，ASR 原有公平调度不变。前文已终态失败时不永久阻塞后文，也不凭空假定未完成范围属于同一活动；后续人工重试历史失败不触发全历史自动重整。本次不批量合并既有碎片事件。

ASR 默认处理全部有效事件，也可按事件标签筛选。事件自然稳定或用户确认结束后，Core 统一判断自动精转和生成策略。自动请求等待事件末尾 15 分钟且相关本地分析/候选拟合没有可推进的待办；后续同源事件可提前关闭观察范围。调度和事件卡片共用 `asr::settling_state` 的范围及阻塞查询，观察范围为当前开始到 `min(结束+15分钟,下一同源事件开始)`；整理、本地 VAD/粗转终态失败（含耗尽尝试的旧 pending VAD）不再阻塞已有事件的精转；保留的未判定原声仍由既有 ASR 输入规划器覆盖。失败不伪装成完成，也不自动重置历史任务。`TimelineItem.local_analysis_failures` 按卡片自身范围与来源只读统计，旧响应缺失时默认 0，与精转状态并列展示；观察范围中的其它失败不污染卡片。pending/processing 候选和实际本地待办继续正常等待。已完成/已提交精转请求按既有引用复用，不能因解阻重复上传。处理中持续显示粗转，失败显式显示异常。人工建事件、改范围、明确“重新精转”或“选择范围精转”可立即规划。

命中自动精转的已确认事件立即规划，无需观察窗口或粗转/候选积压；原声尚未封存时，后续 `audio_blocks` 入库/恢复可用路径在同一事务清空相交已确认事件的 `planned_version`，由原 `asr::refresh` 补规划，已有ASR引用继续扣除，避免漏尾部或重复上传。完成后的等待规划显示「待精转」，不退回等待事件稳定。

`events/asr.rs` 在排队事务内保存不可变 `asr_inputs`：来源封块、原始时间范围、上传偏移与编码时长。封块路径是输入来源记录；实际上传经当前音频清单定位相同原始范围，允许清理其他时段时封块被重写，不改变持久输入和时间映射。新规划使用 `volc-event-silence-v4`：不超过 1 分钟的空档，只有整个区间都由同源 `discard_no_speech_v2` / `discard_digital_silence_v1` 封块证明无人声，且不跨采集或原声/全部清理区间，才在请求内保留等长静默。超过 1 分钟、缺失/不完整/其他来源证据的空档分开物理请求；每处不超过 10ms 的时钟量化缝隙都必须由同 session 且 sample_start/frames 严格连续的相邻封块证明，不能仅凭毫秒接近跨过未知采集空档。没有粗转文字本身不构成静默证据，不改变 VAD 或原声保留策略，也不压缩真实时间。每个新请求只有一个连续时间坐标，事件仍通过既有引用保持完整，原声/回放不变。同一来源每个连续请求最多 20 分钟，编码为 Ogg/Opus，编码后仍检查 10MB 上限；两路来源分别提交。使用有界 10 秒 slab，内存不随整场 PCM 增长。事件可以比上传时长长得多。静默填充也计入 20 分钟上限和用量；相较 v2 可减少请求数，但上传时长与费用可能增加，不宣称文字或说话人准确率必然改善。跨请求云 speaker 编号仍由既有本机同场合组处理。

`event_asr_refs` 记录事件对物理请求的有效范围；`event_asr_state` 仅保存当前范围是否已规划。`transcript_tasks` 统一投影当前事件归属，网络和用量继续使用物理 `cloud_tasks`。拆分继承完整识别历史，当前视图才按子事件裁剪，日后延长可复用原范围。自然续接、裁剪、拆分与合并复用已提交/已完成输入，按输入覆盖范围补新增音频，空结果和失败也不自动付费重送。完整旧句段、纠错和向量保留原 ID；跨人工边界的整句隐藏并显示部分精转，不猜字时间。显式重新精转才退出旧引用、生成新运行。界面在增量处理中同时显示旧精转和未覆盖粗转。

火山标准版使用 `submit/query`、固定资源 `volc.seedasr.auc`，请求 `enable_speaker_info`、`show_utterances` 与当前 `ssd_version=300`。物理任务 ID 也是远端请求去重 ID；未知提交结果应先查询而非直接付费重送。[`cloud.rs`](../../crates/loppi-core/src/cloud.rs)。若供应商把长停顿合为一句，适配器仅在词列表完整、文字可顺序对齐且时刻有效时按超过 3 秒的词间停顿拆句，保留原文、标点和 speaker；不完整/无效的词元数据保持原句，零时长重复句仍拒绝。供应商 `utterances` 的相对毫秒通过持久输入映射还原；对已持久化的旧 `volc-event-compact-v1` 输入，跨压缩接缝的句子仍必须用完整且顺序对齐的词级时间拆开，不能把一个句子拉过原始长空档。任何无法映射的返回令本请求整体失败，不发布部分结果、不自动新建付费请求。通过任务归属/清理、输入时间映射、正时长与请求范围校验后，作为精转事实存入 `precise_segments`；speaker 标签的作用域是物理任务 ID。[`publish_asr`](../../crates/loppi-core/src/events.rs)。空结果可为已完成但“无可识别文字”，不冒充配置失败。已持久化的输入（包括 pending、submitted、complete、failed）及远端请求 ID 均不被本次策略升级重写；已有旧迁移仅负责没有 `asr_inputs` 的更早版本数据。新规划才使用一分钟已知静默连接策略，不给请求额外添加静默尾巴；超过上限的缺口分开请求且不填充上传。已持久化的 v3 三分钟策略输入、v2 连续输入以及更早 v1 压缩输入的既有映射和远端 ID 都保持不变。词级拆句仍用 3 秒词间停顿改善展示，但不作为文字准入条件。文字发布不再按当前原声留存、VAD、静默长度、首尾容差、原声占比或原声重叠过滤结果；即使句段落入已编码静默，也保留供应商原文与时间，接受偶发长时间跨度。声纹和回放各自验证真实媒体，不能因此丢弃文字。对已确定无法接受的结果（时间映射/时间格式/句格式/缺少句列表），任务页明确提供“重新识别”并提示新用量：既有 `RetryCloudTask` 事务将旧物理任务退出当前投影，按 `transcript_tasks` 的当前归属、失败范围和来源调用当前 planner。拆分/合并后也只重建当前有效范围；同事件其它成功任务、人工修订、旧输入、远端 ID 和用量保留。任一归属无保留原声时整笔事务回滚，失败仍可见；不自动付费重送。网络/提交结果不确定的重试仍先查询原 ID。整事件“重新精转”入口保持原语义。 历史 `provider_unmapped_timing_audio_coverage` 是已移除的本机文字过滤，重试仍查询原 ID 并按当前发布规则保存原结果，不归为确定坏结果重新识别；若远端明确不存在，沿既有重试规则处理。

`partial_transcript` 表示有效任务已完成，但部分任务没有可显示文字或文字被人工边界裁剪，不能解释为仍在排队。`TimelineItem.transcription` 是可选、只读的当前任务引用统计（总数、完成数、空结果数、边界裁剪）；列表不附范围，详情附空结果的来源与真实时间，供回听。跨边界的已有文字不计入空结果。部分或全部任务为空时 UI 都明示“精转完成 · N 段无文字”或“边界处文字待核对”；无旧版统计字段时仍明确显示完成。失败、录音缺口与没有任何文字继续使用各自状态，不承诺识别逐字正确。

云 ASR 完成之后才进入本机说话人观察和人物匹配。精转重跑创建新运行版本；旧任务与句段保留作纠错锚点、退出当前投影。人工逐句文字修正独立保存；来源与时间能唯一对应时迁移到新句段，否则进入待核对，不能由新结果静默覆盖。[`retranscribe_event_in`](../../crates/loppi-core/src/events.rs)、[`reconcile_corrections`](../../crates/loppi-core/src/knowledge.rs)。

火山查询适配器把 `45000092`（2026-10-17 实测响应为当前应用下找不到任务）和旧的 `45000000 + cannot find task` 都解释为任务不存在，由既有任务 owner 按提交次数决定提交、等待或终止。其他参数错误不作不存在处理。已失败的历史任务不在升级时自动重送，沿处理队列的显式重试恢复；先前已提交过的请求仍先查原请求 ID。

智能标签随现有整理请求输出。Core 校验配置中的标签 UUID，并保存独立打标状态。事件确定与 ASR 状态分别投影。用户改标签时按确定范围预览和提交动作差异，未提交且失去条件的动作撤回，已有共享精转覆盖继续复用。自动与手动生成在 `events/workflow.rs` 共用输入、调度、发布和版本读取。生成目标绑定事件、范围、来源及转录指纹，清理会使相交的等待、在途任务和成功版本失效。

## 7. 说话人、人物与可见文本

这里有三个不同的判断：

1. **云端分句/临时编号**：同一物理 ASR 请求里的 `speaker_label`。可能误拆或误并，不是跨事件身份。
2. **本机同场匿名合组**：使用当前事件/来源/版本中合格句段的本机声音向量，谨慎合并被云端拆开的标签；仍只是本场“说话人 1/2”。
3. **本机全局人物匹配**：与用户确认的 `Person + VoiceSample` 库比对，满足门槛才在该句显示人物名；人工确认可作用于单句或用户明确选择的本场组。

算法、样例、阈值、撤销与已知质量风险统一见[说话人和全局人物](speaker-identity.md)。当前 UI 用事件内首次出现顺序生成“说话人 1/2”；这个数字不能跨事件查同一个人。[`speakerLabels`](../../src/DetailDrawer.tsx)。

## 8. 时刻动作与截图

Mark、评论和主动截图是独立的 `moments`，按用户触发或选择的真实 `anchor_ms` 保存；事件边界改变只改变它们在详情中的显示归属，不改原始时刻。评论要求非空文字，Mark 不隐式截图。截图先记触发时刻，再截取当前操作屏幕；私有暂存 PNG 经过文件类型、大小、签名和落盘检查后发布，并单独记录实际捕获时刻。本机 Vision OCR 的文字及完成/失败状态写回截图对象供找回，失败不冒充“截图里没有文字”。[`moments.rs`](../../crates/loppi-core/src/moments.rs)、[macOS 原生桥接](../../crates/loppi-core/native/moments.m)。

## 9. 读取、清理与恢复算法

回放按真实时刻从有效封块切片，静音或真实缺口不制造伪音频；搜索读当前有效粗/精转、修订文字、笔记和截图 OCR 的派生索引，GUI 0.1 暂不显示搜索页，CLI 可搜索。导出按所选范围冻结对象身份、分页读取并在发布前复核清理状态，只有完整文件同步/发布后报告成功。[`playback.rs`](../../crates/loppi-core/src/playback.rs)、[`knowledge.rs`](../../crates/loppi-core/src/knowledge.rs)、[`archive.rs`](../../crates/loppi-core/src/archive.rs)。

清理使用“范围 + 声音来源 + 模式”的预览及内容签名；执行时先校验预览仍代表当前数据，再提交 `clear_ranges` 墓碑，使查询、回放、云任务与导出立刻服从清理范围，随后重写共享封块并后台删除旧媒体。`raw_audio` 保留文字和既有声纹特征；`all_data` 还使关联内容与范围贡献的声纹样例失效。清理、供应商迟到结果和人工修订都通过当前版本/范围复核，避免被旧任务复活。[`cleanup.rs`](../../crates/loppi-core/src/cleanup.rs)。

恢复不是重跑全天录音：核心启动时核对封块/暂存与数据库清单，恢复队列、声纹 `processing` 和未完成物理删除；无法恢复的采集尾部记录真实缺口。处理任务可重试，用户手动暂停意图保持。若启用了每日定时规则，正常录制运行恢复时仅应用最近一个未处理的当地时间边界；已处理边界不会覆盖后来手动操作。配置保存不启停录制，定时开始不清除容量保护。纯查询运行不推进定时游标。日志仅辅助定位，不参与事实重建。[`main.rs`](../../crates/loppi-core/src/main.rs)。

## 10. 策略与验收分界

| 当前策略点 | 源码位置 | 性质与未关闭风险 |
| --- | --- | --- |
| 五秒物理封块、48 kHz | [`record.rs`](../../crates/loppi-core/src/record.rs) | 存储/采集策略；需测不同设备回调和睡眠恢复。 |
| VAD 512 样本输入、约 20 秒主动 flush | [`loppi-worker`](../../crates/loppi-worker/src/main.rs) | 控制推理资源；需测长连续语音召回。 |
| `pending_vad_v2` 保留判断 | [`retention.rs`](../../crates/loppi-core/src/retention.rs) | 工作树候选；安装版误删/误留未验收。 |
| 5 分钟候选静默切点、15 分钟计算窗 | [`events.rs`](../../crates/loppi-core/src/events.rs) | 只切计算输入，不决定用户事件边界；保留既有候选起点。 |
| 同源 ASR 编码时长最多 20 分钟、Ogg/Opus、SSD 300 | [`events.rs`](../../crates/loppi-core/src/events.rs)、[`cloud.rs`](../../crates/loppi-core/src/cloud.rs) | 真实双人案例改善误拆；公开多人反例显示仍会误并。 |
| 本机匿名合组及全局人物门槛 | [`knowledge.rs`](../../crates/loppi-core/src/knowledge.rs) | 小样本原型值，跨设备误认/漏认尚未冻结。 |

这些参数的改变须同时检查输入/模型版本、旧任务与修订重放、真实时间对齐、用户可见结果和代表性音频质量。单个案例的说话人组数吻合，不等于逐句分段准确，也不等于跨事件人物识别准确。

恢复重放输出并非全是旧结果：20秒硬分段在新起点上可能包含尚未提交的区间。core 对重放和当前结果使用同一持久 coarse_jobs 区间覆盖去重/清理裁决；升级前无对应 job 的 coarse_segments 也按已发表毫秒范围参与覆盖扣除。仅补实际未覆盖的区间，逐补段检查清理墓碑，不覆盖已完成块的 VAD/保留事实。

## 本机失败的诊断边界

`coarse_failed` 用 `job_id` 关联音频块，`capture_span_id` 关联录制 session；错误码区分解码、worker 启动/调用、上下文回放、回放发布与当前发布。采集错误保留有限阶段码、原生整数码、子进程退出码/信号及各类超时。`ingestion_retry` 标明列举、读/写、准备媒体、提交、确认或 journal 收尾阶段。只发布固定错误码或解析后的整数，不将任意异常文本、路径、转录、云响应或凭据写入结构化日志。

ASR `provider_unmapped_timing_*` 区分旧压缩输入中的词缺失、文本对齐、接缝、词序及首尾范围；`provider_unmapped_timing_audio_coverage` 是旧版文字覆盖过滤留下的历史错误码，当前发布不再产生它。LLM `invalid_fit_boundary_*` 区分倒序、越界、同源重叠，JSON 解析保留错误类别。旧错误码和新子码使用相同用户文案。严格时间校验不变；ASR 输入规划及候选 LLM 有限重试遵循上文新规则。诊断和输入契约修正不能恢复未保存的历史 LLM 原输出，也不代表所有采集中断已修复。回归证据与复现方法见 [本机可靠性验证](local-processing-verification.md)与 [10/21 精转发布失败调查](../research/2026-10-22-asr-publication-failures.md)。
