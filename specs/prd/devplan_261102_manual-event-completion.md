# 人工确认事件结束与详情操作收纳

需求源为本次已收敛对话及[讨论台账](_drafts/manual-event-completion.md)。用户授权「开始开发吧，直到完成」。本文件为对话模式开发计划，不把讨论草稿当作 ready PRD。

## 产品契约

事件详情顶部显示处理状态，右侧事件级管理操作全部收进更多菜单；播放、正文切换、现场记录等内容交互保持可直接使用。点击「等待事件稳定」打开确认弹窗，预填当前事件起止日期时间，两端可编辑，取消不产生业务变更。

- 提交起止与原值相同：保留已有 LLM 结果，确认事件结束，不再参与后续自动续接/修改，立即按既有队列规则规划精转。
- 任一端变更：以新时间为参考，明确告诉 LLM 是用户手动调整过的时间，按现有重整能力重新切割、识别并更新摘要。时间不是硬边界，可产生多个事件。本次成功产出/更新的事件全部确认结束、直接规划精转，无需再次确认或等待稳定。排队/失败期间保留旧有效结果。
- 已确认结束与精转进度分开；显式人工编辑、拆合、重新整理仍可修改。普通新建/重新整理入口保持既有语义，不因本次新增入口而默认确认结束。
- 重复请求、修订冲突、在途旧模型结果、重启和清理沿现有事务/回执/任务有效性机制；原声、粗转、有效精转及人工纠错不因本次 LLM 重整被全量重跑或删除。
- 未来时间/倒置/超长/无文字按现有校验说明；局部未封存原声到达后补精转，不额外等待下一轮事件识别，不把真实缺口伪装为完整。

## 执行台账

### 开发契约
- 必赢场景：刚结束会议，用户打开详情点击等待状态，确认或校正时间；未改直接精转，改时重新 LLM 整理后精转，两种结果都不再自动接长，详情能读到真实处理状态。
- 原子交付：一个批次覆盖 Core、协议、GUI、存储迁移、针对性测试、合成 UI 验收、文档、独立审查及提交。旧持久库新增可空列，组件协议整体升级，不发布/安装正式应用。
- 必须保证：两分支语义、结束保护、保留旧结果、ASR复用、操作收纳、真实状态及失败可重试。
- 明确不做：改采集/权限/供应商/队列调度器、自动恢复暂停、全历史重跑、强制模型语义正确、发布发行版。
- 本次负责的问题：人工完成与自动续接冲突、改时间的重整意图与最终结束事实、尾部音频迟到后的规划、GUI确认及回执处理。
- 状态来源与生命周期：Core唯一写入；named_events承载确认结束事实；一次性重整请求承载目标事件和完成意图；cloud_tasks唯一处理状态；event_asr_state/refs承载现有规划和复用事实；GUI仅草稿/busy/请求ID。
- 复用：Store::mutate_response、mutation_receipts、active_event、reorganization::enqueue/input/apply、publish_fit_with_input、asr::schedule/plan/inherit_coverage、Dialog/Modal、现有详情读取与刷新。
- 新增机制：现有事件表增加可空完成时间；现有一次性重整载荷增加可空完成目标/修订；新增ConfirmEventCompletion协议入口并正常升级版本。无新owner、队列、worker、重试器或第二状态库。
- 架构不变量：Core唯一事实源；模型负责语义、事务负责范围/来源/版本；ASR物理输入不可变；清理与人工修订高于迟到结果。

### 验收与结束条件
- Core：未改值保留摘要且只规划一次；修改任一端只入一笔LLM任务，输入含用户时间来源与目标；结果可变边界/多事件且全部结束；空变更也结束目标；失败/过期/清理不半写；自动旧linked/续接不能改已完成；后续可整理独立尾部；ASR引用与迟到原声可复用补齐；迁移兼容。
- GUI：顶部状态、默认值精度、未改/改时提交、取消/校验/失败/不确定回执、更多菜单与已有操作；合成真实组件交互和截图。
- 检查：npm typecheck/lint、受影响Node与Core/协议测试、cargo check workspace、npm verify、单机架构完整开发构建；不涉及OS/权限变更，不新增跨平台实机门槛。
- 按影响重跑：Core/协议更改影响Rust检查/测试/构建；UI更改影响前端检查/组件验收；最终文档状态不重复高成本构建。
- 结束：上述必做证据与requirements/adversarial/architecture审查全部通过，修复后受影响检查通过并提交；保留未覆盖平台说明，不擅自扩大功能。
