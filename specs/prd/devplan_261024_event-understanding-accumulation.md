# 修复事件理解跨窗遗忘

需求源：用户要求继续沿用窗口分析，旧要点保留、后文纠正能更新、summary 覆盖整场；用上一轮同一份真实长记录重跑并提供修复前后对比。用户随后确认关注一次 LLM 调用的边界：每个窗口仍一次调用，同时输出摘要与结构化内容。

原实现已完成存储、引用、失效，但真实 81 分钟回放暴露全量替换导致旧内容静默丢失。本 devplan 覆盖原 PRD 中“模型全量替换结构快照”的更新契约；已有持久 schema_version=1 不变。

## 开发契约

- 必赢场景：一场活动跨多个窗口，后窗只提供增量也保留旧要点及对象；后文明确纠正旧事实时替换对应要点而非留下互相矛盾的当前结论；整场摘要从累计内容生成，不能描述为当前窗小结。
- 原子交付：一个批次含代码、合成回归、原始真实记录回放对照、三视角审查及提交。不涉及安装发布；不修改活跃库。真实材料只保存在 research 私有忽略目录。
- 必须保证：每窗仍一次 LLM 调用；Core 默认保留实际目标的有效旧条目；更新只能显式引用请求中目标数组的下标，且必须带合法当前窗证据；错误更新不得删旧内容。更正或撤回写成带最新状态的替换陈述（如“原定周五，现改为周一”或“此方案已撤回”），不新增删除日志。同一请求多个修改不能重复消费同一旧条目。
- 结构契约：topics 为新增标签、保留原主题并去重；key_points/mentioned_objects 为新增或替换条目，模型输出要求每条包含 replaces，对应输入显式 item_index（旧数组零基下标）列表；Core 容忍缺失/空并按新增处理。替换列表只作用于实际目标；替换通过后移除被替换旧条目，写入新条目。纯重复条目合并引用，语义合并由模型显式 replaces；只有真正等价重复或明确更正/撤回才替换，补充、举例、不同观点均新增。无有效旧快照时仍按既有完整性规则，不伪造历史。
- summary：同次调用先判断增量，再依据“旧条目经本轮修订后的累计内容”写整场总分摘要，保留早期、中段和尾段主线及具体辨识细节；约 500 字指导，不截断、不拼接旧摘要、不增加第二次生成请求。合成检查验证传递/存储，真实回放人工核对语义覆盖；不承诺任意模型对所有会议零遗漏。
- 明确不做：新队列/状态机、独立总结任务、全量粗转重送、历史自动回填、全局实体、前端结构展示、数据库迁移、模型切换。无需恢复旧版本已遗失且未留快照的内容。原粗转噪声与说话人混淆不是本次修复范围。
- 状态来源与生命周期：named_events 当前 summary/understanding_json 唯一派生快照；coarse_segments 为引用权威。replaces 仅请求局部下标，不持久化。发布前输入快照/revision/观察比对与人工纠错、清理、范围锁保持优先。
- 复用：events::llm_input / fit_context / FIT_SYSTEM / publish_fit_with_input，understanding::prepare_context / normalize，原队列、Store、SQLite 事务、interpretation_for_scope。
- 新增机制：无持久 owner/store/协议/重试；只修改既有 LLM 私有输出契约与原 normalize 中的合并规则。
- 适用不变量：Core 唯一写入者；候选窗不是活动边界；不混入并行事件引用；迟到响应不得复活失效语义；原始文字不被摘要反写。

## 验收与结束条件

1. 合成 3+ 窗口：后窗只返回新条目，旧文本/引用仍在；显式修改、撤回、合并生效，错误/越界/跨来源更新不能删旧条目。
2. 重复发布不增重复条目；linked 重分析与续接使用相同规则；既有 scope、纠错、缺引用、迟到保护、legacy null 回归通过。
3. 同一真实粗转、同一模型、同一生产链路：早期咨询分身、看板四项、订单指标/斜率，中段秘书/一手证据，后段日报与 Agent 记忆在最终累计结构可查；summary 明确包含早中后主线。真实素材没有明确的排期纠正，另用合成纠正样本验证，不伪称真实记录验证了所有纠正。
4. Rust 定向与 Core 回归、workspace check/build；不改前端则其既有检查不重复。私有回放使用同签名隔离测试入口，不执行 ASR、不覆盖安装版。
5. requirements/adversarial 与最终 architecture 审查通过后显式暂存本任务文件并提交。最终代码及报告对应，留存所有调用输出，不择优隐藏失败。没有新增 OS 行为，安装不是本次门槛。
