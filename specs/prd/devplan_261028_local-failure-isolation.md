## 执行台账

### 开发契约
- 必赢场景：一个极短或失败粗转片段不能让整场精转永久停顿；其它片段、来源和既有文字继续可用。新 worker 能处理实际失败输入长度并安全结束。
- 原子交付：同一 PR 交付实现、合成回归、安装版对照/新构建真实模型验证、冻结库只读回放、诊断说明。已发布任务身份、原声、清理墓碑和人工修改是兼容责任。
- 必须保证：Core 是唯一状态 owner；worker 只计算；可重试的本地工作仍参与稳定性判断；失败不伪装成完成；有效结果/已有付费请求不被重做；来源、时间范围与清理边界准确。
- 明确不做 / 不保证：不安装或重启用户客户端，不修改活跃库，不自动重传历史云任务，不新增采集后端，不声称修复 macOS 睡眠时无法采样或保证所有屏幕环境可采集。
- 本次负责的问题：上述已确认输入/调度/生命周期/日志边界缺陷，以及修复引入的相邻路径回归；环境不可用本身与未证实的设备故障记录为限制。
- 状态来源与生命周期：持久事实来自 `audio_blocks` / `coarse_jobs` / `cloud_tasks` / `event_asr_refs`；局部问题只读派生；重试仍由各现有队列管理；模型临时补齐不写回媒体。
- 复用的既有抽象：`AnalysisClient`、`coarse::publish/failed`、`events::asr::settling_state/refresh/plan`、`TimelineItem`、`LogEvent/LogContext`、`source_process::error_code`、`capture_supervisor`、`read_request/serve_one`。
- 新增架构机制：无新增持久状态、owner、队列、后台服务或重试框架；仅扩展既有只读投影/日志的可选字段及模型输入适配。
- 架构不变量：记录/粗转/精转/人物识别独立；真实时钟不能因补齐或失败而改变；错误影响限于来源/任务/范围；不能靠删除失败证据或降低校验掩盖错误。

### 验收与结束条件
- 极短、空、正常输入均有确定行为；真实 X-ASR 连续多请求烟测覆盖 0 / 1 / 32 / 1056 / 2080 / 3200 / 正常长度；非空输入不丢样本。
- failed VAD / coarse 不永久阻塞其它可用音频；pending/processing 仍等待；不同来源与相邻事件不互相污染；重复规划不新增重复任务；无原声不伪造成功。
- 冻结 10/27 SQLite 副本运行生产规划器，两场事件产生可用精转输入；原失败记录、原声、文字、既有云端 ID 不变；不调用云端。
- orphan worker 的强制退出跳过 atexit/C++ 析构；采集正常停止仍保留原封块路径。
- IPC 断连、无效 JSON、执行失败、写回失败有不同固定分类；已知请求 ID 保留，日志不泄漏请求/凭据；声纹延期为 info。
- 本地处理异常与精转主状态并列展示；旧响应缺少新增字段时兼容；React 交互回归验证。
- 验证：适用静态检查、Rust workspace/前端/Python/原生已有门禁、全工作区构建与隔离 Core/诊断烟测、针对性真实模型/冻结库/原生错误传播验证。
- 检查失效规则：worker 改动重跑模型/退出烟测；planner/projection 改动重跑范围与冻结库；UI 改动重跑前端；native/日志改动重跑错误分类与相关原生编译/烟测。最终统一 verify 通过后不无故重跑。
- 结束条件：上述证据与 required requirements/adversarial/architecture 三路审查完成，阻塞项修复且 architecture PASS，提交并创建 PR。发布安装/长期关屏观测属于后续发行门禁，本 PR 不宣称已安装验收。
