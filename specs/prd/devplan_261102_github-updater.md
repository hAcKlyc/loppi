## 执行台账

### 开发契约
- 必赢场景：启动静默检查并下载，设置可手动检查并展示版本/反馈；下载验签完成后左下角侧边栏才出现绿色「重启更新」，点击后不再请求网络、无确认弹窗，直接退出 Core、安装并重启。不点击以及网络/验签失败不影响录音；退出失败不安装；安装失败恢复 GUI 请求能力并可重试。
- 原子交付：三平台的运行流程、更新产物、清单合并与 GitHub 发布入口、测试和文档同次实现；既有无更新功能旧版须手动安装一次。不修改已公开版本或发布未经验证的候选。
- 必须保证：应用端固定 HTTPS GitHub endpoint；按平台/架构匹配，较新版本才提示；原生端串行检查/安装，安装绑定用户看到的版本；验签必须保留；不直接写业务数据库，不强杀 Core/采集进程；更新不会修改录音意图/配置。
- 明确不做：静默安装、定期轮询、断点续传、跨重启缓存、增量更新、测试通道、私有 Release 鉴权、自动发布当前 0.1.18。仅检查失败不弹窗打扰，但设置可见并可重试。
- 本次负责的问题：更新的状态并发、下载与退出顺序、失败恢复、Mac 最终签名/公证包的归档顺序、Windows 安装器退出集成、发布 JSON 完整性与三平台一致性。
- 状态来源与生命周期：当前版本来自 Tauri package_info；远端版本来自 GitHub latest.json；原生宿主会话内保留已验签匿名临时文件与对应 Update 对象并串行操作，GUI 只投影元信息和进度，不持久化第二份事实；Core 是录音和数据库唯一 owner。密钥仅在仓库外，公钥在配置，发行构建必须匹配签名。
- 复用的既有抽象：loppi_protocol::quit_gui_core、lifecycle 的 SESSION/owner 锁等待、EntryRuntime 的刷新、playback_output::shutdown、NSIS prepare-install hooks、Controls 的 Button、build.mjs / build_windows.mjs / package_macos.sh。
- 新增架构机制：Tauri updater 插件及宿主会话内的单飞 Update 槽和匿名临时文件（进程退出自动释放、避免包体常驻内存）；可恢复的 GUI 请求屏障用于安装失败恢复。均属于用户授权更新所需宿主生命周期，不增加 Core 业务协议/持久 store/后台调度。
- 适用不变量：Core 唯一写入者；退出等待录音尾块封存、owner 锁释放，不启动缺失 Core，不杀进程；已发布包身份不可改写；更新包必须取最终完成系统签名/公证的完整组件集。
