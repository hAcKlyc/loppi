## 执行台账

### 开发契约
- 必赢场景：一场多议题两小时会议跨两个一小时计算窗续接同一 ID；连续家庭聊天包含换话题、短暂停顿仍为一个活动；明确散会后打电话、两场相邻会议分别输出事件。
- 原子交付：候选策略、prompt、跨窗上下文、队列顺序、回归和合成样本真实模型验证一起交付。
- 必须保证：候选窗口不成为事件上限；不按话题、来源或疑似换人自动拆分；真正不同活动不按时间接近硬合并；原始音频与粗转时间不改写；人工边界、清理、精转引用继续由既有 owner 裁决。
- 兼容：已有候选起点保留为计算切点，避免从 30 分钟改为 60 分钟直接吞并两个已持久化候选；输入哈希格式不变，不因 prompt 文案变更重跑历史。晚到新证据仍走已有候选修订路径。
- 明确不做：粗转声纹/分人、人物数据上传、新的历史重整服务、批量修改历史事件、新增 UI、修改 ASR 物理切块、重启/安装运行中的 App。此次处理新输入与待处理任务的粒度；已有被拆碎的历史记录不自动批量重整。
- 状态来源：`events.rs` 的候选策略、`FIT_SYSTEM`、`llm_input`/`fit_context` 与 `cloud_tasks`；仅 Core 写入，模型输出仍是受校验提案。
- 复用：`build_candidates_with_cuts`、`refresh_candidates_in`、`take_task_fair`、`evidence`、`publish_fit_with_input`、`event_candidate_links`、既有 ASR 引用。
- 新增架构机制：无新状态表、服务、协议或队列；使用既有候选持久起点、任务排序与有界上下文。
- 架构不变量：真实音频轴不可重排；事件是虚拟范围；音源不是说话人；人工事实优先；新摘要不凭粗转猜身份。

### 验收与结束条件
- 静态/构建：受影响 Rust crate 的 check、build。
- 行为回归：60 分钟墙钟封口、旧 30 分钟候选不被重新分组、跨窗续接、不同活动分离、队列排序、边界上下文有界且来源/时间正确、人工边界与清理回归。
- 真实模型：只用合成对话，调用当前已配置模型，验证长会议、连续闲聊、明确活动切换与同话题不同活动；检验真实 JSON 和发布路径，不把手写 merge 响应当模型质量证据。不得发送本机真实转录或写用户事件库。
- mandatory：上述自动验证及三路 fresh-context cross-review；advisory：真实生活录音上的长期粒度观察，无法由有限样本保证每次语义判断正确。
- 修改候选/输入/发布需重跑对应行为回归与 Rust check/build；修改 prompt 需重跑相关合成模型场景。无 UI/OS 功能改动，不要求重启正在录制的 App。
- 结束：必做检查和 required reviews 通过后提交；说明新构建尚未安装加载与一小时批次的产出延迟变化。
