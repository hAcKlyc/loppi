# hear 0.1 产品需求

## 0. 文档状态与阅读方式

本 PRD 记录首版已经确认的产品行为和交付边界。产品决策来自持续的需求讨论，详细过程见[讨论台账](_drafts/hear-0.1-readiness.md)；未来需求见[后续版本需求](BACKLOG.md)。[技术 RFC](tech_rfc_0.1.md)已按本版范围重新整理，但其实现选择、模型、资源数字和供应商接口仍须原型验证。产品行为以本 PRD 为准。

本版要交付一个完整的 macOS 产品闭环。开发可拆内部批次，但不能把缺少持续记录、事件整理、找回或完整 CLI 的半成品当作 0.1 完成。具体模型、算法阈值、供应商适配细节、资源指标和最低支持系统版本由工程验证确定；本文不把候选参数写成用户已确认的固定规则。

**执行须知：**零上下文接手时先完整阅读本 PRD、[技术 RFC](tech_rfc_0.1.md)、[开发计划](../../plan.md)与本文件末尾的执行台账。本仓库已有开发中的 macOS 应用基础，但尚无 `CLAUDE.md`；MyAgents 源码仅作技术参考，代码复制前须核查权利与许可。一份 PRD 是一次原子交付；下列 Batch 仅供实现、验证、独立审查和提交。实机采集质量、长期资源、云服务真实请求、人物匹配、安装版权限及签名公证均为交付硬门槛，未通过时保持 `in-progress`，不得声称 0.1 完成。

0.1 通过 macOS `.dmg` 直接分发，不以 Mac App Store 上架为交付条件。hear 源码现阶段保持闭源；未来是否开源及开源许可证尚未决定，Apache-2.0 与 AGPL-3.0 只是以后可评估的候选，不是本版承诺。

## 1. 产品定位与成功结果

### 1.1 长期方向与首版焦点

hear 的长期方向是个人上下文记录。0.1 聚焦一台工作电脑上的两种输入：**持续声音记录**与**有限的用户主动截图**。工作场景是优先优化的使用场景，会议、通话、临时讨论是主要样本；有连续内容的课程、播客或电脑播放的视频也可以形成记录，不按“是不是工作”硬过滤。

产品的核心价值是降低用户决定“现在要不要记”的成本，以及持续记录带来的注意力开销。用户完成一次设置并启用后，在电脑可用期间不必为每场对话点开始和结束；系统自动留下人声，轻量加工成可定位的文字与大块事件，同时控制资源、能耗和磁盘占用。Mark、截图和评论可补充线索，但不是持续记录和自动整理的前提。

用户的原声音频、截图、时刻动作和派生记录以本机存储为主；0.1 不自动把整份历史同步到 hear 云端。只有本 PRD 明确的 LLM 事件拟合与 ASR 精转输入会在启用后送往用户配置的供应商；用户另行选择导出文件不扩大后台外发范围。

hear 是独立产品；安装或运行 MyAgents 不是使用前提。MyAgents 可以在未来通过用户授权的本地能力读取或使用选定内容，但不能拥有 hear 的采集、存储和清理状态。

### 1.2 “24 小时”的含义

“24 小时记录”是一种**电脑可用时持续开启的工作方式**，不表示每天必须产生 24 小时音频，也不是“音频仅保留 24 小时”。首版从用户登录、首次设置及权限就绪、且启用意图为开启时开始自动工作；锁屏但未睡眠时继续。电脑睡眠、关机、尚未登录或应用完全退出时不承诺采集。唤醒或下次登录后，依照上次启用意图恢复；用户主动暂停始终保持暂停，不被唤醒、接电或重启覆盖。

### 1.3 用户应得到的结果

用户能沿自己经历的**一条连续时间线**回看：某场会议从开始到结束是一个大块，能够查看整场声音、完整文字稿及期间主动截取的画面和评论。经用户建档的同一个人在不同事件里能够复用人物名并按人找回发言，未建档或无法可靠匹配时仍可看到本场说话人编号。相邻有声素材未被认定为明确事件时，仍在原时间位置作为较大的未整理时间块存在，可回听、按时间找回、手动精转或清理。用户能看到真正未采集、尚未处理、处理失败与已清理的区别。

## 2. 0.1 交付范围

### 2.1 必须完成

- macOS 桌面应用：首次设置、持续记录、悬浮操作、按日浏览的连续时间线、历史、设置和清理；首版图形界面不提供搜索入口或搜索页。
- 麦克风与电脑播放声音两路采集，默认启用，可分别关闭；本地语音检测与录制中的实时粗转录。
- 独立的声音保留策略：自动清理静音及本地语音检测判为无人声的噪音；不把无法绝对证明无人声的环境音长期留下。检测到的人声音频和已有粗转文字默认持续保存。
- 两层时间轴：真实声音与采集状态为底层事实，虚拟事件轴按真实活动形成命名的大块事件；其余保留内容自然成为未整理大块。
- 必配的两项云端能力：LLM 对本地粗文字做事件拟合、命名和自动精转判定；ASR 对符合条件的完整事件精转。最终文字稿必须提供会话内说话人分段，具体由本机分段能力或经验证的 ASR 能力实现；两项云端能力分别配置、分别暂停及恢复。
- 全局人物声纹库：会话内说话人先自动匹配已有的人物身份；用户给未匹配的说话人命名或选择已有的人物后，人物与合格的声音样例在此后的事件中复用，并可修正错误匹配。
- 用户主动整屏截图、Mark、评论；本地截图 OCR；从未整理时间段圈定范围并新建命名事件、修改已有事件的起止时间，以及标题、说话人归属和精转句段文字的人工修正；本地搜索索引与 CLI 关键词、日期、人物搜索；音频回放和选定范围导出。
- 全局音频占用上限、实际磁盘安全线、提前提醒、达到边界后暂停录音；“清除原始音频”和“清除全部数据”两种统一清理操作。
- 覆盖本版产品核心工作流的完整 macOS CLI，与图形界面使用同一产品规则。

### 2.2 不属于 0.1

持续录像、自动周期截图、键盘输入监控、浏览历史或日历账号采集、手机/可穿戴设备、多人协作、自动执行谈话指令、内置通用聊天、自然语言记忆问答或语义搜索、事件自动摘要和关键结论、用户自定义的主题 Prompt/Skill 工作流、MCP 或通用网络服务。全局人物声纹库指本机 hear 历史中的跨事件复用；多设备同步、向其他应用共享人物身份及认证真实姓名不属于本版。Windows 是后续平台，不构成本版验收范围。后续主题处理可以预留内部扩展点，但不因此形成 0.1 的用户可配置功能。

## 3. 首次设置与启用

首次设置以 [单页首次设置 PRD](prd_0.1_onboarding.md) 为准：唯一「准备 Hear」页面集中本地组件、所选声音来源授权、DeepSeek 与火山引擎两项 API Key。模型由用户触发下载，必要模型必须校验与加载成功；云凭据分别验证并保存到 Keychain。读取和操作失败原地恢复，已有进度保留。

点击「完成设置」只进入正常时间线，仍由用户主动开始首次记录；不提供必经试录、欢迎或完成页，不自动注册登录项。登录启动、记录计划及其他偏好继续在设置中管理。「稍后设置」可浏览首页并保留继续设置入口；初次实际业务门槛仍由 Core 执行。已使用用户升级不重置暂停、来源、计划和登录选择。

首次启用要求两项云端能力都配置，是 0.1 的产品门槛。完成后，暂停云处理、断网或供应商故障不阻止已启用的本地采集与粗转，相关云任务通过队列和设置恢复；不要求重走首次页。真实录音与云结果作为研发端到端验收，不做产品必经教学步骤。

## 4. 单一时间线与两层数据模型

### 4.1 真实音频时间轴：发生了什么

用户经历按一条线性时间顺序展开。底层记录电脑何时处于采集、睡眠、手动暂停、容量不足暂停、设备/权限异常等状态；麦克风和电脑声音是可以同时存在的两个来源，带各自时间定位。语音片段、粗转句段、音频文件封块、截图、Mark 与评论都锚定实际时间和来源；文件或句段有多碎，不改变用户经历的顺序。

真实层应区分：确定静音或无人声噪音、保留的人声、疑似人声、模型未识别出文字、真实采集缺口。**没有粗转文字不等于没有人声**。粗转失败、模型落后、权限丢失或设备断开也不能被写成“安静”。睡眠、时钟变化与设备切换后的时间映射应保留真实顺序和缺口；仅有墙上时间的起止值不足以证明音频连续。

### 4.2 虚拟事件轴：这段时间在做什么

虚拟事件轴与真实层使用同一时间坐标，但只承担组织和呈现：在实际活动的开始至结束之间圈出大块事件，必要时赋予主题标题，并关联该时段的音频、转录、截图及用户动作。虚拟分组不移动、不复制、不重排真实发生的素材，也不决定底层人声是否保存。

一个两小时会议可以包含许多本地语音片段和中间讨论间隙，仍是从会议开始到结束的**一个事件区间**；无声或已清理的无人声噪音只影响内部可播放素材，不把会议切碎。会议内换议题仍是一场活动；会议结束后另起的谈话，即使沿用原议题，也是下一段经历。相邻区间确定属于同一活动时可合并；证据不足时宁可漏合并，不强行把不同经历合在一起。短但信息明确的谈话也能形成事件，没有固定的最小时长。

命名事件圈出后，未被组织且仍有留存人声、文字、截图、Mark 或评论的时间，在原位置自然表现为**未整理大块**。不把它们藏进另一个“原始录音”入口，也不按每一句或每个音频文件逐条列成事件。一个未整理大块可以含很多空白：例如 12:00–15:00 零散几句话，15:00–16:00 是已识别会议，则前者仍可作为 12:00–15:00 的大块回看，语句留在各自时刻。安静时只有一张主动截图或一条评论，该时刻同样必须在主时间线上可见。无声时间保留时间位置；没有任何留存素材或用户动作的区间不需制造空事件。按日期浏览只是导航方式，不能把跨午夜的同一场活动拆成两个事件。

同一时刻麦克风与系统声音可能属于同一对话，也可能是互不相关的两件事。同一对话可在一个事件中关联两路；无关活动可在相同时间并列标注，未整理的另一来源也不能被当前命名事件吞掉。呈现仍以用户的一条主时间线为准，不虚构先后顺序或拆出两条“主人公时间线”。

### 4.3 内容与引用

| 对象 | 产品含义 | 不可破坏的关系 |
|---|---|---|
| 音频素材 | 来源及真实时间范围内留存的人声 | 物理封块不等于事件；删除或缺失后须准确显示不可回放 |
| 粗转文字 | 本地实时识别的带时刻句段 | 是派生结果，允许错漏；空文字不证明无人声 |
| 事件 | 一场真实活动的起止区间、标题与关联来源 | 可修订；不改写底层时间和音频事实 |
| 未整理大块 | 命名事件之外仍有留存声音、文字或用户动作的连续时间 | 保持可见、可检索；有原声音频时可手动精转，也可按范围清理 |
| 人物/声纹样例 | 跨事件复用的稳定人物 ID、显示名及由用户确认的声音证据 | 与每场临时 speaker 编号分开；样例锚定原声范围、来源和提取版本，可撤销或更新 |
| 截图/Mark/评论 | 主动操作形成的时刻锚点 | 后续事件边界变化时重新归属，不移动原时刻 |
| 精转/OCR | 基于明确输入产生的派生内容 | 保留输入范围、来源及版本；精转句段的人工修正另存，不能改写原识别结果 |

用户可在未整理大块中选择真实时间区间和关联声音来源，手动创建并命名事件；也可直接修改已有事件的开始或结束时间。事件范围可覆盖活动内的安静间隙，不要求每一分钟都有音频。事件拆分、合并、重新命名、改边界和取消错误的事件标注都只改变虚拟组织；取消标注后，底层声音、文字和用户动作回到其原时间位置的未整理区域，不被删除。创建或扩大事件时，若新范围会与同一来源的其他命名事件发生冲突，须让用户看到冲突并先调整边界、拆分或合并；不同来源的独立活动仍可在时间上并列。用户手动改过的标题或边界有独立优先权，不被后续自动拟合无提示覆盖；用户主动取消的错误标注也不能立即被同一轮自动结果重新建立。旧事件引用发生拆分时应能说明后继范围，不能静默跳到某一段不同内容。截图与评论先属于实际时刻，随后根据当前事件边界显示；独立于是否已有事件，截图或评论仍可保存。

## 5. 第一层：持续采集、声音筛选与本地粗转录

### 5.1 采集与省资源行为

开启记录时，两路声音各自判断是否有内容。长期无声时避免持续写空音频或反复调用粗转模型，以低负担监测声音恢复；有声音时及时保存句首，不能以节能为理由漏掉开头。已开启的静音待机仍是记录状态，区别于用户手动暂停或关闭来源。具体轻量监测、前缀缓存、封块和功耗参数由原型验证；不宣称零功耗。

电脑仍醒着但显示器自然熄灭时，也属于持续记录范围；屏幕是否亮起不能决定电脑播放声音来源是否可录。整机实际睡眠或关机期间不要求采集，恢复后须按既定记录意图继续，并标明真实缺口。

电池、发热或前台负载压力下，优先让本地重计算与云端整理排队、降速，保持已经启用的声音采集。低电量本身不是静默停止录音的授权；除用户主动暂停、已确认的容量/磁盘边界或系统实际使采集不可用外，不能仅为了资源数字好看而制造未提示的声音缺口。无法继续采集时要立即显示原因和真实中断范围。

“电脑播放声音”指当前设备的系统输出声轨，包括会议对方声音及用户播放的课程、播客等。首版不承诺逐个应用选择或准确识别声音来自哪个应用；来源选择的用户层级是麦克风与系统声音两路。

回放 hear 自己保存的声音时，不应把这段回放再次当作新的谈话持续归档、标成新事件或送去精转。双路采集可能同时听到同一声音；必须保留真实来源，并在整理时避免因回声重复制造两份会话。

本地粗转录应在录制过程中持续产生带时间和来源的稳定文本片段，而非整场会议结束后才开始。音频采集、持久化和识别相互解耦；识别变慢时保留真实采集状态及待处理范围，不能把“已录到”伪报成“已转写”。可复用 MyAgents「录音记录」的采集、语音检测、实时转录代码基础，但 hear 需重新适配全天持续运行、跨睡眠/重启、多日存储和全局清理；MyAgents 一次 Record 或其内部 Session 不是 hear 的全天事件。

### 5.2 独立的声音保留策略

声音保留判断是一个独立、可调试的环节，**不以事件价值、粗转文字质量或是否被命名为删除门槛**：

| 判断 | 0.1 行为 |
|---|---|
| 数字静音，或本地语音检测未发现人声的非零环境音、风扇、键盘、提示音、纯音乐等 | 清除相应原始音频；保留真实时间位置和判定状态。非零声音可先短暂封存供本地检测，得出无人声结果后清理，不要求证明绝对无人声 |
| 有人声，虽无聚焦主题、只有零散句子或粗转文字意义不明 | 保留人声音频及已有粗转文字，留在时间线上的未整理区域 |
| 本地语音检测发现人声，虽很远、被噪音盖住，或粗转为空/失败 | 保留音频并标识识别状态；粗转是否有字不是删除依据 |
| 本地检测尚未完成、模型不可用或处理失败 | 保持待判定/失败状态，不能伪称已判为无人声；恢复后继续判定，必要时供用户排查 |
| 连续且有意义的对话、会议或其他完整内容 | 保留整段活动中的人声，进入事件拟合与可能的精转 |

用户明确决定：无法绝对确定无人声的环境噪音也不长期保留。夹杂人声的音乐或环境声须尽量保留检测到人声的部分；语音检测可能漏掉极弱或受遮盖的人声，因此分类阈值、跨封块延迟判定、误删率和弱声样本必须独立测量与迭代。音频清理可移除内部无声素材，但虚拟事件仍保持整场活动的起止区间。策略变更只对新采集素材自动生效；升级前已保存的原声不未经预览批量追溯删除。

保留下来的人声音频和对应粗转文字**默认持续存在**，无论已处理、未处理、拟合失败、是否命名或是否被用户 Mark。不存在“未成事件 24 小时后自动删除”规则，也不设置与事件资格挂钩的补救池。可用时间受用户主动清理和全局容量暂停约束。

## 6. 第二层：候选切分、LLM 事件拟合与精转判定

### 6.1 候选只是计算输入

事件拟合先使用可替换策略把时间锚定的粗转文字及第一层的有人声/识别失败信号组织为候选区间。初始设想是“约 15 分钟没有可用粗转文字”可提示候选封口，但 15 分钟是待调试参数，不能写死成架构边界或真正的会议结束条件。疑似人声或识别失败不应被当成确定的无声；持续检测到谈话却粗转为空时，候选仍须携带这项事实进入事件判断，不能因没有文字直接丢弃。连续很久没有空档时，可为计算资源而切换输入封块；计算封块仍不直接成为用户层事件。

LLM 读取相邻候选的上下文，在实际时间顺序中判断是否属于同一活动、是否需要拆开两个活动、是否应命名，以及是否进入精转。它可以跨候选合并真实的同一场会议，也可以拆开连续说话中实际结束又开始的两个活动；内部静默、话题变化或短句数量不能单独决定边界。无法可靠判断时保留分开或未整理状态，不编造会议身份、人物与结论。

### 6.2 从进行中到稳定事件

活动尚在进行时，时间线上可先显示持续增长的“进行中”大块，本地粗转文字逐步出现；这个块是暂定组织，不冒充已完成的云端判断。活动结束、LLM 拟合完成后再确定事件范围和标题。自动起止时间由实际声音、粗文字、时间连续性等已有证据估计；如果活动在第一句之前或最后一句之后有无法判定的静默，界面不能假称系统精确知道会议开始或结束。用户可在未整理范围手动补建事件，也可调整已有事件的开始和结束时间。后续证据可修正未被用户手动调整的自动边界；手动补建、标题、拆分、合并及相应边界优先。修订影响当前虚拟分组及附属内容映射，不重排原音频或时刻动作。

有明确意义的短片段可以直接命名；明显连续的人声会话即使粗转录很差，也应保守形成普通会话事件、标明“识别不清”并进入精转，而非因文字少被丢弃。信息量不足的人声不强行取标题，作为未整理大块留存。是否命名和精转只决定处理深度，不能决定基础素材的存亡。

### 6.3 自动精转规则

LLM 工作流负责自动判断并创建 ASR 待办。对它判定成立的有效事件，0.1 默认**整场精转**：覆盖事件区间内保留的完整有声会话，不只挑 Mark、关键词、重点发言或粗转差的片段；传输分块是实现细节。已经确认应精转的事件不因为粗转看似清楚而跳过。用户从未整理范围手动补建并命名事件，是一次明确的精转请求：保存事件后，直接为当前事件区间内保留的完整有声会话创建 ASR 待办，不等待 LLM 再决定是否值得精转；若没有可用原声，则保留事件并明示不能精转。对未命名原始素材，用户仍可选择未整理大块中的**一段连续的真实时间区间**及声音来源，显式发起手动精转并直接进入 ASR 待办。该范围立即在虚拟事件轴上成为独立的**未命名精转事件**，不等待 ASR 完成，也不自动生成标题；原未整理大块在选中区间前后分成仍以粗转为主的未整理块，切分只影响虚拟组织，不剪切或复制底层音频。事件内可见独立的排队、进行中、完成、无文字或失败状态。若范围与已有命名事件相交，同一来源的命名事件优先展示，手动范围仅投影其尚未被命名事件覆盖的部分，不能覆盖人工或自动命名事件。两类手动请求都遵守 ASR 队列暂停状态，暂停时显示为待处理。精转结果回到原时间位置。

精转必须保留来源和时间定位，最终文字稿须在一场会话内分段标出不同发言者。首版**优先使用火山云端 ASR 对一场活动的连续音频完成会话内说话人分段**，让云端尽量看到整场上下文；实时本地粗转仍独立运行。只有供应商实测限制或实际音频缺口要求时才切成多个物理请求；物理请求的临时 speaker 编号必须按请求隔离，并在有可信声音证据时才跨请求合并，不能直接拼成十几位“人物”。云端分段可能把同一人误拆：在证据不足时保留“未知说话人”或待用户核对，不能将每个云编号无条件当作真实人数。每场的“说话人 1/2”只是临时编号，不能因为另一场也叫“说话人 1”就视作同一个人；全局身份须经过 6.4 的本机声纹匹配或用户指定，首版不要求把人物库上传云端。事件拆分、合并后应按新范围重新核对标签。如果云端输出不能可靠定位到当前素材区间，不得把旧结果错误挂到修改后的事件。精转文本与原始粗转文字的来源和处理状态应能区分，失败时不抹掉仍可用的本地结果。本地实时粗转录不要求同步完成说话人分段或身份匹配。

2026-10-22 用户确认的数据可用性原则：供应商文字按实际请求时间轴和当前归属发布，保留完整原文与时间，接受偶发长停顿或补入静默内的结果。本机 VAD、当前原声留存、静默长度、首尾误差、原声占比或最小重叠都不能导致整段文字被拒绝。时间映射、请求范围、版本与清理边界仍须正确；声纹与回放独立验证真实原声，可用文字不依赖它们完成。

用户修改已命名事件的起止时间后，当前事件的精转覆盖范围须自动跟着更新：已落在当前范围且时间定位可靠的结果可复用；新纳入而尚未精转的有声素材自动排入 ASR 队列；移出的文字不再作为该事件的文字稿展示。说话人分段也须按新范围重新核对，不能把不同请求中相同编号的发言者直接视为同一人。无法可靠局部复用时，对当前范围重新精转，不能把旧范围的结果冒充为完整新事件。若新增范围的原声音频已清理或从未采集，须明确显示相应范围无法精转，不把“已入队”或旧文字标成“整场完成”。范围修订不能使旧任务或迟到结果覆盖当前事件版本。

用户也可在命名事件详情明确发起「重新精转」，以当前边界和声音来源生成新的一轮整场云任务，无需微调事件时间。旧任务及原识别句段保留作人工纠错和身份锚点，但退出当前文字投影；旧人工修正仅在新句段的来源与时间能唯一对应时自动恢复，否则保留在待核对列表。重新精转不改动事件标题、起止时刻或原声，也不能把云端新出现的短暂 speaker 编号直接宣称为新人物。

用户可逐句修正精转文字中的识别错误，例如人名、术语或数字，并可撤销修正回到原识别文字。这是对已有精转句段的轻量纠错，不提供任意新增整篇逐字稿、编辑原声音频或首版修改本地粗转文字。人工修正另存并锚定原声来源与时间范围，不改写供应商原结果、时间戳或说话人归属；显示、搜索与导出使用当前有效的修正文字，并标明人工修正。重新精转或事件边界修订时，定位仍可靠的人工修正优先于新自动结果；若新分句与原句无法可靠对应，则保留修正记录并标为待核对，不悄悄覆盖、丢弃或贴到错误发言上。原声已清理但精转文字仍在时，可继续修正文字；“清除全部数据”则按选中范围一并删除修正记录。

### 6.4 全局人物声纹库与自动匹配

0.1 的人物库在本机 hear 中全局有效，覆盖过去和之后的事件，而非每场会议各有一套名字。人物拥有稳定 ID 和可修改的显示名；声音样例、声纹特征及其原声时间/来源锚点关联到人物。会话内的临时 speaker 编号和全局人物 ID 是不同对象。声纹匹配用于识别用户建档的人，不宣称根据声音推断陌生人的真实姓名。

每次精转得到会话内说话人分段后，系统先从可用原声中提取说话人特征，自动与全局人物库匹配，然后才形成最终显示名。可靠匹配到已有且没有人工冲突的人物时直接显示其名字，并保留“自动匹配”来源；没有可信匹配时保持“说话人 1/2”等本场编号，明显混杂或无法区分时保持“未知说话人”，可以提示候选但不能强行命名。匹配在本机处理，不要求 LLM 猜人物，也不把声纹库因普通事件处理送到云端。精转的云端 ASR 若只给出临时编号，仍由本机完成跨事件比对；供应商返回相同编号不能直接当作跨事件身份。

用户打开任一说话人的身份选项时，应先看到全局人物列表，可选已有的人，也可输入名字创建新人。把未匹配的说话人命名为新人时，自动建立全局人物记录；把他选为已有的人时，绑定到该人物，不再创建重复记录。同名人物也须用稳定 ID 区分，输入已有名字时不自动合并两个档案。对本场 speaker 的人工指定默认作用于该说话人在本场的发言；若其中个别发言分段错归，用户还可按具体发言时间纠正，不能为修正一句话而把整场其他发言错误改名。用户确认身份后，系统自动从该说话人的清晰、单人发言中选取合格片段作为声纹样例；用户也可在纠错后主动选择具体片段追加样例。重叠发言、回声、短到不足以可靠提取或来源不明的片段不得污染样例库。即使当前没有合格样例，人工命名仍须保存，人物标为“尚无可用声纹”，直到有合格样例可用。用户可管理人物显示名、样例及错误归属；改名不改变稳定人物 ID，删除样例不删除原始事件文字。删除人物时撤回其身份归属，受影响的发言恢复本场说话人编号或未知状态，原转录和音频不因此删除。

新人物或样例建成后，已有未匹配的历史说话人和后续精转结果都应进入匹配范围；历史补匹配可在后台逐步完成，不阻塞录音、粗转和事件查看。人工指定或纠错优先于自动结果；用户否定过的匹配不能被同一证据立即重新赋名。人物匹配、声纹提取和人物库变化均有版本，事件重转、边界修订或样例删除后须按当前有效证据重新核对，不能把过期说话人编号、旧样例或迟到匹配结果直接挂回当前事件。实际匹配阈值、所需声音长度、跨麦克风/系统声道质量和资源消耗需在代表性样本上验证，不在 PRD 中硬编码数值。

## 7. 云端配置、队列、状态与外发范围

### 7.1 能力和数据边界

LLM 与 ASR 是两项独立配置的必备云端能力。LLM 自动接收候选区间内用于事件拟合的本地粗转文字、时间、来源及“检测到人声但未识别成文字”等状态信息，不自动接收原声音频；ASR 接收需要精转事件或用户手动指定区间的相应音频。全局声纹库及跨事件匹配在本机处理，不因配置这两项云端能力而自动上传人物列表或声纹特征。截图不因为配置这两项能力而自动上传；截图 OCR 本地处理，是否把截图交给其他 AI 属于用户后续明确选定内容的单独行为。用户自带供应商凭据，0.1 不建设 hear 账号、额度或计费后台。

本版以能力验证为主，**不实现应用侧月度预算上限、超额拦截或预算耗尽后补算逻辑**。供应商用量、计费方式、鉴权和请求终态仍需核实；对用户说明可核实的费用信息，不能显示推测的精确金额，也不能假称云调用免费或保证精转优于本地。云端短暂不可用不改变已授权的外发范围，也不授权上传全天声音。

### 7.2 两条持久队列

自动处理顺序是：本地持续产出粗转与候选 → LLM 队列拟合事件并决定是否精转 → 符合条件时创建 ASR 队列任务 → ASR 精转 → 本机说话人声纹匹配。LLM 没有给出新判定时，ASR 队列不能自行决定新事件是否值得精转；用户显式请求未整理素材精转、手动补建命名事件，以及修改已需精转事件的范围，是直接创建或更新 ASR 待办的例外。说话人声纹匹配是精转后的本地派生处理，不是第三项云端能力；已有历史的补匹配可排队渐进完成。任务和状态应跨应用重启保留。

LLM 与 ASR 可分别暂停和继续。暂停某队列后不再提交它的新云请求，已经送出的请求允许完成并保存有效结果。暂停 LLM 时，ASR 仍可处理此前已判定的待办；暂停 ASR 时，LLM 仍可拟合和排入新精转任务。用户点击继续后，该队列自动消化积压，不要求逐条再次批准。本地采集和粗转录不受这两项暂停影响。

断网或供应商暂时故障时，在未被用户主动暂停的前提下恢复后自动重试；持续失败留下明确状态并允许手动重试。对已提交但超时、结果不明的付费请求须先核对状态，不无限重发。手动请求优先响应；自动任务须绑定当时的素材范围和事件版本。边界修订或清理发生后，未发出的旧任务失效并按有效范围重建；已在途结果只有经当前素材、范围和版本校验后才能发布，不能复活已删内容或覆盖人工修订。

### 7.3 用户可理解的处理状态

采集状态、声音是否保存、粗转状态、事件拟合状态、精转状态、身份匹配状态和两条云队列的暂停状态分开表达，不能压缩成一个“已处理/未处理”。至少要能区分：待拟合、拟合中、拟合失败、已拟合但未命名、已命名待精转、精转中、精转失败、已精转，以及 LLM/ASR 各自已暂停。对说话人还须区分本场临时编号、自动匹配人物、人工确认人物及无法判定；匹配待处理不阻塞已完成的文字稿。未命名不等于失败；已录音不等于文字已就绪。具体视觉和文案可设计验证，但这些差异必须对用户可见。

## 8. 即时操作、时间线、搜索与修订

### 8.1 悬浮组件

日常入口是桌面常驻的轻量悬浮组件，显示记录/暂停等真实状态并及时响应。**单击主按钮立即标记这一刻为「重点」（Mark）**；悬停后在主按钮上方纵向展开截屏、评论、暂停/恢复三个操作，从下到上的顺序依次如此，不放其他入口。截图操作捕获当前正在操作的整块屏幕。历史和设置在独立窗口中使用，不把复杂页面塞进浮层。截图或 Mark 后不自动弹出评论；评论由用户主动进入。拖动与单击区分、多屏及全屏应用行为留给交互验证。

截图保存实际捕获的画面及触发/捕获时刻，不因用户延迟评论而重截已切换的窗口；失败不能伪报成功。Mark 表达“这一刻我觉得重要”，是时刻信号，**不自动截图、不等于收藏或音频保留指令，也不是自动整理或云端外发的必要条件**。Mark 成功仅说明该时刻信号已保存，不能暗示同一时刻的音频已落盘、能回放或未来声音已被保护。主动评论锚定用户选定或当时创建的时刻，提交时间不覆盖原锚点。三种动作均可在没有命名事件时独立存在，之后随事件边界重新映射。

### 8.2 历史与找回

主视图沿用户连续时间顺序展开，一场完整活动只显示一个大块，内部可查看带时间的粗/精转文字、来源、可回放音频、截图、Mark 和评论。命名事件之间的未整理大块同样可查看和操作；不再另造一个仅容纳零散声音的“原始录音”主入口。精转完成后默认展示带本场说话人分段的精转文字；匹配全局人物时显示人物名，未匹配时显示本场 speaker 编号，并可查看自动匹配还是人工确认。点击说话人可从全局人物列表选择已有的人，或输入名字创建新人并修正错误归属；人物库可单独查看和管理。粗转来源和处理状态仍可核对；同一段声音不会因粗转、精转各有一份文字而在搜索结果中无说明地重复出现。真正睡眠、手动暂停、容量暂停或设备异常造成的未记录时段标明原因；无声时段保留真实位置，不呈现为音频丢失。

日期日程默认同时显示命名事件、手动选出的未命名精转事件及其前后的粗转未整理块，并提供「隐藏粗转」开关。打开后仅从该日的事件列表隐藏**只有粗转或原声的未整理块**；命名事件、手动精转事件、独立的重点/截图/评论及未记录缺口仍可见，底层数据、搜索、导出和清理范围不受影响。初始状态为不隐藏；切换日期或工作台页面时沿用本次界面选择，重新打开应用恢复默认。

桌面事件详情采用左右并列布局：左侧顶部为录音播放与时间定位，下方仅有“文本转录”“音频信息”两个标签；转录按事件内时间正序显示句段及说话人。播放器当前位置与结束位置、每句转录、重点、笔记、截图及笔记输入位置都显示实际发生的本地钟点，不把音频文件内或事件内的相对播放时长冒充钟点；跨日期时须附日期避免歧义。音频文件和供应商结果可保留内部相对偏移，但点击上述真实时刻仍须准确定位到对应原声。右侧是持续可见的现场笔记区，把重点（Mark）、笔记（评论）和主动截图按原始时刻排成消息流，底部可写笔记。消息及转录中的时间可定位到事件内相应录音时刻；事后补写的笔记锚定用户选定的录音位置，不能以提交时刻冒充事件发生时刻。截图、重点和笔记仍各自保存真实时刻及来源，事件边界改变时只更新显示归属。

全局视觉与组件状态遵循 [`specs/DESIGN.md`](../DESIGN.md)：颜色、排版、间距、圆角、阴影、动效、层级和布局尺寸统一由语义 token 驱动，主窗口与悬浮球保持同一视觉语言。界面以内容和操作本身表达产品含义，不在标题/副标题堆叠技术隐喻或说明；可操作文字、焦点、空状态、等待与错误都须在真实窗口验收。

首版图形界面以日期切换和时间线浏览找回内容，不提供搜索按钮、搜索页或搜索筛选器；仍须完成本地搜索索引及 CLI 关键词、日期、人物搜索。CLI 搜索覆盖粗/精转文字、评论和截图 OCR 文字，结果回到原时间及所属来源/大块；按人物找回跨事件发言时仅使用仍有效的人工或自动身份归属。精转句段有人工修正时，默认展示并检索修正文字，原识别文字仍可供核对，不让同一时刻因为两份文字产生无说明的重复命中。截图 OCR 是本地索引能力；OCR 尚未完成或失败时明确状态，不能把“无命中”说成“没有这张图”。用户可在未整理大块中圈定起止时间、选择关联来源并新建命名事件，也可修改已有事件的起止时间、标题，或拆分、合并、取消错误的事件标注。手动建事件和边界修订后的精转进度应随当前范围显示；用户可逐句修正精转文字，但本版不提供完整逐字稿编辑器、粗转文字编辑或音频剪辑器。搜索没有找到内容时，应能区分未采集、处理待办、处理失败、已清理和真正无命中。

### 8.3 导出

图形界面和 CLI 都支持导出用户选定的事件、未整理大块或时间范围。导出清楚列明时间、来源、粗/精转来源与关联动作；默认不隐式附上全天历史。文字及必要元数据可导出，音频和截图由用户显式选入。已清理或不存在的素材不能因旧引用而重新导出；已导出副本不保证随日后本地清理撤回。

用户可自行将选定导出交给外部 AI；这不是授权 hear 在背景中持续向其他 AI 发送历史，也不要求 0.1 内置通用 AI 聊天入口。

精转文字的会话内说话人分段在查看和导出时保持一致；已归属的全局人物可连同当前显示名、稳定人物 ID 和自动/人工归属来源导出，未归属的仍只显示本场编号。人工修正过的精转句段以当前有效修正文字导出并标明修正来源；原识别文字可供用户显式选择附带核对，不默认把同一句作为两条并列正文。导出当前身份与文字状态，不把旧的自动猜测冒充人工确认。

## 9. 全局存储、保留与清理

### 9.1 默认保留和空间暂停

所有通过第一层保留的人声音频及已有粗转文字默认持续保存；事件、未整理、待处理或失败状态没有各自的自动过期时钟。截图、Mark、评论及派生文字也随其实际内容保存，直到用户清理相应范围。是否值得命名、有没有摘要或精转成功，都不改变基本保存资格。

提供可调整的本地音频占用上限，同时监测设备实际可用空间。接近任一边界时提前、去重提醒；到达边界时**暂停新的音频采集并说明具体原因**，不静默删除旧人声或自动淘汰最早事件。触及音频占用上限本身不应阻止尚有空间的主动截图；截图及非音频数据虽不计入音频上限，仍受设备真实剩余空间安全线限制。默认容量、提醒比例和安全余量按真实体积与设备实测校准，不要求用户现在选择数值。空间释放或上限提高后仍保持录音暂停，由用户手动启动，不自动恢复。

### 9.2 两种统一清理动作

每个清理入口都提供完全相同的两种操作名称：**“清除原始音频”**和**“清除全部数据”**。前者始终是默认选项；后者在任何场景，包括 CLI 调用时，都必须另有说明弹窗和确认。可选择单个命名/未整理大块、指定时间及来源范围，或全部历史；执行前预览会删什么、受影响的其他重叠事件及大致可释放空间。底层按真实素材范围执行，不根据虚拟事件名称猜测物理文件。

- **清除原始音频**：清掉选中范围内的原声及可访问副本；保留粗/精转文字、事件标题与区间、截图、Mark、评论、OCR、搜索，以及已经提取的人物归属与声纹特征。预览须明确声纹特征会保留；源音频消失后相应样例不可回听或重新提取。受影响区间明确标为不可回放，也不能再基于该音频新发起精转。取消尚未提交的相应 ASR 待办并在操作前提示；尚未完成且需原声的说话人分段/声纹提取也无法补做，预览须提示。已提交供应商的请求可能完成，可保存其有效非音频转录结果，但不能重新写回被清掉的音频；若因此缺少可靠说话人分段，仍显示处理不完整。
- **清除全部数据**：清掉选中真实范围内的音频、转录、事件关联、截图、Mark、评论、OCR、搜索项、该范围贡献的人物归属/声纹样例及其特征，以及相应待办/派生结果。只清理一个区间时，不连带删除同一人物在其他区间仍有效的样例和人物身份；若某人物仅由选中范围建立且无其他有效关联，连同该人物记录一起删除。清理全部历史时，人物库也一并清空。先让相关内容在所有读取入口立即失效，再完成物理清理；迟到的云结果不能使其重新出现。部分重叠的其他事件只移除实际受影响部分，不误删仍有效的范围。额外弹窗应说明不可恢复范围，以及外部导出、服务商已经收到的副本不在本地清理能力内。

“清除全部数据”是所选历史内容及其派生身份数据的清理动作，不是重置应用。即使范围选为全部历史，供应商凭据、来源开关、登录启动和用户暂停意图等设置也不随时间范围清理；若未来需要恢复出厂设置，应另设明确操作，不能混用当前名称。

两种操作都要正确处理一个真实音频区间被多个虚拟事件引用、双路同一时刻各有素材、物理文件跨越选中范围的情况。清理一处共享音频会影响所有引用它的回放，需预先展示；同一时刻未选中的另一来源不能被连带清掉。清理完成后搜索、回放、导出、CLI 与旧引用保持一致；崩溃后可以继续物理清理，但逻辑上不得重新开放已清内容。

截图、Mark 和评论属于时刻动作，不属于麦克风或系统声音中的某一路。按时间或事件执行“清除全部数据”时，以它们的真实锚点和预览中列出的关联范围判定；仅按某一路声音清理时，不能悄悄扩展到另一声源或未明示的时刻动作。预览必须让用户在确认前看到这类跨来源影响。

## 10. 运行状态、异常与恢复

- 首次安装不擅自采集；用户完成设置、权限和启用后，登录自动启动。关闭历史/设置窗口不停止记录；完全退出应用停止当次采集，但不自行把上次启用意图改成永久暂停，下次登录仍按该意图工作。手动暂停或关闭某路来源是明确意图，跨登录、唤醒及接电保持，不被“检测到声音”自动覆盖。
- 锁屏但未睡眠时继续；睡眠和关机形成真实缺口。唤醒后按用户意图恢复；不把睡眠当成一场会议结束的语义证据。系统时间变化、设备切换、断流须保留真实来源和顺序。
- 静音待机是已开启采集下的自动降耗，不是用户关闭；权限撤销、设备不存在、存储不足、模型不可用、供应商凭据失效和网络/供应商故障均应分别说明影响、保留下来的数据与恢复操作。已完成首次启用后，云端凭据失效不停止本地录音和粗转，相关云任务等待重新配置；两路声音来源彼此独立，一路异常时另一条已启用且可用的来源继续，两路都关闭或不可用时不能仍显示为“正在录音”。
- 采集、媒体落盘、粗转、截图保存和云端处理的成功状态分别确认。粗转失败时若音频已保存仍可回放；音频保存失败时不能只凭文字显示“完整录下”。异常退出后恢复或明确标注尚未持久化的尾部缺口，不凭想象补齐。
- 用户因为磁盘容量被暂停后须手动恢复；用户主动暂停也须手动恢复。普通云端暂时故障在服务恢复后可自动处理积压，用户主动暂停的队列仍等用户点击继续。
- 手动暂停录音只停止新的声音采集，不自动暂停 LLM/ASR 两条云端队列，也不阻止用户主动截图、Mark 或评论；如果实际磁盘已不足以保存截图，则按截图保存失败单独提示。用户若希望停止云端调用，须分别暂停对应队列。

## 11. 完整 macOS CLI

CLI 是 0.1 产品闭环的一部分，而非只读附属入口。用户应能从终端完成本版核心工作流：配置与就绪检查、明确启动/暂停/恢复记录及切换两路来源、主动截图/Mark/评论、查看记录状态与时间线、列出/读取命名和未整理大块、关键词与日期/人物搜索、按时间/来源范围手动建命名事件、修改事件起止时间和标题、拆分/合并/取消事件标注、对已有事件重新精转、逐句修正精转文字及撤销修正、查看全局人物库并创建/改名/删除人物、为本场说话人选择已有的人或建立新人、修正身份归属与管理声纹样例、分别控制两条云队列与手动精转、选定范围导出，以及两种清理。读取或导出精转结果时保留本场说话人分段、当前修正文字、已归属的全局人物及各自来源。CLI 不承诺本版尚不存在的摘要、语义搜索或 Windows 能力。

CLI 与图形界面调用同一个本机核心，不直接改数据库，也不绕过来源、权限、删除、人工修订、任务版本和供应商配置规则。应提供稳定的 ID、时间/来源范围、处理状态、结构化输出与明确错误，便于外部程序使用。常规配置、查询、记录和修订不要求用户先手动打开应用窗口；读取命令即使唤起本机核心，也**不能隐式开始录音**，只有显式开始记录才改变采集意图。系统录音/截图权限仍需遵守 macOS 的许可流程。

从 CLI 执行“清除全部数据”同样弹出额外说明并确认；无可用图形会话时清楚拒绝执行，不提供绕过开关。CLI 导出不能返回已清内容。手动范围精转命令返回范围 ID，以及每个实际 ASR 任务的任务 ID、来源、时间范围和当前状态；同一范围可能拆成多条任务，重复请求仍能找回已有任务及其最新状态，没有可用原声时明确报错。入队不冒充完成，返回的任务 ID 可直接用于队列查询和失败重试。CLI 不意味着默认开放局域网、HTTP 或 MCP 服务。

## 12. 必赢场景与验收

| 场景 | 0.1 应满足的结果 |
|---|---|
| 全天办公且没有逐场操作 | 登录后按上次启用意图持续记录；会议和临时讨论可找回，静音时资源退让，不要求用户判断何时开始 |
| 两小时会议包含多次安静间隙 | 一场会议显示为从开始到结束的一个大块；内部音频可以有已清理的无人声间隙，文字仍按真实时刻排列 |
| 12:00–18:00 只有零散人声，15:00–16:00 是会议 | 会议成为命名事件，其前后留存的零散人声仍在大块未整理时段可查、可回放、可手动精转；选中一段局部精转后形成独立未命名事件，前后仍为粗转块，日期列表可选择隐藏粗转块且默认显示 |
| 用户发现一场漏判的会议 | 在未整理时间段圈定开始和结束、选定来源并命名后形成一个虚拟事件；保留的整场有声素材直接排入精转队列，ASR 暂停时显示待处理 |
| 两路声音重叠且内容无关 | 同时刻分别保留来源并可并列标注，不虚构先后；一条来源的清理不自动删除另一来源 |
| 安静时主动截图或评论 | 时刻动作仍在主时间线可见，未命名也不丢失；按日期查看不拆开跨午夜的同一活动 |
| 远场人声、粗转空白或错误 | 保守留下音频，标明识别不清；明显连续的会话仍有机会成为事件并精转 |
| 悬浮组件截图、Mark 与稍后评论 | 单击主按钮标记重点；悬停菜单可主动截取当前操作屏幕、评论或暂停；Mark 不自动截图；评论回到原锚点，事件边界修订后仍跟随真实时刻 |
| 云端 LLM 或 ASR 分别暂停 | 本地继续录音和粗转；未暂停的队列按依赖处理已有任务；继续后自动补积压且状态可见 |
| 手动改边界、清理与迟到任务并发 | 当前事件文字稿及待精转范围随新起止时间更新；新纳入的有声素材补精转，移出的文字不留在事件中；人工修订不被旧结果覆盖，已清理内容不经搜索、回放、导出、CLI 或迟到结果复活 |
| 错误事件标注 | 用户可取消命名事件的标注，原声音、文字和时刻动作回到原时间位置的未整理区域 |
| 首次精转遇到陌生说话人 | 先尝试匹配全局人物库；没有可信匹配时保留本场 speaker 编号；用户可选已有的人或输入名字创建新人，合格声音形成可复用声纹样例 |
| 已建档人物出现在另一场会议 | 精转后自动比对全局库，可靠匹配时显示人物姓名及自动匹配来源；无法可靠匹配时仍用本场编号，用户可纠错；人工确认不被自动结果覆盖 |
| 精转错了人名或数字 | 用户逐句修正后显示、搜索和导出使用修正文字，原识别结果仍可核对；重新精转不静默覆盖人工修正，无法可靠映射时标待核对 |
| 人物样例所在事件被清理 | 只清原声时预览并保留已提取特征；清除全部数据时删除该区间贡献的样例、特征和归属，其他仍有效的人物证据不受影响 |
| 达到存储边界 | 提前提醒、达到后暂停且不删旧人声；腾出空间后仍由用户手动重启 |
| 终端完成同一工作流 | CLI 可控制记录、查询、修订、精转、导出与清理，并遵守图形界面的权限和额外确认规则 |

验收必须同时看**召回、时间/来源正确性、事件边界质量和资源消耗**，不能靠漏录或删掉疑似人声获得漂亮的低功耗数据。需用实际 macOS 设备、耳机会议、远场与中英混说、短句、两路重叠、多人轮流及重叠讲话、同一人物跨耳机/麦克风与系统声道、长时间静音、睡眠唤醒、磁盘压力和长时运行样本验证。重点测量人声误删、粗转延迟、事件错合并/漏合并、云精转定位与说话人分段质量、全局人物误认/漏认、人工文字与身份纠错后的稳定性、搜索找回率、CPU/内存/电池和磁盘增长。具体量化阈值在原型中校准并冻结；当前没有 hear 的实测成绩。

开发验收的顺序是先用几分钟至十几分钟的真实音频把**全部功能和用户交互闭环**跑通、修正问题，再进行几小时与接近全天的稳定性、资源和恢复验证。短样本可配合可控时间戳与故障注入覆盖长间隙、跨午夜和迟到任务语义，但不能用模拟样本代替最终长跑。图形界面除代码检查外，须由 Codex computer use 操作真实应用窗口完成端到端流程，从用户视角审查可发现性、视觉层级、操作成本、状态反馈与异常体验；发现问题迭代后复测。

## 13. 工程设计边界与后续工作

一个本机核心统一拥有采集、持久数据、云任务、权限和清理；界面与 CLI 走同一套能力。底层音频、转录、截图、事件和清理状态应按真实时间、来源、稳定引用与版本建立关系。物理音频文件、ASR 句段、候选切分和虚拟事件是不同层级，不能把任一技术分块直接当成用户层事件。全局人物库也须与事件和本场说话人编号分层，以可追溯的样例和身份归属连接；模型或人工修订时只更新派生身份，不改写原声与精转内容。声音保留判定、候选切分、LLM 拟合、声纹匹配和后续主题处理各自可以独立调试与替换；其中“15 分钟空档”只是策略初值。

MyAgents 的现有录音代码是复用基础，不等于它的一次 Record、8 小时实时转录上限、存储方式或应用生命周期可直接搬成 hear 全天记录。技术 RFC 已移除旧的滚动回溯、Mark 保留、云端预算、默认关闭与 CLI 只读假设；仍需通过原型确定 macOS 最低版本、资源及质量门槛、供应商实际接口与恢复协议。这些是开发与交付中的验证门槛，不阻止已获用户授权的工程开工；未列出的数值参数不是待用户逐项拍板的产品问题。
