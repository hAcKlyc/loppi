# hear 产品需求

## 执行须知

先读本文件、[技术 RFC](tech_rfc_0.1.md)和[自审记录](REVIEW.md)。本仓库只有设计文档，不能把候选技术、默认参数或验收预算当成已实现能力。PRD 定义用户行为，RFC 定义建议实现与技术验证；冲突须明确修订，不能由执行者择一解释。

本方案围绕一个完整结果收口：用户持续开启后，能找回工作讨论及其声音、画面和自己的评论。开发可以拆内部工作批次，但这里不承诺半成品发布顺序。第10节会改变产品行为的决策尚待确认；其余技术指标进入原型与发布验证，不以公开模型跑分替代。

## 1. 定位与用户意图

**hear 是一个独立的持续情境记录器：将连续采集的声音整理为会话或事件，并关联当时的截图、重点和评论，供用户找回、核对及交给 AI 使用。**

主要价值是工作记忆。用户已明确选择“自动留下会议、通话和临时讨论，事后能找回细节”，并强调最终应形成“一组一组的有意义的音频、音频精转录、这个阶段的其他 action、截图等等”。

产品应让用户正常工作时不必照看，遇到重要内容时随手补充，需要时能够返回原话和现场。安装或运行 MyAgents 不是使用 hear 的前提；MyAgents 可作为外部使用方。

“24小时”表示可持续开启的模式。用户已接受电脑清醒时采集、实际睡眠时暂停、唤醒按原意图恢复；不承诺关机、睡眠或完全退出程序后继续录音，也不把24小时保存窗口与24小时采集模式混为一谈。

## 2. 范围与已确认原则

### 2.1 已明确的核心需求

- 持续采集选定声音，采用本地低成本识别作为筛选和组织参考。
- 将零散声音切分、归组为相对完整的会话或事件；短讨论同样需要覆盖。
- 随时一键截屏，与当时声音关联；一键 Mark；可补充文字评论。
- 有限本地原声兜底，允许回听、重新识别和手动保留，避免价值误判导致立即永久删除。
- 对有需要的片段按授权和预算精转；控制电脑资源与电池消耗。
- 独立产品自身提供记录、整理、找回和回放；预留外部调用边界，CLI 为推荐入口。
- macOS、Windows 是当前评估目标；最低系统版本、处理器架构与首个正式支持矩阵尚未锁定。

### 2.2 当前方案的范围建议

候选范围包括麦克风与系统声音独立选择、原声回放、本地全文搜索、来源可追溯的转写、用户修正会话边界、内容导出、删除与异常恢复状态。平台或模型能力缺失时说明实际可用范围。

当前不把持续录像、定时全屏截图、键盘输入监控、浏览历史、日历账号、跨记录声纹身份、手机/可穿戴采集、多人协作或自动执行谈话指令纳入设计。用户提出的“其他 action”在本轮指主动截图、Mark、评论等记录动作，不推导为监视所有电脑操作。

MCP、通用HTTP服务、内置通用聊天和自然语言记忆问答均不是默认附带范围。若要加入，应说明具体用户价值、数据权限和交付责任，不能靠接口名称扩大需求。

## 3. 用户路径与必赢场景

### 3.1 首次开启

介绍“会留下什么、如何找回、如何停止”。分别选择麦克风和电脑声音，说明来源、权限、睡眠边界、保存/清理规则和默认本地处理。录音权限、模型准备和云端授权分开。

本地模型未就绪时，可明确选择先只保存声音；界面不能宣称文字索引已可用。可提供可跳过的真实短试录；不使用预置文字冒充识别成功。

### 3.2 日常使用

后台状态可随时查看和暂停；不持续弹出每次检测或转写进度，不抢占用户正在工作的窗口。正常会议不需要逐次点击开始/结束，也不需要逐条批准分类才获得结果。

用户可主动标记重要时刻或截图。成功反馈以实际保存状态为准；失败保留可恢复输入并明确提示，不误报“已保存”。“标记已建立”与“相关音频已保存”分别反馈；尚未采集的后文、未持久化的尾部和未完成的截图不能包含在完成承诺中。

### 3.3 找回与使用

主列表按会话/事件显示时间、可识别标题、原文片段和必要状态。一天是浏览分组，不是一条全天巨型录音；物理音频块不成为列表条目。

用户按日期、关键词、评论或截图文字找回内容；命中后直接定位相关句段/画面并回听。没有找到时区分未采集、未处理、已清理和没有命中。未成功归类的内容仍可在实际原声窗口内按时间查找。

选择有关内容后，可导出或交给外部 AI。选定范围和来源应可见，不自动附上全天历史；对方已收到的副本不保证随本地删除撤回。

### 3.4 必赢场景

用户戴耳机参加客户会议，看到报价表时截屏，随后标记一段发言并评论“部署范围待确认”。当天还发生一段未主动操作的临时讨论。次日，用户能找到预算会话中的原话、截图和自己的评论，并能找回仍在回溯窗口内的临时讨论；合盖午休没有被阻止，未开启云端时相关内容没有上传。

## 4. 最终内容与数据语义

面向用户的最终对象称为**情境记录**，技术上对应 Event。它围绕一段会话或事件组织相关声音、转写、截图、重点和评论。

| 概念 | 职责 | 关键约束 |
|---|---|---|
| Evidence：证据 | 原音频、截图、用户文字及精确引用范围 | 可先独立保存，不等待事件识别；注明来源和可用性 |
| Moment：时刻 | 用户截图、Mark或当下评论形成的时间锚点 | 评论晚提交不改变锚点；没有音频也可以存在 |
| Event：情境记录 | 会话的组织关系、标题与范围 | 可合并/拆分/修订，不改变原始证据时间 |
| Derivation：派生结果 | 转写、OCR、摘要、场景判断 | 知道输入来源、范围和版本；不冒充原始内容 |
| ContextBundle：上下文 | 按用户选择/问题/权限装配的内容视图 | 默认是查询结果或发送快照，不建立第二份永久事实库 |

事件可跨多个音频文件，证据可与多个事件有关联。未知说话人、未知场景均合法；一次提到某个金额，不自动成为用户永久事实。

“归档”在本方案中指形成可管理的情境记录及其保存关系，不表示从列表隐藏，也不天然承诺所有内容永久保留。正式记录的期限与原声回溯窗口分别管理，见第7节和决策D2。

## 5. 即时记录与对齐

| 用户动作 | 推荐行为 |
|---|---|
| 截屏 | 捕获选定来源的一帧，保存图片及实际捕获时间，并形成一个Moment；不要求再点Mark |
| Mark | 立刻建立时间锚点并保护有界的前后音频范围，不默认截屏 |
| 评论 | 附于用户选定/正在操作的Moment；独立输入时才新建当前时刻 |

具体快捷键、默认截屏来源和声音保护窗口是待验证/确认的设计参数，不在首次设置暴露模型阈值。

截图需同时区分操作触发时间和实际捕获时间；提交评论不能重新截取当时已经切换的窗口。Mark绑定时间/声音范围，而不是转写句段序号。模型重转、事件重组后仍能回到原时刻。

Mark通常发生在重要话语之后，保护范围必须包含前文。未来部分尚未采集时显示待补齐；中途暂停或断流产生缺口，不能生成假连续音轨。范围已过期时说明不可恢复。

## 6. 自动整理与精转

1. **保存**：原声音先进入有界滚动存储；截图与评论即时保存。
2. **初步分析**：检测候选语音，进行本地初步转写；“未处理”不等于“无价值”。
3. **筛选与归组**：结合时间连续性、来源、内容与用户标记整理会话。碎片可能有价值，静音也不等于会议已经结束。
4. **情境记录**：显示可用声音、已有文字和关联动作；低置信分类使用通用标题，不编造人物与会议身份。
5. **精细处理**：优先用户查询、Mark、评论关联和识别不清的片段。云端精转前经过独立授权与预算，失败保留本地可用结果。

建议无语音时降低识别与整理的计算负担，保持稳定的原声采集质量，避免检测到人声后再切换设备参数而丢失开头。“切割与重组”首先改变引用范围和呈现，不立刻破坏回溯窗口内的原声；跳过静默播放也不改变真实时间关系。

“应该形成记录”“应不应该精转”“可以不可以上传”是三个判断。系统混音有语音不代表用户在参会；识别不可靠也不代表内容不重要。

推荐云端默认关闭；用户可单次处理或明确开启自动模式并设置范围/预算。音频云转写不涵盖截图上传和外部AI消费。最终厂商、自动触发条件和预算见待决策项；不预定未经对照验证的“最准模型”。

## 7. 保留、清理与删除

### 已确认：短期可补救

未入选主要情境记录的声音，不因价值判断立即永久删除；在有限本地回溯窗口内仍可回听、重新识别或手动保留。推荐初始窗口为最多24小时，同时受容量上限约束；界面显示实际覆盖范围。

### 正式记录单独管理

用户保留一个时刻时，应保护截图、评论及明确的声音范围；不能只留下空壳标题，也不能默认为保留全天。正式记录不因原声滚动窗口到期被一起清空。自动形成的记录如何晋升正式保留、保留多久与总容量默认值尚待D1/D2收敛；旧“自动记录统一7天过期”不作为本产品既定规则。

### 操作语义

- 取消Mark/调整分组：改变组织或关注，不自动擦除共享证据。
- 解除保留：撤销该项保护请求；其他有效保护不受影响。
- 删除内容/时间范围：使相关证据、转写、OCR、摘要、索引和待处理任务失效，并清理受影响副本。用户明确删除不受回溯窗口阻挡。

容量不足先清理允许清理的内容；仍不足则可见地暂停采集，不擅自删除用户保留内容。具体阈值由RFC列为候选参数，不能当成用户已拍板的数值。

## 8. 状态、生命周期与异常

界面分别表达实际采集、内容保存、文字处理、来源缺失；不要用一个“录音失败”覆盖所有异常。声音已保存而转写失败时，仍能回放。

推荐：新安装默认关闭，显式开启后记住意图；关闭查看窗口时已启用的采集继续，完全退出停止；用户手动暂停持久化，不被接电/重启/唤醒覆盖；资源原因暂停可按条件恢复。登录自启动与锁屏行为需要在首次设置说明，推荐默认值见D4，不假定用户已确认。

CLI读取不得隐式启动录音。离线不阻止本地保存与已有索引检索；模型缺失、权限撤销、设备断开、存储不足要分别给出可执行恢复路径。云请求超时可能已执行，应呈现结果不明而不是无限自动重试。

## 9. 完成定义与验证

产品验证必须同时评估资源与信息找回，不能通过漏记获得低功耗数字。

| 验收场景 | 应满足的行为 |
|---|---|
| 耳机会议 | 可核对双方来源，失败时明确缺哪一路 |
| 短讨论未Mark | 能自动形成合适记录，或在实际原声窗口内按时间补救 |
| 截屏+延迟评论 | 图片与对应声音可核对，评论仍属于原时刻 |
| 精转/重新分句 | 不移动Mark，不覆盖用户评论与更正 |
| 用户暂停+重启/接电 | 不擅自恢复采集 |
| 删除与后台任务竞态 | 删除内容不通过搜索、旧引用或迟到结果重新出现 |
| 空间/资源不足 | 有界退让、缺口与积压可见，保留内容不被静默删除 |
| 外部读取 | 无需MyAgents拥有数据库；返回获授权的选定内容与来源 |

质量指标应包含短句召回、会话边界/归组正确性、关键数字与专名、搜索成功率、云端相对提升。阈值需在代表语料上锁定；RFC提供实验方法和候选资源预算。目前没有实测成绩，不可据此宣称发布门槛已通过。

## 10. 待确认产品决策

以下属于产品选择，区别于必须通过实验验证的技术参数。设计者建议并不等于用户已确认。

| ID | 决策 | 当前建议 / 尚缺内容 |
|---|---|---|
| D1 | 自动形成与正式归档的条件 | 自动产生可用会话卡；用户Mark/截图为强保留意图；未标记会话的自动归档准则与误判容忍度需定 |
| D2 | 正式记录期限与空间 | 与原声滚动窗口分离；用户明确保留内容不自动过期；自动归档内容的期限、总预算及清理优先级需定 |
| D3 | 云端自动处理 | 默认关闭，单次与显式开启的自动模式；需确定厂商/地域、授权范围、额度与质量门槛 |
| D4 | 来源、平台与启动默认值 | 目标macOS/Windows；建议麦克风与系统声音分别选，关闭窗口可继续，手动暂停跨重启；最低版本/架构、锁屏与登录启动策略需定 |
| D5 | 即时动作 | 推荐截图形成Moment，Mark不联动截图；需定默认截屏来源和前后保护窗口 |
| D6 | 外部接入的交付范围 | CLI为薄入口，优先读取/搜索/导出；是否包含控制、精转请求、MCP或其他接口需明确后冻结 |

## 11. 技术架构摘要

一个本机原生核心统一拥有采集、持久数据、任务队列、权限、保留和删除。界面与CLI调用同一产品能力；计算worker无持久状态写权限。原声音/图片使用媒体文件，元数据与事务由本机存储负责，搜索索引可重建。

持续采集与重计算分离。原生采集不等待ASR/OCR；重任务有界排队并按电源/负载让步。具体进程、数据模型、恢复、时间映射和候选参数见[RFC](tech_rfc_0.1.md)。本产品不依赖MyAgents的Session、Sidecar、工作区或内部RecordStore。
