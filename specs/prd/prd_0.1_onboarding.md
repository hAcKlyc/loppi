# 单页首次设置

## 执行须知（给空 session 的你）

先读 [ARCHITECTURE](../ARCHITECTURE.md) 的所有权、采集生命周期、模型与凭据边界，[DESIGN](../DESIGN.md) 的设置、加载与反馈规则，[原产品 PRD](prd_0.1.md) 第 3 节，以及[现状研究](../research/2026-10-20-first-run-onboarding.md)。参考 [tech_docs](../tech_docs/README.md) 定位既有处理链，不以历史文档代替当前代码。

本 PRD 是一个原子交付单元。页面、状态恢复、模型准备反馈、权限恢复、云配置、升级兼容、验证和文档必须一起完成；开发批次只组织实现、验证、review、commit，全部验收后统一上线。不得只交一个外观页面而继续要求用户到设置里拼接必需步骤。

现状核实基于 2026-10-20 工作树，HEAD 为 `290dc75`，应用版本 `0.1.0`，IPC `PROTOCOL_VERSION=17`。开发开始时须重新核对并保留其他任务改动，特别是独立的[定时录制 PRD](prd_0.1_recording-schedule.md)。本文使用真实文件和符号名而非易漂移行号。

首次签名安装、系统授权身份、关闭/重开不擅自录音、模型资源恢复、双云凭据验证、现有用户升级为发布硬门槛。编译成功、模拟画面或开发机已有授权不能代替这些证据。用户于 2026-10-20 确认：「确认，按这份 PRD 开始开发。」

## 1. 背景、决策与必赢场景

用户希望梳理「客户端软件首次安装后的初始化过程」，随后连续要求「简洁干净」。讨论中明确了两次取舍：

> 「那就保留这两个云服务的配置门槛，先不做统一云服务。」

> 「试一下这个页面都不用吧…」

最终确认：

> 「就按这个单页方案，写成 PRD。」

因此，交付的是一页实用的准备界面。用户下载组件、允许需要的声音来源、填入两个 Key 后直接进入正常首页。不能通过取消云配置门槛来缩短流程，也不能把删除的试录页换成弹窗、倒计时或隐藏必经任务。

**必赢场景：**全新安装后，用户在「准备 Hear」一页完成本地语音组件、所选声音来源和两项云配置；中断可继续，错误原地修复；点击「完成设置」进入首页且仍未录音；用户点击现有开始入口后，真实记录、转录、整理和回放按原产品路径运行。

初始化完成与首次记录成功分别验证：前者不要求用户说话或播放音频；后者在研发端到端验收和用户正常使用中观察，不能用配置成功冒充已实际录到声音。

## 2. 一次交付范围与反向边界

### 2.1 交付内容

- 一个首次准备页面，包含本地组件、声音来源、云服务三组和完成/稍后设置操作。
- 新用户进入、稍后设置、再次打开、完成后进入首页，以及已使用用户升级的路由规则。
- 复用既有模型安装，补足真实阶段、失败类别、空间检查、安装后加载检查和重新准备反馈。
- 所选来源逐项授权、拒绝后恢复、返回应用复查；必要的短时授权探测不保存或上传声音。
- 两个云服务同时可见、分别验证保存、获取 Key 的简短帮助与错误恢复。
- 设置与首次准备共用状态及操作能力；后续失效只修复相关项目。
- 本文规定的迁移、回归、签名安装验收及相关文档更新。

平台沿用现有 macOS 客户端与发行架构，不新增平台，不改变最低系统版本；实际发行支持范围必须由签名验收支撑。

### 2.2 明确不做

不做独立欢迎页、试录页、成功页、导览问卷、示例记录、人物录音教学或第一条记录专用链路。不做统一云服务、账号计费、自选供应商/模型、长期纯本地模式或新的云外发策略。

不新增模型市场、CDN/镜像切换、离线包渠道、字节级断点续传、下载调度服务或独立后台进程。复用已完成的安装资源，但未完成文件可以重新下载，不能把重新下载称为断点续传。

登录启动、记录计划、兔子位置、空间上限继续在现有设置中管理；本页不增加第四组偏好、不代用户注册登录项、不改变已保存选择。首次截图仍按实际操作请求权限，不把截图授权变成额外录音门槛；不扩张成截图或人物教学项目。

不改时间线默认筛选、事件拟合阈值、音频保留、人物识别或云任务算法。不承诺所有网络下固定下载时间，也不将权限/凭据曾经成功解释为未来永久可用。

## 3. 页面与交互契约

### 3.1 唯一页面

标题 **「准备 Hear」**。

采用用户于 2026-10-20 确认的极简草图：去掉副标题、白色大卡片和常驻解释段落。浅灰绿画布上用细分隔线组织三行，左侧动作引导，右侧操作；沿用现有绿色按钮与设计变量。编号不是顺序门禁，三项可以同时准备。没有侧栏或额外欢迎动画。保留原生窗口控制与拖动区；最小窗口 `760 × 540` 时正常状态尽量一屏显示，展开帮助及错误可纵向滚动，页脚在文档流中。

| 分组 | 常显内容 | 操作 |
| --- | --- | --- |
| ① 下载本地模型 | 一个安装按钮，原位显示真实阶段/进度/就绪 | 失败后原位重试；人物识别非阻塞状态与详情可展开 |
| ② 授权声音访问 | 「授权麦克风」「授权电脑声音」两个按钮，完成后显示简短状态 | 来源选择收进可访问的调整入口；异常时提供系统设置/重新检查 |
| ③ 配置云服务 | DeepSeek · 整理、火山引擎 · 转录，两个独立 Key 输入框 | 获取密钥帮助折叠；验证中/成功在输入附近简短显示，错误原位展开 |

两个供应商同时展示，不使用切换标签隐藏另一项。模型名、路径、内部任务 ID 不占主视觉；技术诊断放可展开详情。已完成项目缩成简短确认状态，错误在对应项目下显示。模型下载与填 Key 可并行，一个分组忙碌不禁用无关分组；同一资源的重复动作需抑制。

首次读取显示加载状态，不先画成未配置。读取失败显示重试，不伪装为权限拒绝、模型缺失或未填 Key。后台刷新保留已确认内容，并按请求代次拒绝迟到响应。

键盘可以完成所有操作，状态有文字而非仅靠颜色；输入和按钮有可访问名称及可见焦点，减少动态效果沿用现有规范。

### 3.2 本地组件

用户首次点击「下载并安装」才开始网络下载。应用自动选择当前固定资源，不让用户选择模型、参数或目录。准备动作由 Core 持有，离开页面或关闭主窗不另开一份任务。

必要组件为现有 `speech-v1` 的 SenseVoice 和 Silero VAD。CampPlus 按当前 `PrepareModels` 路径一起准备，保持独立状态，不额外升级为首次录音硬门槛；仅声纹失败时显示「语音识别已就绪；人物识别组件待重试」，允许继续。

页面至少区分：读取/检查、未安装、下载、校验安装、加载检查、就绪、失败。下载显示真实进度；没有可量化进度的阶段显示阶段名，不模拟百分比或预计时间。

完成判断包含固定哈希与必要模型加载检查，加载检查使用本机合成输入，不访问声音设备、不创建录制 session、不写音频/转录、不请求云端。由既有 worker 与资源预算执行，顺序验证必要模型，完成/错误/超时后释放资源；资源压力导致的等待与模型错误区分。只在准备/重试及资源或运行组件身份改变后做检查，不在每次 UI 刷新重建模型。

安装前以已锁定资源的实际下载、解压与暂存空间计算预算，并保留既有录音磁盘安全余量。确切大小需在实现验证中记录；不能使用代码下载上限充当实际大小。空间不足先解释所需空间并停止安装；清理后允许重试。

下载源、资源版本与固定哈希沿用 `model_pack`。失败区分网络、磁盘、校验和加载；重试复用已通过校验的完整组件，仅重做未完成或损坏组件。完全退出或 Core 重启后，重新核实文件；未完成组件显示需要重新准备，不保留虚假的下载中/就绪。重试前清理本任务遗留暂存，不修改其他有效资源。不新增自动无限重试或后台周期自检。

### 3.3 声音来源

新用户延续现有双来源默认选择；可以取消任一路，但不能以零来源完成设置。两个来源均保留时均需完成必要授权；某一路受限或不可用时可主动取消，用另一条完成。

来源选择只保存来源偏好，不改变持续开启/暂停意图。使用既有 `SetSource` 的修订检查，冲突后读取新状态再操作，不能静默覆盖其他客户端选择。

点击对应授权按钮才请求系统权限，一次只发起一个系统弹窗。说明准确对应当前 macOS 和采集路径；旧系统声路径需要屏幕相关许可时说明用于采集电脑声音，不保存屏幕画面。主动截图许可不另列为必填项。

状态区分：未请求、等待用户处理、已允许、已拒绝/受限制、已知设备不可用、读取失败。拒绝后提供打开系统设置及明确路径；系统跳转失败时显示手动路径。用户返回应用自动复查，必要时点击「重新检查」，不循环索权。

对已授权且当前可观察条件满足的来源，表示「已允许/已准备」，不能声称「已验证录音」。不要求用户说话或播放人声，不以音量为零判断设备坏了。只有现有授权机制必需的短探测可以临时打开声音来源，必须由用户的授权/重新检查动作触发；遵循既有截止时间、父进程寿命与回收规则，结果仅为状态，不保留或上传原声。普通页面刷新和完成操作不隐式启动采集探测。

Tap 的 `tap-ready-v1` 仅是历史授权探测证据，不能替代当前可获得的系统授权检查；若平台无法无采集地确定最新权限，状态保留其证据局限，正式开始时由现有采集监督确认。已知撤权/设备不可用不得显示就绪。

### 3.4 两项云服务

首次开始所需两项保持不变：DeepSeek `deepseek-flash` 与火山引擎 `volc.seedasr.auc`。不开放模型 ID、API URL 或旧版多字段凭据表单。

沿用 `CloudKeyInput`：回车或离开输入框后验证并保存，没有另一个保存按钮；同 provider 在途时防重，另一 provider 可独立填写。失败保留当次输入及之前有效配置。空输入/未编辑遮罩不删除或覆盖旧凭据。

只有供应商验证成功且 Keychain 保存确认后才显示「已配置」。已保存 Key 不读回 UI，页面重开后仅显示固定遮罩。未成功保存的明文草稿只存在当前页面内存，退出/重开需重填；不能为了“保留进度”落到 GUI 配置、日志或诊断。

「获取 Key」展开简短说明并链接官方文档/控制台：开通对应服务、创建正确凭据、粘贴到这里。火山帮助必须指向录音文件识别标准版的 API Key，不让用户混入通用云账号 AK/SK。帮助不另开必经页面，也不自动替用户开通或付费。

每项支持验证中、已配置、明确失败、结果待确认。Keychain 保存失败不能显示成功；网络或 IPC 超时不自动再发起付费验证，先查询已提交操作的结果，必要时由用户重试。复用现有请求身份和幂等回执，不另造验证任务队列。错误至少区分凭据无效、服务无权限、网络/超时、供应商暂不可用及 Keychain 失败；拿不到明确余额事实时不能猜测“余额不足”。

云服务下面只常显折叠入口「云端处理 · 按量付费」。展开后说明 DeepSeek 接收文字、时间/来源及主动保存的新截图原图，火山接收待精转音频；声纹与人物库不因此外发，密钥保存在本机钥匙串，验证和使用可能产生服务商费用。云验证使用当前既有测试请求，不采集用户声音做测试。不修改正常任务、暂停和历史内容的既有处理规则。

### 3.5 完成与稍后设置

主按钮 **「完成设置」**；次操作 **「稍后」**（下文的“稍后设置”指同一行为）。

完成条件：

1. 必要本地语音组件校验和加载检查成功；
2. 两项云配置成功验证并保存，无未确认的当前保存操作；
3. 至少一个来源已选择，所有保留的来源完成必要授权，且无已知设备不可用；
4. Core 与状态读取正常，空间满足现有记录准入条件，没有未确认的相关修改。

未满足时禁用完成；具体剩余项通过各行操作状态呈现，并在完成按钮的键盘焦点/悬停提示与无障碍描述中可读，不常驻整段说明。磁盘不足等没有对应行的异常仍需直接显示。点击时刷新当前条件，失败留在原页面；成功保存 GUI 完成状态后进入首页。配置状态是最近成功验证的事实，不要求每次完成/重启重复发送供应商测试调用。权限和网络随时可能变化，不对跨进程状态作永久或原子可用性承诺。

「完成设置」不发送 `Start/Resume`，不注册登录项，不开启记录计划，不清除用户暂停。新用户进入首页仍为未开始，由现有开始入口主动开启。

若设置期间另一个已具备真实准备条件的客户端明确开始或暂停，完成操作不得覆盖该意图；进入首页按最新 `EntrySnapshot` 展示实际状态，不强制写成未开始。上述“仍未录音”指没有其他明确开始操作的新用户正常路径。

「稍后设置」进入首页，可浏览，显示轻量「继续设置」入口；当次不反复弹回准备页，下次冷启动仍进入未完成准备页。新用户通过首页/兔子发起开始且尚未满足首次模型/双云条件时，指向准备页，不另造录音路径。已具备真实条件的 CLI 仍可按现有协议主动开始，GUI 完成标记不是 CLI 许可。

关闭主窗口延续隐藏行为；重新显示同一进程时保持当次页面。下载等 Core 已接收动作可继续；完全退出后不承诺任务仍运行，但下次可根据真实安装与配置继续。已验证配置和来源选择不因退出清零。

### 3.6 首页、老用户与后续故障

首次完成后直接显示正常时间线，不显示庆祝页、假数据、倒计时或要求试录。首页可保留一句轻量说明「点击兔子开始或暂停记录，关闭窗口后仍可继续记录」，不增加持久教学浮层。

第一次实际记录仍由 Core 决定开始/录制/失败，由 `EntrySnapshot` 驱动首页与兔子。没有收到真实声音不能提前显示正在记录；尚无云端结果不能伪造摘要。正常筛选、播放与云队列行为保留。

已使用用户升级直接进入原首页；权限、模型或凭据失效在现有设置/队列修复，不重走 onboarding，也不自动清除完成标记。首次已完成后的断网、供应商故障、队列暂停不停止可用的本地采集和粗转。

## 4. 技术架构、持久化与复杂度边界

### 4.1 当前事实与复用路径

| 当前事实 | 可定位入口 | 本次约束 |
| --- | --- | --- |
| App 初始进入 timeline；refreshContext 汇集云、模型和权限 | `src/App.tsx`：`App`、`refreshContext` | 增加首次页面路由，复用单飞刷新/前台刷新，不再建一组周期轮询 |
| 设置已有对应操作，但分散呈现 | `src/WorkspaceViews.tsx`：`SettingsView`；`CloudKeyInput` | 抽出共用能力操作与反馈，不复制两套保存、授权和错误语义 |
| Core 持有 ModelState，PrepareModels 顺序准备语音/声纹 | `main.rs`：`Request::PrepareModels`；`model_pack::{install,install_speaker,ready}` | 安装及加载检查仍归 Core，UI 不自行下载或写模型目录 |
| 当前 Ready 主要来自文件哈希；worker 有加载/请求路径 | `analysis::AnalysisClient`；`hear-worker` 的 `serve_vad`、`serve_recognizer` | 加载检查复用 worker、协议和资源预算，不把推理运行库放进 GUI |
| 麦克风、系统声由前台 Tauri 命令请求权限 | `lib.rs`：`privacy_status`、`request_microphone_permission`、`request_system_audio_permission` | 系统授权归 macOS，探测与窗口存活归现有宿主/helper，不由 GUI 布尔值代替 |
| 首次 Start 有模型和双云门槛 | `main.rs`：`Request::Start`、`Store::handle`；`events::configured` | 保留实际业务门槛，不以页面完成标志替代 |
| 凭据验证、Keychain 保存与旧凭据替换由 Core 完成 | `Request::ConfigureCloud`；`cloud::{verify_llm,verify_asr,save_credential}` | UI 不直接访问供应商或持久化明文 Key |
| 录音入口共用状态和请求身份 | `EntryRuntime`、`EntryRequests`、`useCaptureControl` | 首页和兔子继续同一控制链，不为 onboarding 新增录音 owner |

### 4.2 状态与权威来源

业务事实仍由现有 owner 管理：Core 管理模型安装、来源选择、云配置引用、空间与录制意图；Keychain 管理密钥；macOS 管理系统授权；GUI 宿主管理页面呈现偏好。

允许新增一个 **GUI 首次设置元数据**，由 Tauri 宿主保存为同一 GUI 配置目录中的版本化文件，测试遵循 `HEAR_DATA_DIR/gui` 隔离。字段仅需 schema version 与已完成状态；缺省为未完成。采用与既有 GUI 偏好一致的受限权限和原子替换，不使用 WebView localStorage 保存权威偏好。

该标记仅决定展示哪个页面，不赋予采集、外发或模型就绪权限。每组真实进度通过已有持久配置和运行状态重建，不保存第二份权限、Key、下载百分比、云可用性或业务阶段状态机。「稍后设置」仅为当次 GUI 会话路由，不另增持久跳过策略。

旧用户识别只在新元数据缺失时执行：若 Core `enabled_intent=true`（已有明确开始历史）或两个供应商均有已保存配置，则视为已有用户，写入已完成标记并进入原页面；否则进入准备页。单个 Key 或模型已安装仍可作为未完成准备复用。判断读取失败时显示连接/读取错误，不当作新安装，不覆盖偏好。不得以当天无记录、历史为空或媒体文件数判断首次安装。

元数据损坏显示可恢复读取错误；重新建立时使用同一规则，不修改业务数据。保存完成标记失败留在准备页并允许重试。保存回执不明时先读取标记确认，不重新配置模型/云或重新触发权限。以后能力失效不重置标记；删除历史也不重置。重装保留用户数据/GUI 偏好时遵循同一规则，偏好不存在而 Core 有既有配置时不强制新手流程。

### 4.3 允许的结构变化

- GUI 新增准备页及共享状态/操作组件；Tauri 增加受限的 GUI 元数据读写命令和必要的系统设置导航。
- 既有 `ModelState` 可以扩展安装阶段、分类错误和加载检查状态；必要时更新现有 IPC 版本、序列化与成套构建，不能悄悄产生 GUI/CLI 不兼容。
- Core 模型准备内部复用现有 worker 做有界加载检查，使用资源准入，不占 Store 锁执行网络/解压/模型加载。终止后回收子进程；父 Core 消失仍按原 worker 约束退出。
- 必要的只读来源可用性查询可以扩展既有权限桥接；没有观察证据时使用未知/已授权表述，不创建后台循环采集作为“检测”。

除此之外，不新增业务数据库表、云验证队列、远程服务、长期常驻进程、录音 session 类型或新的录制意图。GUI 完成状态不参与采集监督或媒体/云任务裁决。

若实现发现必须增加新的下载分发渠道、业务数据库权威状态、长期服务或改变录音/云策略才能达标，应停止扩张并交还用户决策，不能用“实现细节”自行引入。

### 4.4 可靠性与真实外部兼容

- 模型和云动作确认以 owner 的结果为准，网络/IPC 不明不是成功或明确失败；同一用户动作重用已有请求身份/回执机制。
- 稍后设置与重新挂载不重复发起已在途任务，资源错误只影响对应分组。
- 原始 Key、音频、文字、截图不进入初始化诊断日志；日志只保留阶段、版本、耗时和分类错误。
- 不修改其他未提交工作，不重置旧用户来源、暂停、登录项或记录计划；若相关并行改动进入基线，启动/恢复事件不得把首次准备变成隐式开始。
- 不改变固定模型许可与分发契约。现有下载源若在验收环境不可用，应给可操作网络错误并阻止假完成；若目标发行环境无法满足可达性门槛，交还分发决策，不偷偷替换镜像或哈希。

## 5. 关键设计决策及原因

| 决策 | 为什么 | 排除的方案 |
| --- | --- | --- |
| 一页三组 | 用户明确要求简洁，所有必需项一眼可见 | 欢迎、分步授权、成功等多页向导 |
| 双云仍为首次门槛 | 用户指出跳过后核心能力可能一直不可用，并明确要求保留 | 本地基础模式、隐藏未启用能力 |
| 取消独立试录 | 用户明确认为不需要；正常首页已有使用入口 | 把试录改成弹窗或必经小任务 |
| 完成设置与开始录音分开 | 初始化不等于同意此刻持续采集 | 下载/授权完成后自动录音 |
| 凭据用途优先、帮助折叠 | 降低阅读量，同时保留获取 Key 的必要指引 | 服务资源参数表、统一云平台 |
| 只新增展示元数据 | 页面完成状态不应成为新业务许可或状态 owner | 在 GUI 持久化权限与云就绪副本 |
| 复用现有下载与登录设置 | 保持这次原子交付聚焦于单页初始化 | 下载平台改造、登录默认策略重做 |

## 6. 验收与发布门槛

### 6.1 端到端验收

| ID | 场景 | 必须成立 |
| --- | --- | --- |
| A1 | 新用户首次打开 | 只出现一页三组准备；不自动下载、索权、录音或注册登录项；读取中不误报缺失 |
| A2 | 两个 Key 分别配置 | 两项同时可见，独立验证；任何一项缺失/未确认不能完成；失败不丢另一项或旧配置 |
| A3 | 来源选择 | 双来源默认可见；只选一路只要求该路；零来源不可完成；明确取消坏的一路后可用另一条 |
| A4 | 授权拒绝与系统设置返回 | 提供恢复路径；返回后自动复查；拒绝、受限制、读取失败不混为一类；没有重复弹窗循环 |
| A5 | 模型缺失、断网、磁盘不足、文件损坏 | 显示真实阶段和原因；可重试，完整有效组件复用；半安装/未加载不能就绪 |
| A6 | 声纹单独失败 | 必要语音可用时仍能完成；人物组件错误可见、可重试，不谎称全部组件成功 |
| A7 | 中途稍后、关窗、退出、重开 | 已保存来源/Key/完整模型保留；未保存 Key 不落盘；当次稍后不反复弹回；下次冷启动可继续 |
| A8 | 点击完成 | 新鲜条件核对通过、标记保存确认后进入首页；不触发 Start/Resume，录制意图仍关闭 |
| A9 | 首页真实开始 | 现有入口成功启动所选来源，生成真实音频/本地文字并可回放；云结果按正常规则出现，无试录/示例数据 |
| A10 | 初始化操作回执丢失或超时 | 先查 owner 状态/原回执，不能直接显示成功或自动重复供应商付费验证 |
| A11 | 既有用户升级、暂停用户、清空历史 | 不强制准备页，不重置暂停/来源/登录选择，清理历史不恢复首次状态 |
| A12 | 完成后云端断网或失效 | 进入既有队列/设置恢复，可用本地采集与粗转继续；不强制重走 onboarding |
| A13 | 键盘及最小窗口 | 三组、帮助、错误和页脚均可访问；不溢出或遮挡，焦点与禁用原因明确 |
| A14 | GUI/CLI/兔子入口一致性 | 初次业务门槛不能仅靠按钮禁用；GUI 标记也不能阻止具备真实配置的 CLI 主动使用 |

### 6.2 实现内验证门槛与失败处理

| 验证项 | 成功标准 | 失败处理与责任 |
| --- | --- | --- |
| 全新签名安装与 TCC | 在无旧授权的测试用户/机器上，麦克风及实际支持的系统声路径可授权、拒绝、恢复；身份归属与提示正确 | 开发与验收者使用成套签名安装副本复测；未通过不能以开发机权限替代或标记完成 |
| 下载源、包体和磁盘预算 | 锁定资源可下载，测得准确包体/暂存预算，校验与错误恢复成立 | 实现者记录证据；网络错误可重试，目标发行环境无法使用则阻断发布并回到分发决策 |
| 模型加载检查 | 实际发行架构中必要模型加载成功；故障/超时可回收，无用户采集/云调用/假业务记录 | 实现者验证资源预算、失配库和损坏资源；失败不能报告就绪 |
| 来源检查不变成试录 | 普通刷新/完成不打开持续采集；授权必需探测有界且不留声音文件，静音不误报拒绝 | 实现者检查原生探测生命周期，签名真机复测；无法得到确定证据时诚实呈现已授权/未知 |
| 云帮助与实际验证 | 官方帮助能引导取得当前适配器接受的 Key，两家都通过既有真实验证并存入 Keychain | 实现者核实服务入口与错误；不得通过放宽验证或内置开发密钥解决 |
| 持久偏好与升级 | 缺失/损坏/写失败/回执不明均可恢复，旧用户直接进入正常页面，业务意图未变化 | 实现者用隔离目录与升级样本验收，不能在真实用户数据上做破坏性清理 |

全部功能、相关自动化检查与签名真机路径通过，完成一次“新安装 → 单页准备 → 首页主动开始 → 正常记录结果”的完整验收，且旧用户回归无退化，才可标记交付完成。真实录音是研发验收行为，不是产品新增的用户必经试录步骤。

更新 `ARCHITECTURE.md`、`DESIGN.md` 与原 PRD 第 3 节的初始化入口描述，明确本 PRD 对旧“可试录”方案的收敛；不重写无关算法或其他功能的验收状态。
