## 关键纠偏
- 任务数不等于调用数或账单；现有 attempts / submit_attempts 不足以重建逐次消耗。
- 任务最终失败也可能已有云端消耗；查询原 ASR 任务不能当成重新转录。
- 当前 ASR 资源标识为 volc.seedasr.auc（豆包录音文件识别模型 2.0），不能错套同一文档中旧「大模型录音文件识别标准版」的单价。
- 当前代码的 provider=llm/asr 实际是业务能力分类，不是真实供应商身份；新统计模型需区分 capability 与 vendor。
- 输入 Token 包含缓存命中，不能把输入总量与缓存量相加计费或堆叠成总输入。

## 核心使用场景与预期结果
用户从处理队列切换统计数据，选择 D2 的时间范围，从两张按日趋势图查看用量与估算成本，点击指标隐藏/恢复序列，悬停读取当天数值。显示范围横跨模型切换时，统一按每天各请求的历史身份和历史价格累加。

## 设计建议（待确认）

### 界面与口径
- 两张图纵向排列，沿用 C 色块风格；各自图例按钮切换序列，默认全开，切换时间范围保留显隐状态；允许全关，显示「选择指标查看趋势」。按钮支持键盘与 aria-pressed。
- ASR 次数为已确认云端受理的独立识别请求数；同一远端请求的轮询/恢复不新增次数，新请求重新识别另计。本地失败未发出为 0；已发出但受理不明显示待确认，不擅自计零。次数并不是计费单位。
- ASR 左轴次数（整数）、右轴人民币；LLM 左轴 Token、右轴人民币。Token 系列不堆叠，缓存是输入子集；隐藏成本后隐藏右轴。tooltip 使用同一天对应的各指标值与单位。
- 近 N 天包含今天及前 N-1 个本地自然日，今天标记未结束；按请求发出时间归日，不按音频发生日期归日。UTC 时间戳持久化，聚合查询传入明确 IANA 时区。价格所需时区独立于显示时区。
- 真正无调用的已覆盖日期补 0；统计启用前显示无数据；有调用但用量不全的日期保留已知小计并标记部分数据，不能用全零掩盖缺失。迟到 ASR 用量更新原请求归属日。
- 成本统一说明为「按记录单价估算，未抵扣套餐或赠送额度」。极小非零金额增加小数位或显示 <¥0.01，不截成 ¥0.00。

### 三类数据与现有配置的关系
1. 模型目录 model_catalog：稳定内部 ID、capability(asr/llm)、vendor_id(deepseek/volcengine)、API model/resource ID、显示名称、适配器版本。当前仅登记真实支持的服务，不新增通用插件系统；更换供应商时新增条目。
2. 价格版本 price_versions：model_catalog ID、不可变版本、生效区间、币种、来源/核实时间、计费规则版本及单价项。支持音频时长/次数、非缓存输入/缓存读取/输出 Token；未来真正接入缓存写入计费时增加独立项，不能混入读取。价格分母与量纲明确保存，如每 1,000,000 Token / 每 3,600,000 毫秒。峰谷规则含时区、日历版本、分档规则。禁止覆盖旧单价。
3. 调用消耗 usage_requests：内部调用 ID、可空关联任务 ID、用途（事件整理/精转/连接验证）、实际 vendor+model 标识快照、请求 model 与响应 model、远端请求 ID、匿名连接身份、发出/受理/完成/观测时间；用量、用量来源、完整性、计价状态、价格版本与选中档位、计算版本、估算金额。业务发布成功与否单独记录，不能决定消耗是否存在。
- 关联链：当前能力配置选择模型 → 本次实际外发固定模型身份 → 绑定该次适用价格版本/档位 → 保存用量与成本 → core 聚合每日结果。历史不再读取当前配置；模型别名不能伪装为已知精确后端版本，供应商有返回时才保存真实版本。
- 供应商返回的原始用量仅保存白名单数字和必要标识，不保存请求/响应正文、音频、转录或密钥。
- 金额使用定点整数或精确十进制计算；先按足够精度保存各项，再聚合显示舍入，禁止逐请求先四舍五入到分。多币种不能直接相加；当前用人民币价，未来异币种接入必须定义转换来源/时点并保存汇率快照。
- 用量字段按能力允许为空，NULL 与 0 有不同含义。不要用任意 JSON 替代全部可校验用量字段；供应商差异由现有 cloud 适配器归一化。

### 计费公式
- ASR：计价时长 / 3,600,000 × 元/小时。底层保存实际提交音频时长和供应商报告时长；优先有明确语义的供应商时长，缺失可用实际上传文件的帧数推算并标为本地估算，不用事件跨度或句段首尾猜。舍入按对应版本的规则执行。
- 当前 DeepSeek：[(输入总 Token - 缓存命中 Token) × 非缓存输入单价 + 缓存命中 Token × 缓存读取单价 + 输出 Token × 输出单价] / 1,000,000。缓存命中字段的两种表达不可相加；输出里的 reasoning 如已包含，不再次累加。
- 单价按每次调用适用模型、有效版本与峰谷档计算，再求每日总额，不能对一天总用量乘当前单价。历史价格勘误需显式版本与可追溯重算，正常价格更新不改变历史。

### 采集、恢复与保留
- 由既有 core SQLite owner 写入，现有 IPC 读取聚合，UI 不算价格，不新增网络服务。
- 出站之前持久化请求身份和所用配置/价格，网络调用在锁外；得到用量后先独立入账，再解析和发布业务结果。业务 JSON 或时间范围校验失败仍保留已发生的消耗。
- LLM 每次新外发创建新调用；响应按调用身份幂等更新。ASR 按供应商/连接身份/远端任务 ID 归并同一识别请求，提交传输尝试与结果查询不是新的计费单元；独立新远端任务另记一笔。连接验证纳入相应能力用量并标记用途。
- 记录 planned/sent/accepted/terminal/unknown 等实际观察结果；不是把 outbox 写入就当请求已经发送。崩溃发生在外发与结果持久化之间时，ASR 用原 ID 恢复查询，LLM 无法可靠恢复用量则保留 unknown，不能宣称严格账单级完整性，也不能因统计重试付费请求。
- 用量/价格不齐时金额为空并保留原因，日聚合返回已知小计及缺失数量/覆盖范围。后续补齐是幂等更新，不重复累计。
- 建议消耗元数据与任务状态生命周期解耦，清理录音/事件只解除关联、不级联删除消耗；90 天是显示范围，不是自动销毁历史规则。全应用重置仍清除统计。具体留存边界待确认。
- 从启用采集开始统计；旧任务表不能反推历史精确用量或成本，不伪造回填。

### 后续实现必须验证的场景
- 正常调用、业务解析失败但有 usage、超时未知、ASR 多次轮询、手动新请求、重启恢复均不会漏记已知消耗或重复相加。
- 换模型/换密钥账户/更新单价后，旧请求与未结束 ASR 的身份和价格保持；新请求采用新配置。
- 输入包含缓存、峰谷价格、跨天迟到、历史未覆盖、部分缺失、小额精度和不同日期显示时区。
- 7/30/90 天范围、两图独立隐藏序列、全隐藏、无数据/部分数据和键盘访问。
