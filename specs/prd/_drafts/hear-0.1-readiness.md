# 讨论台账：hear 0.1 开发前决策

需求来源：[PRD](../prd_0.1.md)、[技术 RFC](../tech_rfc_0.1.md)及独立产品开工准备审查。当前保持讨论状态，不改变 PRD 的 draft 状态。

## 讨论方式

用户原话：「信息太多了，你通过提问的方式来找我进行需求澄清和问题澄清吧。我来按照你的问题，一个一个给你做决策。」

用户后续更新：「你别一次就问一个题，只要这些东西是相关的，你可以一次多问几个题。」又进一步要求：仅在确有产品决断时提问；普通技术方案和体验细节先由助手按最佳实践判断。

按主题合并真正需要用户决定的产品问题，给出简短推荐与取舍；实现、参数、故障恢复等先形成设计判断并验证，不把它们包装成用户选择题。不把建议或沉默当作确认。

## 岔路清单

- [x] D0a：长期目标是个人上下文记录；MVP / 第一个大版本以工作电脑、工作场景为主体，核心输入聚焦声音和有限的用户主动截图。
- [x] D0b：首版核心价值是降低用户决定何时记录的成本和注意力开销；持续自动记录语音、轻加工成有效内容，同时控制性能与能耗。
- [x] D0c：“24小时”指工作电脑可用、未睡眠或关机期间自动记录；睡眠或关机的中断符合预期。仍需在交付方案中细化登录、权限与手动暂停的优先级。
- [x] D0d：三类声音作为处理层次；清理无声/无意义噪音，其余人声音频与粗转文字持续保留。信息量足够才特别标注为事件并精转；是否成事件不决定基础素材的存亡。
- [x] D0e：产品的第一视角是一台电脑背后的使用者连续经过的时间；回忆和浏览沿同一条线顺序前进，一个大块接一个大块。音频块、ASR句段和截图只是附着在这条时间线上的证据，不是用来反复挑选、重新排列用户经历的主结构。
- [x] D0f：模型明确分两层：真实音频时间轴是实际发生状态的底层事实；虚拟事件轴在同一时间坐标上，按语义/活动把大块区间圈出、命名，未被圈出且有留存内容的余量自然是未整理大块。事件轴是派生组织层，不改写真实层。
- [x] D1a：持续采集与自动整理不依赖 Mark；Mark 是某一时刻的重要性感受信号，不是收藏或保留指令。
- [x] D1b：开启记录后持续采集；从音频层面清理无声和无意义噪音。保留下来的人声音频及对应粗转文字持续存在，文字缺少语义或未成事件都不是删除理由。
- [x] D1c：每场会议按整场活动的开始与结束形成自己的大块事件；两场会议各自独立，本例不要求跨事件组合层。
- [x] D1d：声音保留判断遵循保守原则：疑似有人声、声音较远或粗ASR未识别出文字时保留；纯风扇、键盘、提示音、纯音乐等无人声片段清理；夹杂可辨人声时保留对应片段。该判断是独立、可调试优化的策略环节，不用语义信息量或粗ASR质量当删除门槛。
- [x] D1e：有效事件优先保留完整会话，不按语义价值继续裁掉寒暄、重复或简短回应；明确无声的清理原则沿用 D1b，不能破坏真实时间关系。
- [x] D1f：电脑播放的课程、视频、播客等有完整语义的内容也可自动整理成事件；用户必须能随时手动关闭记录。
- [x] D1g：明显有人交谈但粗转录差时，保守形成普通会话事件并注明识别不清，不因ASR失败删除音频或已有粗转文字。
- [x] D1h：连续声音先分三类：无声/无意义噪音，清理；有人声但尚无聚焦主题，作为原始素材；粗识别文字呈现语义连续性且相对有意义的对话/会议等，组织成日常内容块并进入精加工。
- [x] D1i：有人声但未成命名事件的音频和对应粗转文字持续保留；它们按原有时间位置落入命名事件之外的未整理大块，可在其中找回并手动精转或删除，不再因24小时到期或未晋升而自动清理。
- [x] D1j：明显连续的谈话即使本地粗转录很差，也应保守形成事件并在云端可用时进入精转；不能用本地ASR质量作为唯一晋升门槛。一期不设应用侧预算限制。
- [x] D1k：短但信息明确的片段，即使没有长段语义连续性，也应自动形成事件；不能设固定时长门槛。
- [x] D1l：工作场景是首版优先优化目标，不是内容保留的硬过滤条件；连续且有意义的课程、播客等仍可形成事件。
- [x] D1m：时间轴上相邻且确属同一件事的时间段可归成同一大块事件；无法可靠判断时不合并。用户可接受漏合并，不能为提高合并率误合并不同事件；不把逐句合并当作用户层事件构造方式。
- [x] D1n：本地粗转录应在录制中持续产生稳定句段，而不是等整场会议结束后才处理；参考 MyAgents 现有录音记录实现。
- [x] D1o：事件以整场会议等真实活动的起止时间为主要边界，形成一个大块虚拟 group；底层音频封块和粗转录句段可以很碎，但事件不靠逐段挑选、剔除来拼接。
- [ ] D1p：声音保留策略的具体识别方法、参数、调试观测与误删评估由架构/验证方案单独设计；用户已确认保守的产品行为边界，不要求现在锁死阈值。
- [x] D1q：同一会议中途出现真实无声间隔，后续继续讨论同一件事时仍归为从会议开始到结束的大块事件；无声/噪音处理只影响内部音频素材，不把会议拆成许多事件。
- [x] D1r：麦克风和系统声音分别判断内容关系；同一对话可在一个事件内引用两路声音，互不相关的内容即使同时发生也可以分别标注，但都位于使用者唯一的时间线上的同一时刻。此前同意可形成重叠事件，不意味着用户经历被重排成两条回忆线。
- [ ] D1s：大块事件的起止检测、双路来源归属、同时发生的独立内容及底层音频/转录映射，需在架构方案中具体设计；不能把底层细碎句段暴露成事件分组的主要操作单位。已形成候选切分与事件边界分离的技术原则，仍待样本验证。
- [x] D1t：大块事件按实际活动的开始与结束划边界：同一场会议内更换议题仍为一个事件；会议结束后另起的谈话即使沿用同一议题，也属于下一段经历。
- [x] D1u：活动尚在进行时，时间线上可先显示一个持续增长的“进行中”大块，本地粗转录继续实时呈现；活动结束后再确定事件边界与标题。
- [x] D1v：后续证据表明自动边界判断错误时，系统可修正尚未被用户手动调整的事件；用户手动拆分、合并等修订优先，不被自动结果覆盖。
- [x] D1w：用户确认两层处理架构：第一层在真实音频时间轴上做语音检测与本地实时粗转录，产出带时间的粗文本；第二层从粗转录文本到事件拟合，先做可替换的候选粗切分，再由LLM工作流按实际活动整理、命名并触发后续处理，形成虚拟事件轴。
- [x] D1x：首版事件拟合使用必须配置并开启的云端LLM能力；无需再承诺云端关闭时有完整本地事件拟合替代路径。本地语音检测和实时粗转录仍先于云端事件拟合。
- [x] D1y：按主题自定义 Prompt/Skill 等后处理预留架构扩展点，用户可配置的工作流与自动摘要/结论均不属于本版交付；作为后续版本需求单独定义。
- [ ] D1z：“连续约15分钟没有粗转录文本”是事件拟合层候选粗切分策略的初始设想，不是架构不变量；具体时长、空档判定、跨候选合并与失败补救可独立调试、替换和验证。
- [x] D2：所有通过无声/噪音清理的人声音频及粗转文字默认持续保留；事件标注与精转不改变基础保留资格。此前“未成事件24小时到期”的决定已由最新用户批注取代。
- [x] D2a：有效事件的音频、文字、截图一起保留，用户可主动删除；未成事件的人声及粗转文字同样默认持续保留。
- [x] D2b：未成命名事件的人声音频和粗转文字仍须可找回、可手动精转或删除；没有单独的24小时到期与误判补救池。找回入口是主时间线上命名事件之间自然形成的未整理大块，见 D5i。
- [x] D2c：全局音频存储达到上限时暂停采集并提醒，不自动删除旧人声；用户可调整存储上限，同时监测设备实际可用空间，任一安全边界触发时暂停。默认容量与预警数值待真实采样校准，不让用户拍脑袋决定。
- [x] D2d：已处理但未成事件、尚未处理、处理失败、正在形成事件的人声都不因处理状态自动到期；处理状态仍需明确展示。
- [ ] D2e：当未来全局存储策略实际清理音频时，如何处理共享物理文件、虚拟事件引用、粗转文字和派生结果；清理不得制造悬空引用。
- [ ] D2f：已确认真实音频时间轴与虚拟事件轴共用时间坐标的双层模型；工程方案仍须将双路来源、真实缺口、处理版本与保留状态一并纳入，保证事件边界修订不改写底层事实，不能仅凭墙钟时间戳推断内容关系。
- [x] D2g：所有清理入口统一使用“清除原始音频”和“清除全部数据”；默认选择前者，后者在任何场景下均须额外弹窗说明。前者保留文字、事件标注及其他非音频关联内容，并明确显示不可回放；后者清除选定范围内全部关联数据。
- [x] D2h：容量不足导致的暂停，在用户释放空间或提高上限后仍保持暂停；用户须手动启动记录，不自动恢复。
- [x] D2i：两种清理动作统一接受一个可预览的时间/事件选择范围，入口覆盖单个命名或未整理大块、选定时间范围及全部历史；跨事件共享同一来源区间的音频清理会影响所有引用，执行前展示受影响事件。已导出或服务商已接收的副本不假称可随本地清理抹除。
- [x] D2j：接近用户设定的音频上限或设备安全剩余空间线时提前提醒一次，达到边界后暂停采集并显示具体原因；去重提醒、恢复滞后量和具体阈值由实测确定，空间恢复后仍待用户手动启动。
- [x] D2k：“清除原始音频”保留文字、事件、截图/Mark/评论和搜索，但对应区间不可回放、不可再发起依赖原音频的新精转。待提交ASR任务取消；已经提交服务商的任务可结束并保存非音频转录结果，不重新写回原音频。操作界面预先提示受影响的待精转数量。
- [x] D2l：“清除全部数据”对所选真实时间/来源范围内的音频、转录、事件及关联动作执行逻辑失效，并取消相关待办/阻止迟到结果复活，随后安全清理物理副本；所有场景均按既有决定另弹说明确认。部分交叠事件按实际受影响区间调整，不误删未受影响范围。
- [x] D2m：用户确认全局声纹库加入后，默认“清除原始音频”保留已提取的声纹特征和人物归属，清理预览需明确说明；原声清掉后相应样例不能回听或重新提取。“清除全部数据”仍删除选中范围贡献的声纹样例和特征，清除全部历史时清空人物库。
- [ ] D3：首版必配云端LLM和云端ASR的能力边界、首次启用门槛及无应用侧预算限制已定；具体供应商接口和处理状态细节待验证收敛。
- [x] D3a：用户自带API Key；精选核心供应商，火山引擎ASR为首个验证候选，不默认建设hear账号/额度后台。
- [x] D3b：首版云端能力必须配置并开启，包含两项可单独配置的能力：LLM用于粗转录文本到虚拟事件轴的事件拟合，云端ASR用于精确转录。首次启用全天录制前两项均须配置且验证成功；此前“云端可一直关闭但产品仍完整运行”的理解已被本次决定取代。
- [x] D3c：默认所有有效事件都精转，不因本地转录已清楚而跳过；未来细分策略可设置，尚不作为本轮必交付的规则系统。
- [x] D3d：默认精转完整会话，不只处理重点/不清楚的片段；传输分块属于技术实现，不能偷换成只覆盖部分内容。
- [x] D3e：一期以能力验证为主，不做应用侧月度预算上限、预算拦截或超额续算逻辑；此前“提供默认月预算”的决定由本次答复取代。
- [ ] D3f：仍须核实LLM和ASR服务商的接口、鉴权、计量及成本，以保证集成与信息展示准确；不因此在一期实现预算限制。
- [x] D3g：LLM和ASR分别配置；云端LLM的自动输入限于候选区间的粗转文字、时间与来源，云端ASR只接收需要精转的事件音频，截图不随两项能力自动上传。
- [x] D3h：首次配置完成后，LLM事件拟合与云端ASR精转可以分别暂停/继续；本地采集、语音检测和粗转录不因任一云端队列暂停或暂时不可用而停。点击继续后，对应队列自动处理积压任务。
- [x] D3i：时间轴上的内容需有分阶段可见处理状态，至少区分尚待LLM事件拟合、已拟合但待精转、正在处理、已完成和失败；未被选成命名事件不等于处理失败。LLM与ASR暂停状态分别显示，具体文案与显示位置待交互设计。
- [x] D3j：两项云端队列分别控制；点击暂停后不提交该队列的新请求，已经发出的请求允许完成并保存结果；点击继续后自动消费该队列积压。未被用户主动暂停但遇到断网/服务商暂时故障时，恢复后自动重试，持续失败则保留失败标识并提供手动重试。
- [x] D3k：自动精转是LLM事件拟合的下游：LLM先判断活动是否需要命名与精转，形成/更新事件后才创建持久的ASR任务。LLM暂停时ASR可消费已有任务但没有新的自动判定；ASR暂停时LLM仍可形成事件并积压精转任务。
- [x] D3l：此前已确认用户可对未命名原始素材手动发起精转；这属于用户明确给出的处理决定，可直接创建ASR任务，不改变“自动精转须由LLM先判定”的依赖。若ASR队列暂停，手动任务也排队待继续。
- [ ] D3m：事件边界修订后旧ASR任务的取消/重建、迟到结果的归属与队列优先级须在方案中确定；ASR任务须绑定事件/素材范围及其版本，不能向已变化的事件写入过期结果。已形成按不可变素材范围校验、人工请求优先的技术原则，仍待供应商时间戳能力验证。
- [x] D4：首版 macOS 平台范围、双路来源、锁屏和登录后自动启动的产品行为已定；具体设备与系统版本门槛和功耗需实测。
- [x] D4a：默认麦克风及电脑播放声音两路均启用，可分别关闭；两路分别判断活动状态，静音时降低资源消耗。
- [x] D4b：锁屏但电脑未睡眠时继续记录，锁屏不改变用户开启状态；实际睡眠暂停。
- [x] D4c：登录后自动启动，并恢复上次记录/手动暂停状态，不能覆盖手动暂停意图。
- [x] D4f：首版的自动启动承诺从用户登录且应用可运行时开始；开机但尚未登录的系统阶段不采集。登录后的锁屏且未睡眠仍按 D4b 继续记录。这是对既定“登录后自动启动”的实现边界收敛。
- [ ] D4d：静音监测实现需验证功耗、弱音/句首召回及设备异常识别；不承诺彻底关闭设备后仍能无损唤醒。
- [x] D4e：用户可随时手动关闭记录，既有手动暂停意图持久化规则继续有效；不能把用户关闭实现成静音监测待机。
- [x] D5：悬浮操作、主时间线、历史查看、关键词/日期搜索和人工修正的首版产品范围已定；视觉与交互细节待设计验证。
- [x] D5a：一键截图默认捕获当前正在操作的整块屏幕。
- [x] D5b：截图/Mark后不自动出现评论；评论通过悬浮组件展开的操作主动进入，不因“不出现评论”删除评论能力。
- [x] D5c：日常入口是桌面常驻的悬浮组件（类似悬浮球/桌宠），显示状态并及时响应；hover时展开Mark、评论等操作。
- [x] D5d：单击悬浮组件立即截取当前正在操作的整块屏幕；用户确认“解脱”指截图。
- [x] D5e：悬浮组件统一提供入口，Mark、评论、暂停/恢复等轻操作就地完成；历史、搜索和设置打开独立窗口。

## 决策台账

### 2026-09-27：分发渠道与源码状态

- 用户明确 0.1 通过 macOS `.dmg` 直接分发，不走 Mac App Store。安装版仍按直接分发路径完成签名、公证、权限与常驻核心验证。
- 用户明确 hear 现阶段主要验证产品体验，源码暂时闭源；未来若开源，Apache-2.0 或 AGPL-3.0 仅为可能选项，尚未决定。MyAgents 现有 AGPL 声明与第三方组件的各自许可在复制前逐项核对。

### 2026-09-27：精转句段人工纠错

- 用户选择首版支持精转逐句纠错。修正作为独立版本保留，不改写云端原识别文字、原声时间/来源或说话人归属；默认显示、搜索与导出使用修正文字，并标明人工来源，允许回看或撤销修正。
- 再精转或边界修订后，仍能可靠定位到原声范围的人工修正继续生效；若新分句无法可靠对应，则保留修正记录并标为待核对，不能静默覆盖或移到错误发言。清除原始音频后留下的精转文字仍可修正；清除全部数据时一并删除相应修正。CLI 与界面同能力。用户选择的是精转逐句纠错，不等于粗转文字编辑或完整逐字稿编辑器。

### 2026-09-27：声纹特征的清理语义

- 用户选择默认“清除原始音频”保留已提取的声纹特征，让全局人物匹配继续可用；执行前须在预览中明确告知。原声音频删除后，样例失去回听和重新提取能力。“清除全部数据”继续按选中范围删除关联身份数据，全部历史清理同时清空全局人物库。
- 由全局人物身份与原声时间锚点的既有原则补齐：用户给本场 speaker 指定人物，可作用于该 speaker 在本场的发言；具体某条发言若错归，可按原声时间范围局部纠正。不同人物同名时以稳定 ID 区分，不按文本名字自动合并。

### 2026-09-27：全局人物声纹库与自动匹配

- 用户澄清：声纹库必须是全局的；初次没有匹配时显示 speaker1/speaker2，用户选择并命名后建立可复用的人物声纹档案。以后在其他说话人的身份选项中能选择已有人物，并且每次匹配姓名时系统先自动匹配全局声纹库。这替代了此前“0.1 仅有会话内说话人分段、跨事件人物库待决策”的范围假设。
- 产品行为：本场 diarization 的 speaker 编号只在本场有效；精转后本机提取可用说话人特征，与全局人物库比对。可信匹配直接显示人物名并标明自动来源，不可信则保持本场编号；用户可选已有的人或创建新人，人工修正优先。命名时自动为合格的清晰单人说话片段建立样例，不合格片段不能污染声纹库；没有合格样例的人物仍保留人工命名，待后续补充。
- 全局库的生命周期必须服从既定清理动作：“清除原始音频”保留已提取的派生声纹特征并在预览中说明，“清除全部数据”删除选中范围贡献的样例、特征和身份归属，清除全部历史时也清空人物库。用户可在图形界面与完整 CLI 中管理人物及纠错。匹配质量、阈值、来源差异与资源消耗由样本验证，不把模型相似度等同于绝对身份保证。

### 2026-09-27：人工补建事件、边界修订与身份库提议

- 用户确认：在未整理时间段选择范围、新建并命名事件，随后触发精细转录；已有事件也能修改开始和结束时间，转录处理随之自动适应。两类操作属于虚拟事件层的人工修订，声音、粗转、截图与评论仍锚定真实时间。
- 手动补建命名事件是用户直接要求处理整场素材，可绕过 LLM 对是否值得精转的自动判定，向 ASR 队列创建任务；ASR 人工暂停仍生效。改边界后，当前事件的精转范围跟着更新；可核实时间定位的有效结果可复用，新纳入范围补精转，过期任务或迟到结果不能覆盖新版本。音频已清理或未采集的范围明确显示不可精转。
- 用户最初提出“按人身份的声纹库”设想：希望在手动修正说话人后，可能把可信语音片段添加为该人的样例。MyAgents 现有实现提供单条录音内的说话人分段、人工修正及原音频锚点，也有本地说话人特征提取模型，但没有跨录音的长期人物库。随后用户已进一步明确全局人物库和自动匹配为首版范围，见本台账顶部最新决定。

### 2026-09-27：PRD 审查与说话人分段

- 用户要求审查 PRD 中未写清的产品边界；可以从既有决定推导的内容由助手直接完善，真正改变范围的事项再澄清。
- 用户先确认首版精转文字要求会话内说话人分段。本场临时标签仅在当前事件中相对有效，模型不确定时标未知，质量须在多人轮流及重叠发言样本上验证。后来补充了独立的全局人物声纹库，不能再将此前“尚未确认跨事件身份”视为现行边界。
- 由既有双层时间轴和“时刻动作独立存在”原则补齐：安静时仅有截图、Mark 或评论也必须在主时间线可见；按日期查看不把跨午夜的同一活动拆开。
- 由既有“事件只作虚拟组织、素材持续保留”原则补齐：用户可以取消错误的事件标注，使内容回到未整理区域；精转默认展示但保留粗转来源，并避免搜索重复命中同一段声音。
- 由录音与云端队列独立、主动截图独立的既有原则补齐：暂停录音不自动暂停两条云队列，也不阻止主动截图；一路音频故障不拖停另一条；时间范围的“清除全部数据”不重置供应商配置、来源开关或暂停意图。
- 由“电脑可用时持续记录”的核心承诺补齐：电池/热压力先让推理和云处理退让；低电量本身不授权静默停录。旧 RFC 的低电量自动停止采集只能作为历史候选，须按新版 PRD 修订。

### 2026-09-27：首版平台与命令行范围

- 用户选择首版正式支持 macOS。Windows 在后续平台计划中保留，但不作为本版交付承诺；最低 macOS 版本、芯片和功耗要求通过真实设备与所选采集 API 验证后确定。
- 用户随即纠正：命令行功能须“按照预期提供完整的”，只是先限定在 macOS 场景下闭环做完。前一版把 CLI 收窄为只读，并排除录音控制、删除、精转请求，是错误理解，现已撤销。
- 首版 CLI 覆盖本版产品已经定义的实际能力：首次配置与就绪检查（云端凭据经安全输入/系统凭据存储）、录音开始/暂停/恢复和两路来源开关、截图/Mark/评论、命名及未整理大块的列表/读取/关键词与日期搜索、事件标题及边界修订、LLM/ASR 队列暂停恢复和手动精转、选定范围导出，以及两种清理。具体命令表、参数与机器可读输出在工程方案中冻结，不能以“CLI 完整”为由扩大到本版尚未承诺的摘要、语义搜索或跨平台能力。
- CLI 操作同样经过核心的权限、素材范围、版本和清理检查；“清除原始音频”仍为清理默认选项，“清除全部数据”仍须在任何入口展示额外说明弹窗并确认，不能因从终端调用而绕过。选定范围导出可含文字与时间/来源元数据，音频和截图由用户显式选入，不默认导出全天或已清数据。
- “完整 CLI”意味着常规配置、查询、记录和修订工作流可从终端完成，不要求先手动打开应用窗口。若核心未运行，读取类命令可启动不采集声音的本机核心来处理请求；只有显式开始记录命令才改变采集意图。录音权限等系统级许可仍按 macOS 要求由系统确认；“清除全部数据”因已定的任何场景额外弹窗规则，可唤起原生确认窗，无图形会话时应清楚失败，不提供绕过开关。具体进程/IPC 机制须工程验证。MCP/通用网络服务属于另一种接入面，不因 CLI 完整而自动纳入。

### 2026-09-27：事件候选、修订与精转任务的技术原则

- “15 分钟无文本”只提示当前候选可暂时封口，不能直接宣告活动结束。事件拟合应读取相邻候选的上下文，允许跨候选合并，也允许在一个候选中拆开两场相邻活动；LLM 不确定时保留未整理或分开的块，避免错误合并。对于长时间没有空档的讲话，候选输入需有可续接的大小上限，输入封块不等于用户看到的事件边界。
- 第一层同时输出粗文字和语音检测结果。检测到疑似人声却没有可用文字时不得当作确定的“15 分钟无语音”；候选策略可使用声音存在、来源、时间和已有人工动作辅助判定。第一层的保留/清理策略与第二层的事件拟合策略各自有版本，便于用同一批真实样本对比和回放调试。
- 事件拟合的输出使用有边界、有来源、有处理版本的结构化结果。命名事件占据活动级时间区间；未命名的剩余时间通过时间轴差集自然形成未整理大块，不另存一套可被模型任意拼接的“未整理事件列表”。自动修订只更改虚拟层，标题、边界等人工改动分别保留优先权。
- 自动精转任务由LLM判定创建，任务记录当时的事件版本与不可变音频来源/时间范围。用户直接请求的手动精转优先处理，但仍遵守ASR暂停状态。新边界或删除到来时，尚未发出的旧范围任务作废并按新范围重建；在途结果只在仍有效的真实素材区间与可核实的时间定位上复用，否则标为过期且不能写入现行事件。云端超时若无法判断服务商是否已受理，先核对/查询状态，不无界重发同一付费请求。

### 2026-09-27：无需产品决断的首版交付细节

- 首次设置自动准备本地语音模型：MyAgents 现有录音实现已经采用应用自带推理运行时、独立下载和校验模型包的结构；当前模型源清单约 210 MB 下载、约 285 MB 安装。hear 首版沿用这一交付思路，但复用代码前仍需验证许可证、质量、性能和具体模型版本。模型未准备好时不宣称已经实现实时粗转录或完整的全天记录。
- 登录边界：已确认“登录后自动启动”与“锁屏未睡眠继续”足以定义首版行为；开机但尚未登录时不运行用户级采集，避免引入系统服务、账户密钥和权限语义。若以后要覆盖登录前阶段，作为独立产品范围决定。
- 主题级自定义 Prompt/Skill 后处理先留扩展接口，不作为 0.1 用户配置能力或验收条件；这遵循已确认的本版不自动摘要/结论范围，不妨碍后续版本加规则。

### 2026-09-27：由设计方案收敛的全局音频空间与清理语义

- 讨论方式调整：用户要求先由助手按技术实践和用户体验判断，只有真正需要产品选择的事项再提问。以下是设计层收敛，非用户逐条确认的数值参数；默认GB、剩余空间安全线和预警比例仍须以录音体积/磁盘实测校准。
- 容量：提供可调整的本地音频占用上限，另监测存储卷实际可用空间。达到任一边界暂停采集并说明原因，接近边界时去重预警；不静默清旧人声，不自动恢复。截图和其他数据虽不计入音频上限，仍受实际磁盘空间安全线保护。
- 统一范围模型：所有清理入口先选时间/来源区间或由事件映射出的实际素材范围，界面可提供单个命名/未整理大块、时间范围、全部历史三个入口；底层执行同一套范围清理。预览将删除什么、影响哪些重叠事件和可释放的估计空间，避免每个入口实现不同语义。
- 共享素材：底层音频以来源与时间区间为准。若两个虚拟事件引用同一段真实音频，清除该音频会影响两处回放；同一时刻的另一来源若不在选定素材范围内，不受牵连。清理前展示所有受影响事件；被清理区间从共享物理文件中隔离，不能保留可访问的旧副本或悬空引用。

### 2026-09-22：媒体内容、识别不清与手动关闭

- D1f：有完整语义的电脑播放内容也是用户接触的上下文，自动整理范围不限于用户参与的工作会议。
- D1g：明显有人交谈而粗转录较差，优先保守留下，形成普通会话事件并注明识别不清；不因ASR失败丢掉会话。
- D4e：产品必须提供随时手动关闭记录的能力。已确认的双路分别关闭、手动暂停跨重启保持规则继续成立。
- 工程语义建议：全局关闭须停止两路实时采集/监测，不继续保留关闭期间的声音；重新开启不能把暂停期缓存作为前缀带回来。已保存记录的浏览不依赖开启采集。入口建议托盘/菜单栏可见开关及全局快捷键，具体键位属于后续交互设计。
- 区别：静音待机属于记录已开启时的自动省资源策略；用户关闭属于明确停止意图，不能被检测到声音、锁屏解锁或登录恢复机制覆盖。

### 2026-09-22：云端服务方式与自动精转

- 用户原话：「1. A，预期我们会精选一下最核心的供应商，比如火山引擎的 ASR 能力作为首个候选。2. A」。
- 定了什么：用户提供自己的服务商凭据，hear直接调用；采用精选供应商策略，火山引擎ASR是首个验证候选。不是承诺任意供应商通用兼容，也没有要求自建账号、额度或计费后台。
- 当时的自动模式：用户开启云端并接受/调整预算后自动处理，支持手动指定；后续确认精转覆盖所有有效事件的完整会话。最新决定已将云端LLM与云端ASR改为首版必配必启，“云端可一直关闭、仅本地处理”不再是完整使用模式。
- 为什么：维持独立桌面产品的范围，以少量验证过的供应商保证集成与识别质量；自动处理符合无需用户逐条照看的定位。
- 原待定的自动筛选、精转粒度和预算设置方式已由下一条决策收敛；金额与供应商能力仍需验证。
- 选型验证：后续核实火山引擎具体产品/接口、真实鉴权字段、时间戳能力、中文/混说/远场质量、音频输入方式、计费与请求终态。用户用“API Key”描述自带凭据模式，不意味着厂商实际只有一个Key字段。当前没有调用真实云服务或验证价格。

### 2026-09-22：全事件、完整会话精转与当时的默认预算方案

- 用户原话：「1 B，这个未来细分策略可以设置。2 A 3 B」。
- 定了什么：开启云端时默认对所有有效事件精转，覆盖完整会话；即使本地文字已较清楚也不据此跳过。此决定取代早期“默认只挑高价值/识别不清片段”的建议。
- 当时的预算方案（已被最新决定取代）：产品提供可修改的默认月预算，金额结合实际计费确定。最新用户决定一期仅验证能力，不做应用侧预算上限或拦截。
- 范围区别：所有有效事件不等于所有原始音频。静音和被判无效的干扰不因此上传；Mark既不是上传必要条件，也不是独立外发授权。
- 后续策略：用户希望未来可设置细分策略，当前先确定全事件、完整会话的默认行为，不擅自引入复杂规则配置界面。
- 最新架构下，本地粗转录仍提供实时文本与时间锚点，云端LLM负责事件拟合；服务商故障或用户暂停可影响处理时延，不能把暂未拟合或精转伪报成已完成。首版不实现应用侧预算耗尽/补算逻辑。
- 待同步：PRD精转触发描述、RFC云端选择与优先级语义，以及原先把Mark直接关联长期保留的表述统一修正。

### 2026-09-22：悬浮组件作为日常入口

- 用户选择：「1 A  2 不出现评论。」截图默认当前操作的整块屏幕；截图或Mark完成后不自动打开评论。
- 用户原话：「正常情况下，它在桌面上表现为一个类似于悬浮桌宠或悬浮球的东西，始终保持一个状态，并且是实时响应的。」
- 用户原话：「只要点击这个悬浮按钮，就可以完成“解脱”的操作。」
- 用户原话：「当鼠标 hover（悬停）在这个按钮上时，可以出现一些其他的操作，比如你提到的评论、mark 等。」
- 用户原话：「此外，刚才提到的那些最长、最多的功能，也都可以通过这个悬浮组件来实现。」
- 已明确：常驻悬浮入口、状态反馈、单击主动作、悬停展开其他操作；评论由用户主动进入，Mark仍是轻量时刻信号。
- 后续已确认：主点击指截图；轻操作就地完成，历史/搜索/设置独立窗口。具体视觉是球还是角色、状态呈现与动画程度留给交互设计，不由类比自动推导。
- 不推导：桌宠类比不等于要求养成玩法、角色动画或常驻高频视觉效果；“通过悬浮组件”不等于已决定把完整历史列表、搜索与设置都塞入浮层。
- 待技术验证：悬浮交互不抢前台输入、截图不包含自身控件、跨屏定位与缩放、全屏应用场景以及静态/动态状态反馈的资源成本。这里仅登记验证点，不宣称实现完成。

### 2026-09-22：悬浮主动作与复杂功能入口

- 用户原话：「1 对，截图 2 A」。
- 定了什么：单击悬浮组件完成截图；悬停展开Mark、评论、暂停/恢复等轻操作。历史、搜索和设置从悬浮组件进入独立窗口。
- 为什么：日常记录动作随手完成，复杂内容浏览有足够空间；不增加第二套互相竞争的记录入口或让截图自动弹评论。
- 后续交互设计需明确：悬浮控件隐藏与恢复、拖动与点击区分、多屏“当前操作屏幕”的判定，以及主动评论的时刻锚点；普通键位和视觉细节由设计方案提出。

### 2026-09-22：事件修正、搜索与摘要范围

- 用户原话：「1 A  2 A 3 B（一期需求不要，但记录需求作为下个版本）」。
- 定了什么：本版支持改标题、拆分、合并事件；提供关键词和日期筛选，检索转录、评论、截图文字；不要求语义搜索。
- 本版展示：标题、完整文字稿、音频、关联截图与用户时刻信号/评论，不自动生成摘要或关键结论。
- 未来需求：自动事件摘要与关键结论已单独登记在[下一版本需求](../BACKLOG.md)，不是当前PRD内待补齐的开发批次，也不预先冻结未来模型/接口方案。
- 边界：本次确认的手动修正是标题及事件归组；不能据此自动扩大为全文转录编辑器或音频编辑器。

## 张力时刻

- 开工准备审查一次列出过多信息；用户要求改为逐个提问并由其决策。
- 自动整理的验收不能被“短期原声可手动回溯”替代；这是审查建议，尚待产品契约收敛。
- 用户纠正：把 Mark 理解成重操作的收藏/保留，错误地把持续记录与人工选择绑定。后续提问应围绕自动筛选与事件组织，不再围绕“是否 Mark 才保存”。
- 用户认可虚拟事件归组，随后明确撤销按24小时自动删除未成事件人声的方案；存储清理另立全局策略，不能再依赖事件入选结果决定是否保留原声。

## 必赢场景

已有目标：无需 Mark 也持续留下人声与粗转文字；自动把会议、通话和有意义的临时讨论标成独立事件，关联截图、时刻信号及评论，事后能找回细节。会议一与会议二各自整理成事件，事件内优先保留完整会话；零散有人声片段未成事件时仍在长列表可找回、可手动精转或删除。只有无声/无意义噪音按采集清理规则去除；全局容量与清理策略尚待独立收敛。

## 全局音频存储清理策略（待讨论）

- 本章负责全局容量、提醒、暂停/恢复和可能的清理行为，不借用“是否被标为事件”决定人声音频及粗转文字的保存期限。
- 当前已确认：通过无声/噪音清理的人声音频与粗转文字默认持续存在；用户可主动删除。没有未成事件人声的24小时自动到期规则。
- 音频占用达到用户可调整的上限或设备实际可用空间过低时暂停采集并提醒，不自动删除旧声音；提前去重预警，具体容量和磁盘安全阈值待实测校准。
- 所有清理入口统一使用“清除原始音频”和“清除全部数据”；前者为默认项、保留非音频关联内容并显示不可回放，后者在任何场景下须另有说明弹窗、清除选定范围内全部相关数据。
- 空间条件恢复后仍维持暂停，须由用户手动重新启动记录。
- 范围与提示：单个大块、时间范围、全部历史走统一范围清理；共享底层音频删除会影响所有引用并在操作前展示，外部导出/已外发副本不假称可由本地操作清除。
- 技术约束：任何物理删除都须同步裁决共享音频区间、Event、转录、截图关联、搜索索引与迟到任务，不能留下可访问的已删内容或悬空引用。

## 原子交付边界

- 本 PRD 必须一次完成并统一上线的范围：macOS 工作电脑上，登录后按上次启用/暂停意图自动采集麦克风与系统声音；本地语音检测、实时粗转、保守保留人声；云端 LLM 事件拟合和云端 ASR 整场精转；单一连续时间线上的命名事件与未整理大块；悬浮组件主动截图/Mark/评论；回放、修订、关键词/日期搜索、导出；全局存储上限与两种清理；覆盖同一能力的完整 macOS CLI。两项云端能力需首次设置，之后可分开暂停。
- 反向边界：参考现有 PRD 第2节并纳入本轮新决策：本版不提供语义搜索、自动摘要或关键结论；自动摘要作为下一版本独立需求登记。

## 技术前提

- 已有依据：RFC 包含平台资料、候选架构和资源推算；推算不等于实测。
