## 决策台账
### D1: 设计先于开发
- 定了什么：先理解产品、探索并共同收敛全部设计要素，再开展具体实现。不修改生产组件与已有更名工作。
- 为什么：需要建立可持续迭代的独特美学，换色或局部美化不足以解决现有问题；不能把第一轮探索包装为定稿。
- 用户原话：「咱们最终的目的是在这个 session 里完成我们这款产品的真正新版本的全部设计相关的要素定稿。之后会在进行具体的开发一步一步来。时间非常充裕。」

### D2: Loppi 与开源发布
- 定了什么：产品正式名称按 Loppi 处理，设计面向用户明确提出的开源发布意图。
- 为什么：当前分支为 `codex/rename-loppi`，大量已暂存更名改动正在进行；设计探索应在独立新目录内累积，避免混入更名实现。
- 用户原话：「当前分支还在进行一个工作是更名，从原来的 hear 改成了最新的 loppi」；「我接下来会把这个产品正式开源并发布」。

### D3: 安静与简洁是产品原点
- 定了什么：持续记录、少打扰、兔子形象构成探索起点。现有兔子不是必须全部推翻的对象，也未正式确认不可改变。
- 为什么：品牌应来自真实使用关系；不可为“独特”引入需要照顾宠物的负担、炫技动效或过量装饰。
- 用户原话：「它是一个 7×24 小时默默在后台记录用户笔记本所有音频信息的产品，以一个兔子的形象不打扰用户，默默承担这一切。」；「形象上我其实初步觉得哈可以是现在这个兔子的形象。」

### D4: 安静的桌边伙伴
- 定了什么：用户选择「安静的桌边伙伴：有性格、有温度，但不需要照顾它」。此项确认的是人与产品的关系，没有确认 A/B/C 的视觉方向、色彩或布局。
- 为什么：陪伴应降低持续记录的注意力成本。性格与温度由角色的细微回应、文案分寸和交互体贴承载；用户无需管理兔子的需求。界面保持清楚、克制，让内容容易找回。
- 用户原话：「安静的桌边伙伴：有性格、有温度，但不需要照顾它（我倾向这一项）」
- 设计推导（待关键场景校验）：常驻时低注意力；主动接近时轻微回应；主界面以真实记录为主；异常要说明事实与恢复动作，避免拟人化自责、索取陪伴或让用户产生负担。它可以采用有力度的排版与中性色，不从“伙伴”直接推定浅绿、大圆角或宠物化 UI。

### D5: A 的温暖感值得继续探索（暂定倾向）
- 定了什么：以第一轮 A「日常手札」作为第二轮探索母方向，保留“稍微好一些”的不确定程度，尚未确认整体路线、字标、字体、朱红色、布局或最终方案。
- 为什么：用户首先感知到 A 更温暖；需进一步识别温暖来自底色、排版、容器减少还是其他因素。第二轮保留纸白与墨色，比较轻微书卷气和更清爽的当代字形，同时减少日期/概览的视觉负担。
- 用户原话：「你发的那个三个，感觉第一个好像更加温暖一点？稍微好一些」

### D6: 沿 A2「清爽日常」深化独特身份
- 定了什么：用户选择第二轮 A2 为继续深入的基底；保留舒适、温暖、清爽日常的方向。具体色值、字标和组件尚未定稿。
- 为什么：用户明确感到 A2 更舒服，但仍普通；下一轮应探索可跨主界面、入口与发布物料复用的品牌语言，不能停留于通用的米白/无衬线/细分隔配方。
- 用户原话：「清爽日常这版感觉更舒服一些，可以沿着这个方向继续。不过现在还是有点普通，在深挖打磨一下。」
- 设计师下一步：从当前兔子的像素、奶油与桃色细节提炼可复用的尺度和形状；检验自定义字标、时刻标记、阅读排版和主次色比例之间的一致关系。以视觉假设呈现，尚不视为用户已选中具体标记或标志。

### D7: 已完成用绿、进行中用温和暖红；i 点回归深色简单方点
- 定了什么：用户回指并附上第三轮 `soft-pixel-identity.png`，认可其逻辑与色彩。绿色代表已完成的记录，温和红色系代表进行中/记录中。字标 i 点采用前面较深的暖红色，取消浅色阶梯形，改为简单方点。
- 为什么：连续记录需要可感知、低压迫的状态表达；用户认可温和色彩。字标保留简洁、清楚的小尺度识别，减少阶梯细节。
- 用户原话：「这张的逻辑与色彩我觉得挺好的哦，绿色代表了已完成的记录；红色系代表了进行中、记录中的状态。且都比较温和，这是一个持续的事情没有给人太强的压迫感。但就是那个颜色在 logo 里面 i 的那个点，我觉得你前面那个深色的更好一些，浅色做的阶梯有点复杂了。日期和兔子的关系等会再说。你先把上面这部分梳理一下，在出一张图我在确认一下。」
- 用户确认程度：语义与简化方向明确，具体色值、方点尺寸和新确认图仍待用户审阅。以用户这次附图为调整基准，不误用最后的“当天一页”空间探索。
- 覆盖旧推导：第三轮设计师认为“正常记录暖色属于错误”的判断撤销；进行中的暖红现在是用户明确选择，不再强制正常状态使用薄荷色。
- 本轮边界：只整理色彩/状态与字标细节并出一张确认图；日期、兔子布局和导航方式暂缓讨论，不将其收敛或改动。
- 本轮设计落实：已完成音频与已保存笔记标记用柔和绿；正在记录、当前时间、当前播放进度/阅读定位用柔和暖红。暖红用于小面积标记、细线和浅底，正文保持炭黑。字标方点独立用较深暖红。
- 语义精度：绿色表示当前对象已完成/留存，不能凭音频已结束推定精转或云任务已完成；处理状态仍由文字给出。故障/删除等完整语义体系留待后续设计，不在本轮擅自定稿。

### D8: 确认第四轮视觉基准，转入正式资源与规范规划
- 定了什么：用户接受 `round-04/color-wordmark-confirmation.png`，将其颜色关系、深暖红简单 i 方点与温和清爽的视觉表达作为后续正式制作基准。六个基础色按确认稿标注复现：正文 #292C28、纸底 #FAF8F2、表面 #EDE9E1、完成绿 #8BBDA1、进行中暖红 #F4A686、字标深暖红 #B65B42。
- 为什么：视觉方向已认可，下一步需要把生图示意转成真实可复用的素材与明确规则；不继续反复探索同一配色和方点形式。
- 用户原话：「可以啊。接下来应该要输出哪些素材资源还有规范呀？」
- 确认边界：视觉基准确认不等于字标精确曲线、最小尺寸、完整功能状态、页面/导航布局、字体选择、角色全套动作或发布物料全部定稿。日期与兔子的布局仍按用户要求暂缓。
- 制作原则：字标制作真正可缩放的矢量母版；兔子保留像素母稿与透明图，不将其机械平滑矢量化；基础色的文字/底色配对和功能派生色须按实际可读性验证。

### D9: 升级规范并完成项目改造、打包与本机重启
- 用户原话：「这份文档先彻底升级了，让它成为整个项目的设计系统的核心，必须确保信息凝练、无任何错误信息。然后再去按照你前面说的事情一个一个全部实施完成。最终应该把整个项目都改造完成，并且直接能打出一个新包，重启让我看到。」
- 定了什么：在 D8 基准上完成正式资源、核心规范、现有全部界面、发布物料与检查；新建 `codex/loppi-design-system` 分支，验证后构建签名包并本机安装重启。
- 执行边界：沿用现有侧栏、日期导航与右上兔子的职责关系；不采用未选定的顶部导航探索。保持用户数据、凭据、暂停/声源配置，不公开发布。
- 授权范围内的设计收敛：统一双竖耳图标；系统无衬线与等宽时间；纸白开放式记录、较小圆角；完成绿、进行中暖红、等待中性、注意琥珀、失败深莓红。具体数值与组件规则在核心规范中管理。
- 状态：实施和验收进展只在交付台账更新，避免在历史清单中维护第二份状态。

### D10: 产品 ICON 固定保留，与倾听动画独立
- 用户原话：「我的图标不换哦，原来那个耳朵一个折的一个直的头歪歪的，这个是产品 ICON，不换哦。」；「两个都竖直的那个是正在听录音的状态动画，和产品 ICON 是独立的不影响」。
- 定了什么：原产品 ICON 的源图、GUI 方图、平台各尺寸与 ICNS 均不改；双竖耳继续用于倾听动画。覆盖 D9 中设计师统一双竖耳图标的实施判断。
- 落实：撤回此次 ICON 替换，正式资源包复制既有 ICON，导出脚本不再写回运行时图标。其他已确认视觉和完整实施授权继续有效。

### D11: 左上角使用设计稿的圆润字标与深暖红点
- 用户再次明确：软件左上角使用设计稿里的圆润定制 logo 与红点，而非普通文本。
- 落实：常规侧栏已引用 `src/assets/brand/wordmark.svg` 的独立矢量轮廓，i 点为深暖红简单方点；紧凑侧栏复用原产品 ICON。此提醒与 D10 的 ICON 保留要求分别管理。

### D12: 颜色达标，首页模块美学未通过；同一 HTML 对照
- 用户原话：「虽然色彩上我觉得你的这次 design system 已经达标了，但是页面上具体这些模块的样式，我觉得你现在的设计怎么还那么丑啊？」；「我刚才说的是把它放在同一个 HTML 里面。」
- 定了什么：保留已确认的配色与品牌资产，重新审视首页模块构型。现有页面、资源截图和已安装0.1.15不能视为最终美学定稿。
- 本步交付：把旧版与当前版放入同一独立 HTML，统一颜色、数据和逻辑窗口，具体指出容器、比例、留白与阅读顺序的问题。用户澄清是新旧版本对照，不涉及天猫。
- 设计判断：此前主要去卡片与缩小元素，削弱旧分组却未建立新秩序；下一轮应重做概览分量、条目组成与连续阅读关系，再进行界面验收。

### D13: 回到旧版布局，先应用新字标与色彩规范
- 用户原话：「你在旧版的基础上，把 logo 换了，然后把色彩和一些关键点、色啥的都按照新的规范来搞。我们再看还要优化啥」。
- 定了什么：本轮以旧版模块构型为基底，保留概览/条目白卡、圆角、尺寸、间距与时间排法；先统一正式矢量字标、基础配色与语义标记，再共同判断后续优化。
- 落实：同一 HTML 默认展示“旧布局×新规范”；完成/留存用绿、录制/定位用暖红、普通选择中性、注意琥珀/失败深莓红。产品 ICON 和状态动画继续独立。可以切换录制/暂停/空白、1/3条、1120/760，并与原布局或上一轮方案对照。
- 边界：这是本轮审阅基底，不将上一轮开放式条目或新的模块重排视为已确认方向；生产页面的下一次调整依据本轮审阅继续收敛。

### D14: 完整 token 驱动的最终前端实施
- 用户明确要求：「设计系统应该有全套的设计 token」；「前端要整体改造好，色彩你自己看着确认全部」；「把代码里实现最终方案」。
- 本轮授权：以 D13 旧布局基底落地生产代码，建立完整分层 token 并迁移全前端；设计师收敛所有功能色，不再只改 HTML 或维持独立覆盖样式。
- 保持不变：已确认的六个基础色、定制字标、原产品 ICON 与动画分工、用户数据和录音/处理语义。完整实施、审查、打包与本机重启仍为同一交付目标。

## 张力时刻
- 初步设计判断（待与用户校验）：兔子有性格，UI 却依赖通用的灰绿底、白卡片、大圆角和低对比绿色；不应只把这一套换成另一种流行色。
- 需要共同解决的张力：一直在场又不造成被注视感；温暖有性格又不幼态；界面极简又能清楚交代录制、暂停、中断和云处理。
- 用户对第二轮的纠偏：A2 舒服但仍普通。接下来的标准应同时满足舒适性与可识别性；反复微调相似首页不足以完成品牌设计。
- 第三轮自审：像素与边注品牌细节探索后，完整主窗仍与 A2 过于接近。普通感还来自熟悉的侧栏/顶部概览/列表组织，不能仅以微调字标证明问题已解决。因此新增“当天一页”空间探索供用户判断，尚未确认更换导航或状态位置。
- 用户随后将讨论拉回其附上的像素身份板，优先确认色彩语义和字标 i 点；明确日期与兔子的关系稍后再说。后续以这次范围为准，不继续推动空间方案选择。

## 第一轮视觉假设

### 推荐制作顺序
1. 将已确认的字标与基础色做成正式母版和基础样张，同时核对现有兔子素材的身份一致性。该步骤无需先确定主界面布局。
2. 用时间线、事件阅读和常驻入口三个真实场景验证字号、空间、颜色角色与组件；日期/兔子布局在此时回到讨论。
3. 将验证后的公共规则扩展到其余页面和全部必要状态，形成完整规范与可交互样板。
4. 按最终界面制作发布截图与开源物料，连同源文件、导出与使用说明统一打包。

### 交付完成标准
- 标志为可编辑矢量；像素角色为透明原稿和可复用动作资源；所有正式资产有清楚名称、用途、尺寸与版本。
- 设计规范与实际母版、样板使用同一套颜色和尺度；关键文字颜色在实际背景可读，状态有文字/形状支持。
- 完成与进行中、主动暂停与异常、录音状态与后台处理状态均能准确区分。
- 核心界面覆盖真实内容、必要状态和支持窗口；主窗、常驻入口与发布材料具有同一身份。
- 所有未决定事项保持明确记录；不将探索图、自动生成的字体名/文案或暂定版面冒充最终资源。
