# 日期跳转与智能识别界面

日期区域按双位月份/日期预留固定宽度，左右按钮不随文字宽度变化；保留左侧较新、右侧较旧的倒序方向，点击只跳到最近有记录的日期，跨月/跨年亦成立。日历和“回到今天”保留直接选择语义。

首页记录卡片去掉左侧「粗转」「精转」「内容摘要」冗余内容类型标签；保留时间、真实声音来源、现场记录数量和右侧处理/录音状态。异常反馈不丢失。

侧栏与页面名称改为「智能识别」。两张卡片分别为：
- 事件分析：使用云端大模型对本地转录文本进行事件分析识别
- 语音识别：使用云端大模型对确认的事件进行二次精准语音识别

主页面在两张识别卡片下直接展示既有统计图与时间范围，取消“队列/统计数据”页签。每张卡片计数右侧增加“任务明细”，进入对应服务的任务二级视图，左上角返回智能识别。已有任务重试与待核对操作必须可达；返回保留主页面统计范围，不继承设置或任务页的滚动偏移。

卡片不显示常态“运行中/已暂停”描述；开关保持既有真实队列控制。开关左侧增加设置按钮，点击进入设置页“识别与整理”并定位对应项；两处标题/副标题保持一致。余额不足、未配置等必要异常提示保留。

## 执行台账

### 开发契约
- 必赢场景：固定位置连续点击日期箭头，跨过空白日期；两类识别卡片清楚呈现目的和计数，设置入口一次直达对应模块。
- 原子交付：前端、必要的既有Core只读日历投影扩展、对应检查及文档一次完成；不更改真实录音/云队列意图。
- 必须保证：无数据不跳、最早/最近边界禁用、请求失败/过期回复不造成错误跳转；日界按本地时区/DST；不新增GUI数据库读取或逐日全库扫描。已有自动定位与日期选择不回归。
- 独立加载：识别状态未就绪、失败或缺少服务快照时，已读任务与待核对仍可通过服务卡片入口打开；未知状态不伪装为关闭或零计数。
- 状态来源：Core为记录可用性唯一事实源，GUI通过既有只读IPC读取；页面/对应配置定位属于现有App导航会话状态，不持久化。
- 用户追加二级视图：复用QueueView既有局部导航状态，改为服务任务视图；统计图保留既有范围与加载所有者，优先保持同一组件实例，不引入新路由器、持久缓存或任务业务状态。主滚动容器按App页面生命周期隔离位置。
- 复用：CalendarDays/calendar_days的记录可用性语义、dayBounds、TimelineView、App.selectDate、QueueView、SettingsView、CloudServiceSettings、Switch与现有设置滚动容器。
- 允许实现：如月度CalendarDays无法确定全历史相邻日期，可在既有Core请求/只读GUI投影内增加最小相邻记录查询；遵守协议版本契约，不新增状态所有者、存储、缓存服务或重试通道。
- 明确不做：变更识别服务商、付费操作、任务调度语义、录音默认行为、Notch交互、公开release或清理共享工作区。
- 本次负责：日期按钮稳定/跳空、重复标签、智能识别名称与配置直达；保留其它并发工作。
