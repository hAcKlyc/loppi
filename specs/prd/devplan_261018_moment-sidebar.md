# 详情右侧现场记录整理

用户实测 notch 截图/重点后发现详情右侧内容混乱：不同宽度的右对齐聊天气泡、截图 OCR 零碎文字直接铺开且被裁切。统一为按原始时间正序的现场记录，重点紧凑，笔记可读，截图原图与识别文字分开操作。

## 执行台账

### 开发契约
- 必赢场景：混合重点、笔记和截图的右栏可快速扫读，识别文字默认收起、展开后可完整阅读；时间明确可回听，截图独立打开；输入区明确笔记时间与保存动作。
- 原子交付：一次前端改动与提交，无数据迁移、无协议变化。
- 必须保证：保留所有记录与原始 anchor_ms，时间正序；记录不因类型改变对齐或挤出栏宽；原图按需读取；OCR 失败/空结果不误报截图失败；笔记保存内容和时刻不变；右栏独立滚动、输入区固定。
- 明确不做：不改截图/OCR/录音后端，不引入缩略图批量加载/缓存，不改转录与说话人功能，不合并或删除用户连续重点。
- 本次负责的问题：用户截图中的展示混乱及本次修改造成的直接交互回归。
- 状态来源与生命周期：DetailDrawer 既有 moments 为 core 查询结果；anchor 为用户选择回听/拖动的位置；图片沿用 screenshot_data 按需读取；OCR 折叠采用原生 details，无持久状态。
- 复用的既有抽象：Moment、loadMoments、playFrom、showScreenshot、sendNote、wallClock、tokens.css。
- 新增架构机制：无新 store/owner/protocol/retry；允许将记录展示提取为无状态组件，现有图片加载状态可用请求中的 moment ID 提供准确反馈。
- 架构不变量：GUI 仅展示 core 返回的原始记录；不改变真实时刻、数据存在性与媒体读取边界；沿用语义 token。

### 验收与结束条件
- 混合记录统一布局，重点单行，长笔记换行，截图 OCR 默认不占正文。
- 展开识别文字可完整滚动，空/失败有准确文案；截图入口不触发回听。
- 点击时间传原 anchor；保存笔记时间与显示一致，保存失败保留草稿；窄窗口不横向溢出。
- 证据：针对性组件回归、typecheck/lint/build、浏览器/桌面视觉烟测。改变展示重跑组件与视觉；改变动作重跑动作回归。
- requirements/adversarial/final architecture 全部 PASS、验证通过即结束；主观视觉偏好仅 advisory，不扩张本批次。
