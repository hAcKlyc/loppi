# 悬浮兔子拖动与四边吸附

用户报告桌面悬浮入口不能移动，要求按住拖动并自动贴边；已明确选择松手后吸附到当前显示器最近的上、下、左、右任一边。保留单击标记重点，拖动不标记；靠边时菜单向屏内展开，保存位置。

## 执行台账

### 开发契约
- 必赢场景：按住兔子移过 7pt 后连续跟随鼠标，松手贴最近四边，下一次打开仍在该位置；四边菜单完整可用。
- 原子交付：一个 macOS GUI 修复批次，复用现有入口原生桥接、GUI 配置及动作入口。没有业务数据迁移。
- 必须保证：区分点击和拖动；快速拖动/移出兔子后仍跟随；跨屏选择落点显示器；屏幕可用区域内吸附且菜单/提示可见；拖动期间不展开菜单；结束只保存一次；顶部模式和快捷动作不回归。
- 明确不做：改变录音、转录、计费、全局快捷键、Windows 支持、更新用户凭据或权限；不扩展原兔子 PRD 的历史发布范围。
- 本次负责：当前异步 WebView 拖动启动和遗漏的取消/结束路径，以及缺失的四边吸附和边缘布局。
- 状态来源与生命周期：现有 HearEntry 原生窗口拥有鼠标手势、显示器和几何；React 只投影展示并调用既有动作；EntryRuntime.preferences 保存显示器 UUID 与归一化位置，结束写盘。
- 复用：HearEntry.updatePointer/install/layout/hitRegion、hear-entry-native、EntryRuntime.save、FloatingWidget.perform/collapse、EntryRequests。
- 新增架构机制：无新 owner/store/进程/协议；将鼠标点击与拖动判定归入已有原生事件监听，替换 WebView 异步 startDragging；扩展已有私有事件/几何以投影四边布局。只增加当前按下点和起始锚点的手势内存。
- 约束：仍是同一个 float 窗口，命中与可见区域一致；鼠标移动不发业务 IPC、不写盘；配置不进入 Core 业务库。
