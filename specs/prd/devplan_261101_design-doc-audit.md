# 设计系统文档一致性复核

用户要求重新检查整个项目的设计系统文档。以最新已确认的中性卡片、暖红「正在记录」标签、平涂时间轴及独立产品 ICON 为准，核对核心规范、组件速查、正式资源、发布简述和历史材料的边界。

## 开发契约

- 修复事实错误、过时规则与重复数值来源；正式生成素材的 UI 色彩从 `src/tokens.css` 读取。
- 保留批准的字标母版、折耳歪头 ICON 与状态兔子原字节；不修改业务状态或生产界面。
- 历史探索、截图与旧验收保留日期和事实，不冒充当前规范或当前发布验收。
- 不涉及安装、打包、发版及尚未完成的 Windows 实机门槛。
- 基线：`/tmp/loppi-design-doc-audit-before/`，为本轮开始时的工作树快照；同一文件已有的早前改动不属于本轮新增范围。
- 无新增状态、owner、协议、依赖、持久配置或运行时分支。

### 初步发现

组件速查残留未整理描边和模糊的录制卡片规则；核心规范中“单一悬停灰”与卡片/控件两种语义不符；发布生成器硬编码旧色板；英文发布文案只写 Mac；历史截图缺少与当前样板的明确区分。原生颜色解析单测的页面色期望仍为旧色值，解析源本身正确。

### 结果与验证

- 核心规范新增关键颜色角色表，区分品牌六色与完整 UI 色组、卡片/控件悬停、标签/轴段/当前时刻；补充 Windows 配置来源与首次准备/后续启动区别。组件速查同步平涂轴段、双轨保存标记、中性卡片与录制标签。
- 静态生成器从现有 token 源解析颜色；使用样张、封面、反白字标及离线 DESIGN 重建，清单88项。批准的彩色字标、产品 ICON、兔子源与受保护导出未改变。
- 发布文案覆盖电脑而非只写 Mac；旧截图与历史对照保留原貌、明确日期/提交和适用边界，不作为当前发布截图或原生验收。
- `node --test scripts/test_design_assets.mjs scripts/test_entry.mjs`：14/14通过。新检查覆盖正式色样、封面/反白派生、PNG纯色与当前 token 一致性，避免系统字体差异导致跨平台误报。
- `rustc --edition=2021 --test src-tauri/build_theme.rs` 及生成的测试程序：2/2通过；核心规范10个本地链接全部有效；使用样张与README头图已目视检查。
- 独立需求审查 PASS。故障审查发现“节点保持中性”措辞可能覆盖已留存绿节点，按真实实现明确两类节点后定向复核 PASS；最终全新架构审查 PASS。导出机制沿用现有构建器，无新增运行时机制或依赖。
- 本轮仅文档、静态导出与对应检查，未重新打包或宣称 Windows 发布门槛完成。尚未单独提交：生成物依赖此前工作树中的已确认 token/界面改动，需随整体源码一并提交，避免制造不一致的中间提交。
