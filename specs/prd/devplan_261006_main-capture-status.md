### 开发契约
- 必赢场景：时间线日期左侧与兔子状态右侧成为一个首页模块；录音的清醒兔子和暂停的趴睡兔子明显不同，通过暂停/继续/开始控制既有核心，顶部兔子保持一致；其它页无全局提醒。
- 原子交付：本次主窗控件及相应验证作为一个 delta；不宣称此前兔子 PRD 或整个0.1完成。依赖已有未提交入口实现，不能把其未验收代码混入本次独立提交。
- 必须保证：使用现有 EntryRuntime 快照和 appearance/control；不按原因文字猜状态；来源部分失败、启停、未知、空间不足和准备条件有明确表现。未知状态禁止盲目切换；请求结果不明时同 ID 确认，确认回执不提前冒充实际录制/停止。双击不重复提交，事件序号防迟到旧快照覆盖新状态。错误就地显示，不被时间线刷新清除。
- 明确不做：新录音状态机、轮询、协议、持久设置、自动重试、录制计时或实时音量波形；不改常驻入口规则，不启动长跑，不在用户原目录写测试记录。
- 状态来源与生命周期：core 为录音事实 owner，EntryRuntime 为现有 GUI 查询/请求 owner；App 订阅有序快照，并保留既有请求/反馈UI会话，不随页面切换丢失待确认ID；控件只负责展示与动作入口，既有Rabbit和CSS/可见性管理动画。
- 复用：EntrySnapshot、getEntrySnapshot、EntryRequests.send、entry_action、ServiceState结构化诊断、Rabbit清醒/等待/异常播放、manifest调色板、tokens.css、现有设置路径。
- 新增架构机制：无；只增加主窗展示组件、纯展示映射及已有请求槽实例。
- 架构不变量：不新增后台进程或状态查询链，不以控制回执/动画替代实际来源状态。
