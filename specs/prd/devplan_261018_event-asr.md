# 事件级精转与增量复用

需求源：[讨论稿](_drafts/event-asr-redesign.md)。用户已明确「确认需求，核实技术细节，然后开发测试直到完成」，授权本次完整实现与验证；以下细化遵循已确认的稳定后精转、上传空档压缩、完成音频不重复提交三个约束。

## 执行台账

### 开发契约
- 原子交付：输入计划/映射、稳定调度、结果复用与当前事件投影、历史兼容、身份与清理兼容、界面状态、测试/审查/构建一次完成。
- 必赢场景：同一事件每来源尽量一个请求；确认无语音的 >3s 空档在上传副本压至 1s；真实时间和原声不变；自然续接仅补新增，旧句段 ID/人工纠错/声纹保留。
- 稳定：以事件末尾之后 15min 的已知语音/分析证据为观察范围；事件已被后续独立事件分隔可收口；相关 pending/processing 分析与拟合阻止提前提交，明确失败显示原有异常不伪装静音。手动精转立即规划；静默阈值来自末尾真实时间，不在每轮规划重新计时。
- 外部事实：官方当前任务提交文档 task-submission-http-1（DocumentID 2606791）规定 Ogg/WAV/MP3、512MB、5h；未列单独 Base64 上限。保留已实机使用的 10MB 直传边界，本地按实际编码时长最多 20min 分批并检查字节上限，不承诺达到供应商最大文件规模，也不新增对象存储。压缩后的 20min 不是事件墙钟上限。
- 空档：仅完整被 discard_digital_silence_v1 / discard_no_speech_v2 记录覆盖且没有 media_gaps/清理的区间允许压缩；其他长缺口隔开请求。输入计划在排队时固定，保留真实样本范围与编码映射；旧任务无计划仍按旧线性映射完成查询，不伪造历史事实。
- 映射：保存完整对齐的词级信息用于跨接缝拆句；不可定位的请求整体失败、无部分发布，不自动新建付费请求。旧成功片段不因另一任务失败消失。显式重试沿既有远端查询优先语义。
- 复用：Core 保存事件对物理识别任务的有效范围引用；覆盖按输入范围而非返回文字计算；已完成（含空结果）、有效失败/待处理/在途均不因重新规划自动重复提交。明确重新精转才建立新轮次。
- 边界编辑：现有完整句段仍落在新事件内则复用；跨人工裁剪边界不猜字时刻、不自动重转，保留原事实并显示部分结果供显式重转。拆分/合并复用原任务有效范围，不能因新事件 ID 重新付费。
- 清理：raw_audio 保留已完成文字与已有向量，all_data 遵循原有墓碑；输入/事件引用不能复活清理内容。显式重转沿现有旧稿退出当前投影及人工修正可验证恢复语义。
- 声纹：既有 CampPlus/人物库、人工优先和质量门槛不变；当前事件引用参与身份/匿名组投影，不以云编号统一为验收条件。
- 新增机制仅限 Core 的不可变 ASR 输入计划与事件任务引用/规划版本；不新增进程、队列、供应商、重试系统、声纹模型或对象存储。统计页不加新的图表，计费改用真实编码时长。
- 复用：events::queue_asr / publish_asr / task_current、cloud::submit_audio / query_audio、media::OpusBlock、knowledge 当前投影/匹配、cleanup 事务、storage::migrate、usage::Recorder。

### 验收与结束条件
- Rust 定向回归覆盖：压缩/真实缺口、接缝文字时间、稳定与积压、增量覆盖、空结果/失败不循环、重启同远端、原声/全部清理、裁剪/拆合/人工修改/身份保持、旧数据库兼容。
- 真实供应商用合成非私人语音对照验证上传/接缝/时间/编码时长，禁止批量重转用户历史录音。确定性映射误差 ≤20ms；真实语音定位以人工可听词边界偏差 ≤500ms 且无跨长空档首字拉长为门槛。
- cargo check/test、前端 typecheck/lint/build、运行时隔离 smoke、macOS 构建；受影响修复后重跑相关检查。
- cross-review：requirements/adversarial 新上下文并行，修复后 fresh architecture；全部 PASS 后提交。未完成真实供应商门槛不能标 implemented。
