## 当前结论

0.1 的产品范围已收敛为 macOS 上的持续双路声音记录、本地实时粗转、云端事件拟合与整场精转、全局人物声纹库、主动截图与时刻动作、连续时间线、搜索/导出、两种清理以及完整 CLI。PRD 决定用户行为；RFC 提供待验证的实现方案。两份文档均不能代替真实录音、功耗、声纹质量或云服务适配测试。

## 本轮纠正

| 原有问题 | 当前落点 |
|---|---|
| 把 24 小时误写成原声音频保留期限 | PRD 明确电脑可用时持续记录；经保留策略留下的人声持续保存，空间满暂停 |
| 把语音分段、人物身份、跨事件声纹匹配混为一层 | 本场 speaker 编号、全局 Person 和声音样例分别建模，先分段后本机匹配 |
| 让云端 ASR 供应商是否返回 speaker 标签决定产品能力 | 产品要求最终文字稿有分段；本机或经验证的云端能力均可完成 |
| 用户命名说话人却不能在其他事件复用 | 全局人物列表、自动匹配、人工创建/选择/纠错和历史补匹配纳入首版 |
| 精转文字识别错误后缺少明确的人工修正范围 | 首版支持逐句纠错，保留原识别结果与时间锚点；显示、搜索、导出使用修正文字，重转不静默覆盖 |
| 人工补建事件、改边界缺少精转后续 | 手动事件直达 ASR 待办；边界变化更新当前精转范围并拦截旧任务 |
| 候选切分参数被误当真实事件边界 | “约 15 分钟无文本”仅是可调候选策略，会议按完整活动成块 |
| “清除原始音频”与全局声纹库关系不明 | 清原声保留已提取特征并明确预览；清全部数据按真实范围删除样例和归属 |
| RFC 仍使用云端默认关闭、预算拦截、Mark 保留与 CLI 只读假设 | RFC 按新版 PRD 重写；完整 CLI 和两条独立云队列成为技术主线 |
| 早期 Windows 方案与本版 Mac 验收混在一起 | 0.1 只验收 macOS，Windows 留到后续平台工作 |

## 尚待工程验证

- 在目标 Mac 上测语音漏检、句首保留、实时粗转延迟、双路回声与睡眠/设备切换恢复。
- 验证 LLM 候选拟合的活动边界、云端 ASR 整场时间定位，以及说话人分段在多人、重叠与中英混说场景的质量。
- 用跨麦克风、耳机、远场和系统声道的同人/异人样本测全局声纹误认与漏认；阈值和样例质量门槛由验证冻结。
- 验证精转重跑、边界修订和删除时，人工逐句纠错的时间定位、待核对状态以及界面/CLI/搜索/导出一致性。
- 确认模型与原生扩展的许可、打包、下载、升级和本机功耗；选定云端供应商后核实鉴权、时长、时间戳、查询/重试与计费。
- 验证音频占用上限、磁盘安全线、清理共享封块、人物样例失效、迟到任务、崩溃恢复与完整 CLI 的一致性。

## 技术架构复核补充

本次逐段对照最新版 PRD 与 MyAgents 录音/本地推理代码，并核对 Apple、SQLite、sherpa-onnx、火山引擎的一手资料。已直接修订 RFC，重点是以下原先不足以指导实现的环节：

客户端形态已明确为首版选型：Tauri 2 + React/TypeScript/Vite 主界面，独立 Rust 常驻核心与 Rust CLI，本地推理 worker，必要的 AppKit/ServiceManagement/ScreenCaptureKit/Vision/Keychain 桥接；SQLite、短 Opus 封块与本机模型包作为本地数据/推理基础。此处早期审查曾建议原生 `NSPanel` 内容；Batch 5 已改用独立 Tauri 透明窗口，原因、私有 API 使用及待验证门槛记录在 RFC。MyAgents 的 Node 服务、单 Record 领域模型和悬浮聊天业务不属于 hear 的依赖。常驻核心在安装版取得采集权限和登录恢复能力须有实测证据。

| 优先级 | 原先的技术缺口 | RFC 当前处理 |
|---|---|---|
| 阻断 | 只说有界缓冲和保守保存，没有证明声音判定慢、写盘失败或崩溃时原声仍可找回 | 增加待判定短封块、持久清单/游标、恢复扫描、故障来源暂停与真实缺口报告；容量计入临时副本 |
| 阻断 | “关闭窗口仍录、完全退出停、登录恢复、CLI 查询不启动录音”缺少进程与状态机 | 采用单写入核心 + 本机 IPC 的原型方向，分离持久启用意图与本次登录会话的完全退出标记；用安装版验证 launch agent、权限和启动路径 |
| 阻断 | 两路样本序号、墙钟日期、跨设备/睡眠/重启的时间关系不够明确 | 为每个采集段保存来源、代次、单调时间锚点、UTC 映射及质量；日期作为视图，时间不可靠时不硬合并 |
| 高 | 长会议多请求精转可能把相对时间或局部 speaker 编号误当整场事实 | 增加不可变请求清单、分段时间映射、请求内 speaker 编号作用域，以及局部成功不冒充整场完成 |
| 高 | 候选封口、模型输入分窗可能把一场有长间隙的会议切成多场 | 候选仅推进处理游标；相邻上下文、暂定事件与稳定发布水位共同决定用户层大块，窗口切分不直接发布事件 |
| 高 | 清理后已打开的媒体句柄、缓存或长数据库快照可能继续泄露所选区间 | 媒体由核心按范围提供并在清理时撤销/逐块重检；日志与临时外发文件也纳入生命周期 |
| 高 | 云端任务只有“持久队列”描述，无法确定依赖、重试与迟到结果如何裁决 | 持久任务图记录输入版本、远端任务 ID、尝试代次和结果状态；手动精转可绕过 LLM 判断但仍受 ASR 队列控制 |
| 事实修正 | 将火山“极速版”一概写成仅支持 `audio.url` | 分开列出两个官方 API 文档的上传形式与限制，最终只按选定适配器做真实验证 |

另修正 PRD 验收表的一处旧文案：悬浮主按钮单击是标记重点，截屏位于悬停菜单。后续用户已明确 0.1 通过 macOS `.dmg` 直接分发、暂不走 Mac App Store，hear 源码现阶段闭源；未来是否开源及许可证未定。RFC 已按直接分发补齐签名、公证和安装版验证，并把闭源复用 MyAgents 代码前的权利与许可核查列为工程门槛。其余待验证的是具体 Mac、后台权限、供应商适配与质量/资源门槛。

以上是技术与验收工作，不要求用户逐项拍板参数。若后续出现真正改变用户可见行为的产品分歧，再回到 PRD 收敛。
