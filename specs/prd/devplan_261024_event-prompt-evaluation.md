# 精简事件 Prompt 的真实样本评估

用户接受 Schema→通用规则→示例的候选方向，要求至少 10 个长短不同的真实事件，多轮测试至结构与质量均通过。上一轮明确先不改正式 prompt；本轮仅改隔离评测工具和候选文本，不替换 FIT_SYSTEM、不安装、不写活跃库。

## 开发契约

- 原子交付：12 个冻结真实样本、输出前写定的事实与禁错标准、候选 prompt/schema、所有迭代记录、最终两轮全量复验、质量人工审核、可复用隔离回放工具、独立 review 与提交。
- 必须保证：生产 planner/input/model/normalize/publish 链路逐窗运行；每窗一次模型调用，模型仍为 deepseek-flash；low 为生产基线，显式 high 为隔离对照且分开验收；不额外生成摘要、不为通过而手工修补输出。模型原始响应、输入、实际保存、时延、用量均留存。失败不擦除、不选择性展示。
- 样本：12 个真实独立选定时间段，至少 3 个长于 15 分钟，短中长兼顾，含噪声/混合内容/真实自我纠正。旧自动标题只是选样线索，不作为金标准；原粗转为语义依据。另有既有合成纠正样本时标为补充，不计入 12。
- 验收：最终固定 prompt 连续两轮全部 12 样本（从空事件库重跑）结构 100% 通过、必保事实 100% 可查、无重大不实/状态颠倒/错误删除，跨窗未变更条目保留，摘要覆盖对应活动主线。允许合理措辞/分组差异，不强求旧版活动数。每项必保事实由证据片段和语义人工核对，而非只搜关键词。约 500 字非硬限，记录偏长和冗余但严重影响可读性时判不通过。
- 稳定的含义：只声明固定 12 样本两轮通过，不宣称普遍零失败。两个保留样本首次在候选冻结后运行；若发现问题进入开发集并诚实撤销 holdout 标签，不伪称独立泛化。
- 不做：生产架构/协议/存储变动、新模型、新调用链、新队列/恢复器、ASR修复、说话人推断、外部事实核验、重放完整历史替代窗口续接。不可凭含糊粗转补出具体人名/型号/金额。
- Owner：冻结 coarse_segments 是事实依据；单次隔离 replay.sqlite 的 named_events 是输出权威；评测仅观察，不写活跃数据库。复用 real_understanding_replay、Store、refresh_candidates、take_task_fair、llm_input、cloud::chat、publish_fit_with_input、recover_tasks。
- 新机制：仅测试编译入口允许显式指定候选 prompt、1 窗短样本、记录耗时；默认使用生产 60 秒 deadline；显式 120 秒仅用于分离质量评估，不得据此声称生产时限通过。Python 离线评估 schema/引用/落库一致性，无生产 owner。
