# hear：安静倾听的兔子入口

## 执行须知（给空 session 的你）

先读[现有 PRD](prd_0.1.md)、[架构](../ARCHITECTURE.md)、[设计规则](../DESIGN.md)及[本功能 RFC](tech_rfc_0.1_quiet-rabbit-entry.md)。用户于 2026-10-01 明确确认「需求和设计素材可以了」；本稿进入可开发状态。用户已确认需求与方案并授权完整开发；按下方执行台账推进，原生验收须记录实际证据。

macOS 两种入口、真实状态与动作、设置、原生窗口及验收是一次原子交付；开发批次只组织实现、验证、review 和 commit，全部完成后统一上线。引用以文件及符号定位。焦点、截图避让、全屏和屏幕变化必须通过签名应用实测，HTML 模拟不能代替。

## 1. 产品目标与范围

hear 在电脑可用时持续记录，入口应安静陪伴。用户指出录制时间、波形等「都是在为用户创造焦虑」；新的表达是一只彩色像素兔子，「它的存在就代表着当前正在运行的含义」。主动暂停则「兔子睡着，入口仍在」。

用户一整天工作时不需要管理录音仪表盘；需要留下某个时刻时，展开入口完成截图、重点或评论，立即回到工作。正常时低注意力，真实停止时不能误报健康。

本 PRD 一起交付 macOS 顶部入口和悬浮兔子、模式设置及配套 B4 角色动画 / I4 应用图标替换。Windows 仅记录「只提供悬浮兔子」的产品规则，用户已确认不包含 Windows 客户端适配。沿用现有首次启用、权限、睡眠、退出、数据保留及云端规则；不扩展采集范围，也不隐藏系统权限提示。

不增加快捷功能、自动截图、区域截图、角色养成或主题系统，不改变时间线与 OCR 的业务能力。

## 2. 入口与屏幕规则

以下默认细节由 Agent 按用户「不需要的你自己决策保持整体逻辑一致性」的授权收敛：

| 项目 | 规则与理由 |
| --- | --- |
| Mac 默认模式 | 顶部入口，设置中可切为悬浮兔子；记住选择，切换不改变录音 |
| 有物理刘海 | 收起兔子默认在刘海右侧，不再增加左右切换设置；避免为同一功能增加偏好项 |
| 无物理刘海 | 同一顶部模式，兔子收起时在屏幕顶部中央，展开为同一面板；不绘制假的硬件刘海，不自动改掉用户选择的模式 |
| 多显示器 | 全局仅一个入口。顶部模式固定在系统配置的主显示器，按该屏有无刘海适配；不随键盘焦点或鼠标迁移 |
| 悬浮位置 | 沿用首次右下角位置，允许拖到任意显示器，记住位置；模式切换后可回到该位置 |
| 屏幕变化 | 顶部入口随主显示器变化重新定位；悬浮所在屏消失则回主屏可见区域。缩放变化后夹紧位置，保证兔子和向上菜单可见 |
| 全屏与工作区 | 保留收起入口，主动 hover 才展开；切换工作区/全屏时先收起。评论草稿保留，不因显示变化提交或丢弃 |
| 设置 | 主窗口设置提供「顶部 / 悬浮兔子」模式选择；不增加动画强度、兔子左右、全屏行为等开关 |

选择无刘海顶部入口，是为了保持用户要求的 Mac 默认体验，并覆盖最初提出的「在顶部」场景；两种入口已经足够，不再把无刘海设备做成第三套交互。

## 3. 两种入口的交互

### 3.1 顶部 notch

收起时只有一只兔子，原地偶尔眨眼或轻微动耳朵；不随音量变化，不显示时长、波形、录制灯或持续录制文案。无刘海屏沿用同一角色与动效。

用户已接受「薄荷团子 B4 好奇折耳」角色与「I4 折耳近景」APP 图标素材：薄荷绿、奶油口鼻与胸腹、大脸紧凑身体，保留一立一折的耳朵。[B4 / I4 素材包](../../design/rabbit/b4-i4-v1/index.html)是当前视觉基准；工程导出和原生展示仍须验收。APP 图标母图必须正方形、满幅背景、无边框，不预制圆角、外边距、阴影或底座；不同用途的圆角矩形及其他裁切由同一母图派生。

常驻只用倾听呼吸和睡眠待机两个循环。hover 歪头、保存成功点头、实际恢复后小伸展、实际暂停后合眼均只播放一次；睡眠中的 hover / 保存回应保持闭眼，不表示恢复采集。抬爪是已备素材，不新增触发入口或随机定时彩蛋。动作不等待播放结束才收起面板。隐藏、减少动态效果和素材加载失败时停止非必要动画，使用对应静态姿态；不能因资源失败显示错误的采集状态。

顶部从收起兔子进入功能面板时，黑色表面在约220ms内向两侧、向下平滑展开，内容轻柔淡入。顶边始终贴屏幕，过渡中的原兔子位置仍可命中，透明区域仍穿透；截图、重点、评论提交及取消即时收起，评论输入立即获得焦点。减少动态效果时直接呈现最终形态。

hover 展开后，顶部小兔子消失，面板左侧是兔子，右侧依次为 **截图、重点、评论**。同一时刻只显示一只兔子。hover 左侧兔子出现遮罩：倾听时为暂停图标，睡眠时为播放图标，点击请求暂停或继续；右侧不增加暂停按钮。

鼠标与键盘焦点都离开后，延迟 200 ms 收起普通面板。键盘聚焦提供等价的遮罩和动作；展开时焦点不能留在隐藏的顶部兔子上。

| 动作 | 行为 |
| --- | --- |
| 截图 | 点击即收起，沿用现有主动整屏截图并保存时刻记录 |
| 重点 | 点击即收起，在点击时刻保存重点 |
| 评论 | 面板替换为自动聚焦的输入框；有效回车发起提交后即收起 |

用户的澄清是：「你唤起 notch 就是为了去点击。」因此动作后只收起展开内容，**小兔子仍常驻**。收起后，指针仍停在当前入口上时不因残留 hover 自动重开；操作按钮区域已经消失，不得继续作为抑制区域。重新移入兔子、显式点击或键盘聚焦均稳定展开，重复展开不切换为收起。轻提示出现与消失不重新锁定入口。

收起与保存结果分开：核心确认保存后，在入口附近短暂提示一次；不弹出主窗口、不自动重开面板。失败也用简短反馈说明，保留必要的重试内容。暂停时三个动作仍可用，不擅自唤醒录音。

### 3.2 notch 评论与草稿

- 输入框替换兔子与动作区，立即可输入。支持长文本自动换行，内容区超过三行后内部滚动；不让整个面板无限长。
- 普通 Enter 提交，Shift+Enter 换行；中文输入法组合期间 Enter 只确认候选词。空白不提交，长度沿用核心最多 5,000 个 Unicode 字符的校验，不显示常驻字数计数。
- 评论锚定首次点击评论的真实时刻，不改成提交时间。鼠标离开不收起输入框；Esc、点击「取消」或点击外部收起，保留本次 GUI 会话的一份草稿及原时刻。取消放在保存按钮左侧，不发起保存；已在途请求仍遵循原结果确认规则。
- 再次点击评论恢复草稿。清空文字后离开视为取消；下一次进入新评论使用新时刻。保存成功才清空，退出 GUI 不跨会话保存未提交草稿。
- 提交时先收起，明确失败后轻提示；用户再次进入评论可看到原文并重试，不强制抢回输入焦点。模式切换、屏幕变化不清空草稿；这份草稿仍属于 notch，悬浮评论继续沿用主窗口流程。

### 3.3 悬浮兔子

兔子形象本身就是入口，不绘制圆球外壳。沿用原悬浮球代码逻辑和顺序：

| 操作 | 行为 |
| --- | --- |
| hover / 键盘聚焦 | 菜单向上展开；鼠标与焦点都离开后收起 |
| 菜单从上到下 | 暂停/继续/开始、评论、截屏；兔子位于下方 |
| 单击兔子 | 标记重点 |
| 拖动兔子 | 移动位置，不同时触发重点；保留现有 7px 拖动判断 |
| 评论 | 打开主窗口原评论入口，沿用 `show_main` 与 `hear-open-comment` |

只优化角色、菜单间距、材质与 hover 反馈，不套用 notch 的点击暂停或就地评论。透明窗口的空白区域不能阻挡其他应用，向上菜单须在屏幕范围内。

## 4. 共用状态与反馈

两种入口使用同一状态映射。姿态表达实际采集，界面的展开、收起和保存反馈不改变录音状态。

| 实际状态 | 兔子表现与操作 |
| --- | --- |
| 至少启用一路，且所有已启用来源正常采集 | 清醒、耳朵立起、低频微动；有声和静音相同，提供暂停 |
| 主动暂停且实际来源已停止 | 闭眼、耳朵放松、安静睡觉；提供继续，入口保留 |
| 尚未启用 | 休息姿态，展开提供「开始」，沿用首次设置检查 |
| 正在启动/停止，或状态暂不可得 | 清醒等待、停止正常微动；不提前宣称成功，不无限沿用旧健康状态 |
| 部分已启用来源不可用 | 一只耳朵放低，展开说明缺失来源；其他来源继续，可暂停 |
| 异常全部停止 / 容量暂停 | 清醒垂耳、小静态提示，展开显示原因与处理入口；不画成主动睡眠 |
| 空间预警但仍可采集 | 保持倾听，展开说明空间情况；不显示已经停止的姿态 |

用户主动关闭一路不算故障。云端处理失败、没有文字、没有人声都不等于停止。`capture_state = recording` 可能只有一路采集，必须同时检查启用和实际采集字段。

暂停要等真实来源停止才睡觉，继续要等来源实际恢复才倾听。容量停止优先显示容量原因，释放空间后仍由用户继续；不由 UI 自动唤醒。详细异常原因在展开时解释，复用主窗口现有处理入口，不增加第四个常规按钮。

正常动效只用低频装饰，减少动态效果时静态姿态仍可识别；隐藏时暂停动画。成功/失败提示短暂、无声音、无闪烁。异常主动提醒按第 6 节执行，其余状态不反复弹出提醒。

## 5. 实现边界与失败语义

保留 Tauri 2 + React 与现有 macOS 原生桥接；`hear-core` 仍是采集和业务数据唯一 owner。两种形态复用状态读取与动作服务，不建立独立进程、HTTP 接口、采集数据库、客户端持久队列或另一个评论对象。旧悬浮球视觉由兔子替换，不同时保留两个常驻入口。

模式、悬浮位置由 GUI 宿主保存到本机应用配置，缺失或损坏时回到默认且可操作。草稿、当前请求与展开状态仅存当前 GUI 会话，模式切换不销毁。只有模式和位置新增持久偏好，不迁移已有录音与时刻数据。

复用 `ServiceState`、`Pause`/`Resume`/`Start`、`AddMoment`、`CaptureScreenshot` 及现有时刻刷新事件。正常状态沿用现有查询节奏，动作后及时刷新，不用动画驱动新轮询；来源切换和核心不可达不解析自由文本原因作为稳定状态码。

允许在现有本机协议中补充最小的结构化采集诊断与截图排除窗口参数，支持真实状态区分和控件避让；不改变通信形态或状态 owner。协议变化须同步 GUI / core / CLI 并按既有版本检查处理。具体字段及兼容责任见 RFC，不新增业务表、持久任务或后台录屏服务。

同一保存动作禁止连点重复提交。确认超时不等于确定失败：当前会话保留该动作的稳定 ID、原内容与修订，通过现有 `send_from_with_id` 和核心回执确认/重试，不以新 ID 自动再提交。结果未确认时重试沿用原内容；明确失败后可编辑，并作为新动作提交。确认前保留草稿，结果不明的内容不被静默清空；退出 GUI 不承诺自动补交。保存操作不能长期锁住暂停能力。

截图沿用 `moments::capture` 的鼠标所在显示器整屏语义，不改为区域选择或全屏拼接。拍摄前排除 hear 入口、面板和反馈；如需临时隐藏窗口，拍摄结束即恢复，这是截图措施，不是动作后的入口消失效果。成功与失败路径均须释放隐藏状态。

原生层负责刘海安全区域、屏幕几何、窗口层级、焦点及命中范围。hover 不抢前台输入，点击评论才获取键盘焦点；提交后回到原前台应用，点击外部则尊重用户新选中的应用，不反向抢焦点。若真实原生能力无法满足，应回到架构取舍，不以 HTML 效果替代交付。

## 6. 异常提醒规则

用户已确认：异常导致无法继续倾听时，**异常姿态＋轻提醒一次，问题未变不重复**。

- 权限、设备或容量问题导致已启用的来源全部停止时，兔子清醒垂耳，入口附近轻提示一次；不弹主窗口、不抢焦点、无声音。展开查看原因与处理方法。
- 同一持续异常期间，轮询、模式切换、自动重试和原因文本变化都不重复提示。确认正常恢复后再发生停止，视为新的异常；恢复本身不弹出「正在记录」。
- GUI 启动时已经存在的问题只呈现异常姿态，避免每次打开应用补弹同一提醒；在当前会话内观察到的异常停止才主动提示。不为去重新增持久状态。
- 主动暂停、关闭所有来源及短暂启动/停止切换不触发异常提醒。部分来源缺失先通过姿态与展开说明表达；状态不可得时不捏造已停止事实。

这个取舍保留日常安静，也避免用户长时间没发现漏记。提醒去重由同一入口状态映射管理，两种形态共用，核心仍裁决采集事实。

## 7. 验收与证据

| 验收场景 | 通过标准 |
| --- | --- |
| 顶部与悬浮 | 主窗品牌标识使用 I4 APP icon；悬浮菜单字号 15px、贴近兔子；Mac 首次顶部、切换可记忆；有/无刘海按规则布局，只有一个入口；悬浮保留点击、拖动、向上菜单顺序 |
| 正常与暂停 | 无时间、波形、录制灯和正常录制文案；单只兔子；真实暂停后睡眠、恢复后倾听，异常不伪装正常或主动暂停 |
| 异常提醒 | 当前会话发生异常全部停止时轻提醒一次；持续故障、轮询和切模式不重复，启动已有故障不补弹，正常恢复不弹录制提示 |
| notch 快捷操作 | 展开顶部兔子消失、左兔右三按钮；截图/重点点击收起，评论有效提交收起，残留 hover 不重开；真实保存后反馈与时间线结果一致 |
| 评论 | 自动焦点、长文可编辑、中文 IME 不误交、空白不提交、失败不丢文；关闭/重开/切换后草稿与原时刻正确 |
| 截图与可靠性 | 截图不包含 hear 控件；失败恢复入口；重复输入、回复丢失与同 ID 重试不产生重复记录，保存不锁死暂停 |
| 原生使用 | 全屏与工作区、拔插与缩放后入口可见；透明空白不挡点击，hover 不抢焦点，评论输入及焦点释放正确 |
| 视觉资源 | B4 / I4 识别一致，常驻仅两种低频循环；睡眠回应不唤醒，动作不延迟收起；隐藏/减少动态效果停动画；方形源图完整，实际应用图标和裁切无多重圆角、边框或底座 |
