# hear 0.1 视觉与交互设计系统

状态：开发中。适用范围：macOS 客户端主窗口、事件详情、悬浮球、弹窗和反馈。设计规范在这里，实际可调数值以 [`src/tokens.css`](../src/tokens.css) 为唯一来源；组件规则位于 [`src/App.css`](../src/App.css)。

## 设计目标

hear 在后台工作，界面只需帮助用户回答三件事：**现在是否正在记录、今天发生了什么、这段素材能如何使用**。主界面安静、清楚，复杂处理状态在需要时出现。避免用标题、副标题或长段提示解释数据结构和技术架构；时间、来源、播放、文字与现场动作本身承担表达。

视觉采用暖白底、深绿色操作色、克制的灰绿中性色。绿色标识当前可操作与命名事件，暖色留给重点/截图、容量提醒和错误。颜色不能成为状态的唯一信号，状态同时有文字或图标。优先稳定的布局、明确的反馈与内容可读性，而非装饰性阴影或密集卡片。

## 信息架构与布局

| 区域 | 内容与行为 | 关键约束 |
| --- | --- | --- |
| 左侧导航 | 时间线、处理队列、人物库、设置；底部录制状态 | 固定宽度来自 `--layout-sidebar-width`。0.1 的界面不展示搜索入口，CLI 与核心搜索继续提供。 |
| 时间线 | 日历入口、居中的选中日期与两侧相邻日期、当天声音/事件分布、倒序日程 | 一次只查看一个自然日；日期与日程倒序。时间轨道表示真实时刻，命名事件只是其上的区间。未整理素材仍可见。 |
| 事件详情 | 覆盖约四分之三以上窗口的抽屉；上方播放器，左侧文字/音频信息，右侧现场笔记 | 文本转录与音频信息仅两个 tab。句段在事件内按时间正序；笔记、重点、截图显示原始时刻。 |
| 悬浮球 | 常驻录制反馈与重点入口；展开菜单向上依次截屏、评论、暂停/继续 | 不加入其它快捷项。关闭主窗口仍可使用；触发动作要有即时反馈。 |
| 弹窗 | 新建/编辑事件、导出、清理、轻量纠错 | 只问完成当前任务必需的信息。清理默认为“清除原始音频”；“清除全部数据”显示额外确认。 |

主窗口的详情抽屉宽度由 `--layout-drawer-width` 控制；小窗口可退化为上下结构，不能把文字压成难读的窄列。内容最大宽度由 `--layout-content-max` 控制。笔记发送区在屏幕右下为悬浮球留出 `--layout-floating-safe-area`，按钮仍能直接点击。时间、说话人、转录正文、动作的视觉顺序应与阅读顺序一致。

## Token 体系

### 命名和层级

全部 token 定义在 `:root`。组件只引用语义 token，不直接写色值；字号、圆角、阴影、动效、层级和常用间距也引用 token。`--color-*` 描述用途，`--type-*` 描述字号层级，`--space-*` 表示间距阶梯。后续若加入深色主题或调整品牌色，在 token 层覆盖，不在每个组件里搜索替换。

| 类别 | 核心 token | 用法 |
| --- | --- | --- |
| 底色与表面 | `--color-canvas`, `--color-surface`, `--color-sidebar`, `--color-surface-subtle/hover/selected` | 页面、卡片、导航、悬停与选择层级。 |
| 文字 | `--color-text`, `--color-text-strong`, `--color-text-secondary`, `--color-text-muted`, `--color-text-faint` | 正文、强调、说明与非关键装饰。可操作文字不能只使用 faint。 |
| 边界 | `--color-border`, `--color-border-subtle/strong/active` | 默认分隔、安静分隔、强分隔和选中边界。 |
| 品牌/状态 | `--color-brand`, `--color-brand-hover/accent/soft/border`, `--color-positive`, `--color-warning-*`, `--color-danger-*` | 主动作、事件、录制成功、容量提醒与破坏性动作。重点、截图、评论各有专用色。 |
| 字体 | `--font-ui`, `--type-micro` 至 `--type-display`, `--weight-*`, `--tracking-*`, `--leading-*` | 使用 macOS 系统字体；正文以 `--type-body` 为基准，12px 以下只用于附属标识。 |
| 节奏 | `--space-1` 至 `--space-14` | 2–64px 的间距阶梯；重复出现的组件内外边距从这里选。 |
| 形状 | `--radius-xs/sm/control/md/lg/xl/pill` | 表单/按钮、卡片、抽屉内面板、药丸。圆形头像和播放钮可用几何值 `50%`。 |
| 深度 | `--shadow-nav/card/card-hover/popover/control/drawer/floating/modal` | 仅为层级变化提供阴影；普通内容不额外叠阴影。 |
| 交互 | `--color-focus`, `--ring-focus`, `--motion-fast/standard`, `--ease-standard` | 键盘焦点、输入焦点、菜单/控件过渡。系统减少动态效果时关闭非必要过渡。 |
| 层级/尺寸 | `--layer-*`, `--layout-*` | 弹层层级与主布局几何。时间轨道、图标等固有尺寸可留在组件。 |

### 色彩和可读性

- 大段正文用 `--color-text` 或 `--color-text-strong`；辅助文字用 `--color-text-secondary`。`--color-text-muted` 在白底上目标至少达到普通文字约 4.5:1 的对比度。`--color-text-faint` 仅用于不可操作、无需细读的装饰性刻度或空状态陪衬。
- 选中/正在记录不能仅靠绿色圆点表达；按钮文字、状态文案与界面结构也要给出结果。错误使用危险色，但必须说明下一步如何重试。
- 原声音频、粗转、精转、人工修正要有明确来源/状态。说话人显示“说话人 1/2…”或已命名人物，不暴露任务 UUID、声纹特征或内部状态码。
- 页面始终使用浅色主题。深色主题尚非 0.1 范围；后续通过语义 token 覆盖实现。

## 组件规则

### 时间线

选中日期是唯一强视觉锚点，邻日只是轻量导航。时间轨道与日程共享同一自然日；轨道保留声音和缺口位置，列表按最新在上展示。卡片优先显示时间、标题/未整理、来源与处理状态，避免再写解释性副标题。未整理块中的手动精转只标注其实际选中来源和时间区间，不把局部精转写成整块完成。事件点击打开详情，编辑边界后回到新的时间范围。

### 播放与转录

播放器放在详情顶部，播放按钮、当前位置、来源切换保持同一区域。5 秒分块的实现不显露给用户；拖动和点击句段应定位到真实时刻。精转句段优先，未覆盖部分可以显示本地粗转，来源标签必须清晰；命名人物还要区分自动匹配和人工确认。人工修正的文字作为显示、搜索和导出的有效版本；原识别结果仍可查看。句段操作跟随句段本身，不用长段操作说明占据正文。

未整理块的“选择范围精转”进入音频信息页，直接选择真实起止时间与可用声源；提交只为所选局部创建 ASR 待办，不把整块改写为已精转。已命名事件仍按整场精转。

### 现场笔记

右侧使用类似对话流的时刻记录：重点、评论、截图按原始时间排列。输入框默认锚定当前播放时刻或事件起点，发送后即刻出现在流中。截图可查看本地图片和 OCR 状态。这个区域不自动生成摘要，也不将现场动作伪装成转录内容。

### 人物与队列

说话人入口允许选已有全局人物或输入新名字；新建并绑定应是一次可恢复的用户动作。未识别身份用会话内可读序号。队列分开显示 LLM 和 ASR 的配置、暂停与失败状态；本地录制状态不被云队列状态覆盖。失败动作提供明确的重试/继续入口，不自动吞掉错误。

## 状态、反馈与操作成本

主状态只有“正在记录 / 已暂停 / 未开始”等用户可辨认的结果；权限、模型、空间与云处理细节放到设置或队列。等待中的操作显示禁用和进度/反馈，完成后让列表与详情同步。表单错误就地说明原因；版本冲突应刷新数据并允许用户重试，不能留下半创建的人物或误称操作成功。破坏性清理先预览范围和影响，再执行确认。

悬浮球的菜单默认隐去，鼠标悬停或键盘聚焦出现；按钮具备可访问名称和清晰焦点。收起时其原生窗口只占可见圆钮，展开时向上扩展，不能让透明区域截获主窗口点击。可操作小字与图标要有足够命中区。减少动态效果选项下去掉非必要动画。

## 维护与验收

1. 新增视觉值先判断是否已有语义 token；确需新值时，在 `tokens.css` 增加并在这里说明用途。组件 CSS 不新增裸色值、孤立字号、随机圆角或未经命名的阴影。时间轴比例、图标宽高、1px 边框等几何值可在组件保留。
2. 调整 token 后检查时间线、详情、悬浮球、队列、人物与设置的实际窗口，不只看一张静态图。特别检查长句、多说话人、空状态、云失败、清理预览和小窗口。
3. 代码门禁为前端类型检查、格式检查和构建；视觉门禁为 Codex computer use 在签名版 macOS 窗口中的任务验收。检查文字层级、对比度、焦点、反馈、抽屉与悬浮菜单是否仍合乎上述规则。
