## 1. 设计目标与审美原则

Hear 在后台工作，界面帮助用户回答三件事：**现在是否正在记录、今天发生了什么、这段素材能如何使用**。主界面安静、清楚，复杂处理状态在需要时出现。时间、来源、播放、文字与现场动作本身承担表达，避免用标题、副标题或长提示解释内部数据结构。

视觉延续已确认的 C「无描边色块」方向：灰绿页面底、白色内容表面、深绿操作色、浅绿实时记录。精致感来自稳定的对齐、可读的层级和一致的操作反馈；兔子承担主要品牌表情。

| 原则 | 执行规则 |
| --- | --- |
| 内容优先 | 时间线以选中日期为主锚点；详情以转录为主阅读区。标题、正文强于元信息和工具，不能让所有分组标题、徽标和按钮同时抢占注意力。 |
| 颜色承担意义 | 深绿用于操作、选择和必要强调；暖色用于现场记录类别或需注意的状态。类别与错误仍用文字区分，不能仅靠同一个暖色传达。 |
| 表面形成分组 | 页面、侧栏、内容表面构成主要三层；卡片内部优先使用留白和信息分隔线，避免逐层嵌套白卡。 |
| 状态真实 | 本地录音、云任务、保存操作分别表达。请求已发出、回执已收到、业务已生效不是同一个状态。 |
| 操作稳定 | 悬停、聚焦、提交和刷新不引起无必要的位移；同类动作有一致的尺寸、命名与反馈。 |
| 动态克制 | 动效解释变化、位置和生命感，不掩盖内容。减少动态效果时仍能完整判断状态与操作。 |

### 1.1 表面与边界

- 页面用 canvas，侧栏用 sidebar，内容卡片用 surface。概览、历史记录、统计、人物和设置取消装饰描边及卡片悬停阴影；实时记录使用专用浅绿底，悬停加深填色。
- 次级按钮用浅灰绿填充，选中 / 新建事件用较明确的浅绿。白色面板内的表单用浅色填充；浅色弹层与笔记输入区用白色，移除描边后仍须能辨认输入范围。
- 详情左侧为白色阅读区，右侧现场记录用灰绿底，播放器与记录卡片保留色块。日历、弹窗、抽屉保留表达浮层关系的阴影。
- 时间轴、行分隔、选中标签下划线属于信息线，继续保留；键盘焦点与输入焦点属于操作反馈，必须清晰。需要保留几何占位时可用透明边框，避免状态变化时跳动。
- 常驻入口保留专用深色表面及角色素材，不把该例外扩大为主窗口深色主题。

## 2. 信息架构、窗口与滚动

### 2.1 页面与入口

| 区域 | 内容与行为 | 关键约束 |
| --- | --- | --- |
| 左侧导航 | 时间线、处理队列、人物库、Agent 接入、设置 | 常规 / 紧凑侧栏共享布局 token，留出原生红绿灯空间。0.1 不展示 GUI 搜索入口，CLI 与核心搜索继续提供。 |
| 时间线顶部 | 左侧日期导航，右侧兔子、状态、来源与录音操作 | 仅首页显示，不增加全局状态栏、声音柱或胶囊外框。窄窗保留日期顺序及左右关系。 |
| 时间线主体 | 当天声音 / 事件分布与倒序记录 | 一次查看一个本地自然日；日期与日程倒序。轨道表示真实时刻，未整理素材可见。 |
| 事件详情 | 播放器、转录 / 音频信息两个标签页、右侧现场记录 | 抽屉保留双栏；句段与现场记录按时间正序。 |
| 常驻入口 | 顶部或悬浮兔子，截图 / 重点 / 评论与录音操作 | 关闭主窗口仍可用；不持续展示计时、波形或录制灯。不同入口的点击语义见 6.1。 |
| 弹窗 | 新建 / 编辑事件、密钥与配置编辑、导出、清理、纠错 | 只询问当前任务需要的信息；破坏性操作说明范围与影响。 |

### 2.2 窗口契约

原生窗口尺寸以 [`tauri.conf.json`](../src-tauri/tauri.conf.json) 为准：初始 1120 × 760，最小 760 × 540。以下均为逻辑像素。不能用高于 540px 的根容器最小高度制造另一套窗口下限。

| 范围 | 布局要求 |
| --- | --- |
| 常规桌面 | 侧栏 `--layout-sidebar-width`（184px）；内容最大宽度 `--layout-content-max`（1170px），时间线另用 `--layout-timeline-max`（1104px）。 |
| 1100px 及以下 | 收紧页面水平留白；详情采用现有约 88vw 的中间布局。优先让内容换行，不缩小功能文字。 |
| 850px 及以下 | 侧栏 `--layout-sidebar-compact-width`（104px）；隐藏导航文字仍保留可访问名称；详情占满窗口并避让窗口按钮，继续双栏。 |
| 最小 760 × 540 | 导航、主动作、关闭、表单提交均可达；长内容在所属区域滚动，不靠提高根高度、隐藏错误或裁掉页脚满足截图。 |
| 大窗口 | 宽度到达内容上限后增加外部留白，不无限拉长正文与表单。 |

时间线的时间栏、轴线和概览来源栏由 `--layout-timeline-gutter/rail`、`--layout-map-label` 管理，不改变详情宽度。日历、下拉浮层与菜单根据可用空间定位，不能越出窗口后让主要动作不可达。

### 2.3 滚动与原生窗口

- 主页面由自己的内容区域滚动；布局中的可收缩区域允许缩小到可用高度。不要让 body、页面和卡片同时产生没有意义的嵌套滚动。
- 转录详情接近底部时自动分页加载，无需点击“显示更多文字”；加载失败保留正文并提供重试。粗转与精转按已加载的共同时间范围合并，未加载的精转不能视为空缺；真正未被精转覆盖的粗转仍保留。后台刷新和追加分页不重置阅读位置。
- 详情左栏固定播放器和标签 / 转录工具栏，正文独立滚动；右栏记录列表独立滚动，笔记输入固定在该栏底部。展开识别文字随记录列表滚动。
- 弹窗限制在可用窗口内，长内容在弹窗内滚动；关闭与提交仍可到达。首次设置的展开内容采用页面纵向滚动，页脚留在文档流中。
- macOS 使用 Tauri Overlay 标题栏并隐藏原生标题文字，不画独立横贯标题行；红绿灯位于内容左上角，侧栏品牌向下留出 60px，窄窗保持净空。
- 主窗顶部空白（含页边距）和侧栏非交互空白可拖动，沿用 Tauri 命中模式。日期、文字选择、日历、导航和整块录音控件保留原行为；拖动属性不向交互子项继承，不铺设截获点击的透明层。
- 常驻入口展开 / 收起同步原生窗口命中区域；透明区域不能截获主窗口点击。原生行为须用安装版验收，浏览器预览只能验证布局与 Web 交互。

## 3. 视觉基础与 Token

### 3.1 所有权和命名

全局设计 token 定义在 `src/tokens.css` 的 `:root`；组件引用语义 token。新增颜色、字号、常用间距、圆角、阴影、时长和层级先查已有用途，不能因为某个页面看起来特殊就再造一套同义值。

| 类别 | 现有 token 家族 | 角色与边界 |
| --- | --- | --- |
| 表面 | `--color-canvas/surface/sidebar`、`--color-surface-*` | 页面、内容、侧栏、悬停与选择；不要把 selected 用于任何普通浅绿装饰。 |
| 操作与录音 | `--color-control/hover`、`--color-recording-surface/hover` | 次级动作与正在记录的内容表面，不能互相代替状态。 |
| 文字 | `--color-text`、`--color-text-strong/secondary/muted/faint` | 按角色选择并检查实际背景；名称不保证自动形成明度阶梯。 |
| 边界 | `--color-border`、`--color-border-subtle/strong/active` | 信息分隔、需辨认的边界和选中提示；不是每张卡片的必选装饰。 |
| 意义 | `--color-brand-*`、`--color-positive*`、`--color-warning-*`、`--color-danger-*` | 操作、成功、注意与错误；标记色、文字色、表面色分别配对。 |
| 现场记录 | `--color-mark/screenshot/comment` | 重点、截图、笔记类别；仍须有类型名称，不借类别色代替失败状态。 |
| 文字与节奏 | `--font-ui`、`--type-*`、`--weight-*`、`--leading-*`、`--tracking-*`、`--space-*` | 使用下面的角色表，不在每页自由组合。 |
| 形状与深度 | `--radius-*`、`--shadow-*`、`--ring-*` | 表面几何、浮层深度及焦点反馈。 |
| 动效与布局 | `--motion-*`、`--ease-standard`、`--layer-*`、`--layout-*` | 时长、缓动、层级与共享几何。 |
| 深色常驻入口 | `--entry-*` 中的表面、文字、操作和反馈 token | 专用于顶部 / 悬浮入口；角色位图自身调色板属于素材。 |

组件内部可以保留 1px 信息线、SVG viewBox、时间轴百分比、原生屏幕几何等固有值。由 `entry-api.ts` / `FloatingWidget.tsx` 动态注入的 `--entry-band`、`--entry-rabbit-*` 等是运行时几何参数，不是遗漏的全局 token。不要为消除扫描告警伪造默认值。

### 3.2 色彩配对与可读性

| 内容 | 规定配对与限制 |
| --- | --- |
| 正文 / 重要说明 | text 或 text-strong 配实际 surface / canvas；强调同时依靠字重、位置和空间，不能假设 strong 一定比 text 更深。 |
| 辅助信息 / 功能占位提示 | secondary 或 muted，仍按普通文字验算。空态原因、未配置说明、输入占位和可点击操作不使用 faint。 |
| 附属装饰 | faint 只用于不承担理解或操作任务的陪衬；有必要读出的时间刻度仍须可读，不能只因字号小就归入装饰。 |
| 主操作 | brand 表面配浅色文字；hover、focus、disabled 分开表达。前景需要独立语义别名，不能在组件中写白色色值。 |
| 警告 / 错误 | 警告正文优先 warning-strong；danger 文字在实际表面上验算。warning、mark、screenshot 等标记色不能直接当作小字号正文色。 |
| 录音 / 选择 | 专用浅绿表面配清晰文字；同时提供“正在记录”、选中标识或可访问状态，不能仅用绿点或底色。 |
| 深色入口 | 使用 entry 的前景 / 背景配对，含透明色时按实际合成背景检查，不能直接套主窗对比度结果。 |
| 图表 | 次数 / 输入用绿色系，输出蓝色系，缓存紫色系，成本暖色系；颜色随日期范围保持稳定，配合名称、图例与数值，成本独立轴。 |

普通文字以 **4.5:1** 为验收下限；确属大文字时可用 **3:1**，不能把 16px 卡片标题自动算作大文字。识别控件、图表信息和状态所必需的非文本线条 / 图形以 **3:1** 为目标；自定义焦点指示也须相对实际相邻背景达到清晰的 3:1。半透明背景按合成色计算，不用截图抗锯齿边缘取样。无描边按钮可以由清晰的文字或图标表达操作，无需为满足规则给所有卡片补边框。[W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

禁用状态不能伪装为可用；需要解释的阻断原因保持正常可读，不能随整个容器一起降透明度。选中、错误、录音、处理中均有文字或结构线索。满足这些局部要求不等于已完成全应用无障碍符合性认证。

### 3.3 排版角色

使用 `--font-ui` 的系统字体栈，中文使用系统中文字体。正文保持正常字距；`--tracking-tight` 只用于合适的品牌 / 大字局部，不能套到中文段落、按钮和元信息。时间、容量、用量与成本使用等宽数字（`tabular-nums`），避免更新时抖动。

| 角色 | 字号 / 字重 / 行高基线 | 使用规则 |
| --- | --- | --- |
| 当前日期 | type-date：32px / semibold / tight | 时间线唯一强日期锚点，邻日弱化但可读。 |
| 页面标题 | type-heading：22px / semibold / tight | 设置、人物、队列等；不附加无信息量的宣传副标题。 |
| 区域 / 卡片标题 | type-lead：16px / semibold / body | 事件标题、常规分组；不与页面标题同强度。 |
| 正文 / 摘录 | type-body：14px / regular / body 或 relaxed | 列表摘录与说明；卡片摘录用 relaxed。 |
| 长转录阅读 | type-reading：15px / regular / relaxed（1.75） | 详情句段正文；元信息与修正入口保持 12px，原识别文字继续使用辅助角色。 |
| 常规操作 | type-meta / control：13–14px / medium 或 semibold | 按钮、标签页、选择器；medium 使用已定义的 500 字重 token。 |
| 元信息 / 紧凑操作 | type-caption：12px / regular 或 medium | 来源、时间、状态；功能动作最低 12px，不等于命中区只有 12px。 |
| 附属标识 | type-micro：11px / regular | 仅限低优先级附属内容；不用于保存、修改、重试等功能文字。 |
| 常驻菜单 | type-entry-menu：15px | 保留已确认的入口菜单字号，不强行归并为 14px。 |

现有 20 / 26 / 38 / 42px token 保留给已经明确的局部角色，不新增每页独有的标题等级。文字不靠连续缩小来塞入窗口；优先换行、调整布局或让内容滚动。按钮标签尽量短，说明、错误和已保存配置不得因省略号丢失唯一关键信息。

### 3.4 空间、尺寸、圆角和深度

间距继续使用既有 `--space-1` 至 `--space-14`（2–64px），不重新编号。常规节奏优先 4 / 8 / 12 / 16 / 20 / 24 / 32px；2 / 6px 留给图标、标签等局部光学校正。

| 场景 | 规范 |
| --- | --- |
| 同一控件内部 | 图标与文字常用 4–8px；标题与说明 4–8px。 |
| 内容卡片 | 内边距 16–20px；窄窗 12–16px；同级记录间隔 12–16px。 |
| 跨分组 | 常用 24–32px；靠留白表达分组，不再重复套边框与阴影。 |
| 通用控件高度 | 紧凑最小 28px，常规最小 34px，宽松最小 36px；使用 control-height 角色 token。允许长标签增高，不固定高度裁字。 |
| 图标按钮 | 常用图形 16–18px，命中区遵循控件尺寸；日历入口保留 40px，兔子入口按专项几何。 |
| 圆角 | sm 8px 用于小控件，control 10px 用于标准表单 / 按钮，md 12px 用于内容卡片，lg 16px 用于浮层 / 大分组；xl 20px 只用于已有大表面。pill 仅用于需要的标签 / 选择器；圆形用 50%。 |
| 阴影 | popover / drawer / modal / floating 表达浮层深度；control 仅用于确有浮起关系的控件。普通历史卡片不增加悬停阴影。 |

焦点样式不改变布局；可采用独立 outline 与外扩间距，或对完整输入组显示焦点环。不能移除浏览器焦点后只保留肉眼难辨的浅绿光晕。字号、视觉尺寸与命中区分别定义，不能用放大图标代替扩大操作区域。

### 3.5 图标、角色与动效

- UI 图标沿用 `Controls.Icon` 的线性 SVG：24 × 24 viewBox、1.6px 线宽、圆端点；常规显示约 18px。新增图标在同一体系补齐，避免 `×`、`＋` 等文本字符与 SVG 的基线混用。装饰 SVG 隐藏于辅助技术，按钮负责提供名称。
- 兔子采用已确认 B4 / I4 素材及共享 `Rabbit` 渲染，不用局部 SVG 重画。48 × 48 悬浮素材在 52px 目标内居中，1× / 2× 以整数像素倍率检查；首页另有 72px 布局角色，需单独检查清晰度，不能据此声称所有显示尺寸都是整数缩放。等待态的收耳姿态与正常倾听态保持区别。
- fast 120ms 用于 hover / pressed，standard 180ms 用于轻量显隐，layout 300ms 用于日期布局，loading 1400ms 用于骨架；统一使用 ease-standard，不另加任意弹性动画。
- 日期导航按文字实际宽度排列，选中日期与邻日保持紧凑间距；变化时保留同日期 DOM，按当前实际几何续接，快速连续点击不先跳回旧位置。悬停不移动内容；保存状态变化保持按钮宽度稳定。
- 系统减少动态效果时关闭非必要位移、扫光、呼吸和骨架动画，保留静态状态。文档隐藏时停止兔子动画；恢复后根据真实状态继续，不重放积压动画。

### 3.6 本版要求补齐的 Token

以下角色已进入生产 token 并完成调用方迁移。新增角色仍需先定义再引用，不给未定义变量统一加 fallback。

| 已实现角色 | 约定 | 迁移规则 |
| --- | --- | --- |
| medium 字重 | `--weight-medium: 500` | 补齐统计 tooltip 已有引用；其他组件按角色使用，不全局替换 600。 |
| 主按钮前景 | `--color-on-brand`，初始别名指向现有白色 surface | 独立表达按钮前景；未来变更表面时仍单独验证配对。 |
| 警告正文 / 功能占位 | `--color-warning-text` 指向 warning-strong；`--color-placeholder` 指向 muted | 消除把类别标记色、faint 直接用于功能文字的混用。 |
| 控件高度 | `--control-height-compact/default/comfortable` 为 28 / 34 / 36px | 用于 min-height，不强行覆盖日历、播放与兔子专项尺寸。 |
| 常驻菜单字号 | `--type-entry-menu: 15px` | 收拢 entry.css 中对应字号，其余裸字号映射已有角色。 |
| 图表系列 | `--color-chart-usage/output/cached/cost` | 先迁入现有系列配色并验证实际背景；不在收敛时顺便更换整套配色。 |
| 焦点与状态配对 | 修订现有 focus 及不合格的前景 / 背景配对 | 以对比度和实际界面验收，不把研究预览候选值自动视为最终色板。 |

## 4. 公共组件契约

以下是所有页面共用的行为要求。已有组件见第 7 节；未有公共实现的部分按第 9 节迁移，不能仅通过新增 class 宣称完成。

### 4.1 Button 与 IconButton

| 类型 | 使用场景 | 视觉与交互 |
| --- | --- | --- |
| 主动作 | 当前任务的确认 / 保存 | brand 实心；同一个操作组只突出一个主动作。 |
| 次级动作 | 新建事件、并列的辅助操作 | 浅绿或浅灰绿填充，按既有页面语义选择。 |
| 轻量动作 | 句段编辑、返回、展开详情等 | 文字或图标为主，hover 有轻填色；仍有独立焦点与足够命中区。 |
| 危险动作 | 删除、破坏性清理 | danger 语义与明确动词；进入确认前展示对象和影响。 |

所有按钮覆盖 default、hover、pressed、focus-visible、disabled、busy。pressed 使用不移动布局的内描边，保持原前景 / 背景对比度；不能用整体调暗损失文字清晰度，也不能代替选中状态。原生 button 默认 `type="button"`，只有表单提交按钮使用 submit；不能把整行交互容器与内部按钮嵌套成两个 button。

busy 来自业务操作状态：阻止重复提交，提供“保存中…”等可读反馈，避免仅旋转图标。按钮处理禁用与事件守卫，不能只调低透明度。普通不可用操作使用原生 disabled；需要保留焦点解释原因的特定入口（如首次设置完成按钮）使用 aria-disabled 加守卫，不把该例外泛化到所有按钮。

IconButton 必须提供描述动作的可访问名称；仅显示“编辑”图标时名称要能区分对象。辅助 tooltip 同时支持悬停与键盘聚焦，不能只依赖 HTML title；唯一关键说明放在可见页面中。

### 4.2 Field、草稿与提交

- 输入有可见标签；placeholder 仅补示例，不能代替标签。提示与错误通过 `aria-describedby` 关联，校验失败使用 `aria-invalid`；错误位于对应输入附近。
- 表单只有一个明确提交入口。单行输入的 Enter 遵循所在表单契约，中文输入法组合输入期间不触发提交；详情多行笔记 Enter 换行。顶部评论保留 Enter 提交、Shift+Enter 换行的专项契约（见 6.1），不把它泛化为所有多行输入的快捷键。
- 草稿由当前表单管理，已保存值由业务数据管理。打开编辑以当前已确认值初始化，取消不提交；失败保留输入，成功确认后关闭 / 更新。
- 设置密钥显式“验证并保存”，失焦不提交；首次设置 compact 密钥保留回车 / 失焦验证，这是已确认的场景例外，见 6.6、6.8。
- 不能把固定掩码当作新密钥提交；不得用错误清空现有配置。修订冲突、结果未知的处理遵循第 5 节。

### 4.3 Switch 与 SegmentedOptions

Switch 表达单个已确认的开 / 关配置，具有稳定名称和 `aria-checked`。使用原生 button 的键盘操作；应用期间禁用重复提交，成功前不画成已确认的新配置。来源“已启用”与权限“可录制”是两种事实，需要分别呈现。

SegmentedOptions 表达一组选项中选择一个值，沿用原生 fieldset / radio 的分组、名称和方向键行为；选中不只依赖底色。准备模型、重新验证、导出和清理是普通动作，不能包装成开关。

### 4.4 Tabs

Tabs 切换内容面板，SegmentedOptions 选择配置值，两者不合并为万能切换器。转录 / 音频信息、队列 / 统计数据使用同一个 Tabs 契约：

1. 容器为 tablist，有可理解的名称；每项为 tab，具备稳定 id、aria-selected 和 aria-controls；对应面板为 tabpanel，以 aria-labelledby 关联标签。
2. 同一时刻只有一个标签处于普通 Tab 顺序；左右方向键在标签间移动焦点并循环，Home / End 到首尾。采用手动激活：Enter / Space 选中聚焦项，避免方向键浏览时触发有延迟的加载。
3. Tab 从标签进入可见面板的下一可聚焦内容；没有合适焦点目标时面板可聚焦。隐藏面板不暴露可操作内容，不能仅用透明度隐藏。
4. 焦点与选中分别可见。刷新不把焦点拉回标题，不无故重置页面已保存的筛选或播放状态；数据加载仍由页面负责。

详情和队列已共用 `Tabs / TabPanel`；手动激活、单一 Tab 停靠与面板关联由公共组件负责。[W3C Tabs 模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)。

### 4.5 Modal、Drawer 与 Popover

| 模式 | 背景与焦点 | 关闭与滚动 |
| --- | --- | --- |
| Modal | 真正阻断背景；打开后焦点进入，Tab / Shift-Tab 留在内部；提供标题与必要说明 | 明确关闭 / 取消，Escape 由最上层处理；内容过长内部滚动。 |
| Drawer | 事件详情作为模态抽屉，复用相同焦点生命周期；保留双栏与独立滚动 | 关闭回到原触发记录；嵌套图片预览先关闭自身，不能一键连关多层。 |
| 非模态 Popover | 日历、说话人等依附触发点，不推动正文；按内容提供合适的语义，不虚设 aria-modal | Escape / 点击外部关闭，定位自动避让；键盘可离开，焦点离开整个浮层后关闭，不设无出口的循环。 |
| 图片预览 | 模态呈现原图，名称可读，控制与图片状态可达 | 返回详情原来的截图入口；图像缩放不改变父层滚动归属。 |

普通表单优先扩展现有原生 `dialog.showModal()`。初始焦点必须可显式指定：短表单聚焦首个输入，长说明聚焦标题 / 说明，危险确认优先取消或说明；不能一律搜索第一个 input。关闭后恢复触发控件；若原控件已删除或不可用，转到同任务的合理位置，不能任由焦点落到页面根。

允许遮罩点击关闭的普通弹窗，与 Escape / 关闭按钮使用同一业务守卫。破坏性操作绝不因点击遮罩执行；已进入不能安全取消的提交时阻止关闭并说明正在处理。只读加载不应锁住退出；未知结果进入可确认的恢复流程，不能无限停留在忙碌遮罩。

说话人浮层包含搜索、范围和保存，不能仅标成菜单；其编辑与草稿规则见 6.5。任何确需阻断背景的浮层必须使用模态实现，而不是只添加 `aria-modal="true"`。[W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。

非模态浮层通过 Escape / 取消等动作关闭时恢复触发点；焦点自然移到外部控件而关闭时，保留用户的新焦点位置。实现不能一边允许 Tab 离开，一边又把焦点强行拉回。

普通页面层级沿用 `--layer-*`。原生 dialog 进入浏览器 top layer 后不能靠普通页面的更大 z-index 覆盖；该弹窗的下拉、错误与反馈须置于正确的活动层内。嵌套关系由弹层基础组件协调，不给每个页面添加全局 Escape 监听。

### 4.6 SettingRow、状态、加载与反馈

SettingRow 只负责标题、弱化状态、下一行说明与操作区的布局；不读取设置、不保存配置。窄窗长状态自然换行，操作区保持可达；不能通过截断唯一状态信息来维持固定行高。

StatusLabel 至少区分普通、正在记录、处理中、警告、错误和待确认的展示角色；这是 UI 映射，不要求新增核心状态枚举。每个角色有文字，不把所有成功、选中、录音和处理中都做成同一种绿点。

Loading / Empty / Error 复用 `LoadingState.tsx` 的展示基础，数据事实留在业务 owner。成功短反馈可用非阻塞提示；持续错误在对应页面或表单内保留并提供下一步。状态更新可使用温和的 live region，不逐帧播报动画、时间或进度，不为装饰骨架制造重复播报。

## 5. 状态、内容与反馈的共同规则

| 状态 / 场景 | 用户看到什么 | 数据与操作约束 |
| --- | --- | --- |
| 首次加载 | 与目标布局匹配的骨架或明确加载说明 | 尚未成功返回，不显示空态、零计数、未配置或未授权。各区域按各自请求结束加载。 |
| 已加载为空 | 简短原因与适用的下一步 | 仅在成功读取且确实没有内容时出现；不把失败伪装成空。 |
| 后台刷新 | 保留已有内容，必要时轻量标注刷新 | 不整页闪回骨架；刷新失败说明当前内容可能未更新。 |
| 切换范围 | 明确属于新日期 / 月份 / 统计范围的加载或结果 | 不能将旧范围结果直接显示为新范围数据。 |
| 提交中 | 原操作附近显示忙碌，阻止重复提交 | 不提前宣告成功，不借按钮内部计时推断完成。 |
| 结果未知 | “待确认”等明确反馈与原请求确认入口 | 保留请求 ID；不能自动发起另一笔付费请求，也不能当作普通失败盲目重试。 |
| 校验 / 操作失败 | 对应位置说明原因与重试 / 修正入口 | 保留草稿和已确认配置；保留原图、已有转录等仍有效的内容。 |
| 版本冲突 | 提示内容已变化，刷新并允许明确重试 | 不覆盖新版本，不留下半创建人物，不误称成功。 |
| 成功 | 更新真实数据，必要时短反馈 | 控制回执不代替实际录音快照；只在业务确认后更新成功状态。 |
| 破坏性操作 | 对象、范围、影响与确认 | 清理默认“清除原始音频”；“清除全部数据”额外确认。 |

文案使用用户能辨认的结果与动作，例如“正在记录”“已暂停”“未开始”“保存笔记”“重新识别”。权限、模型、空间与云处理细节放到相应设置 / 队列；不暴露 UUID、内部状态码、声纹特征或任务分块细节。详情骨架分别匹配转录与现场记录布局，加载完成后列表与详情按真实数据同步。

摘要、原文摘录、粗转、精转和人工修正必须有清楚的来源；缺少摘要不能用摘句冒充。说话人显示已命名人物或会话内可读序号。费用使用“估算”等准确表达，不把记录单价推算当作真实扣款。

## 6. 场景规范

本节保留已经确定的产品行为。公共外观与操作复用第 3–5 节；场景例外在本节明确说明，不以统一组件为由抹平。

### 6.1 兔子与录音入口

#### 常驻入口

以[安静兔子 PRD](prd/prd_0.1_quiet-rabbit-entry.md)和[技术 RFC](prd/tech_rfc_0.1_quiet-rabbit-entry.md)为入口规则来源。macOS 默认顶部、可切悬浮；无刘海屏顶部居中，Windows 仅记录悬浮规则。正常状态通过用户确认的v2双竖耳薄荷兔倾听呼吸表达，主动暂停睡眠；异常保持清醒、静态提示，展开说明，不能冒充睡眠。主窗口仍保留必要的明确状态文字，本规则针对常驻入口。

顶部展开左兔右侧截图 / 重点 / 评论，收起角色同时隐藏；鼠标 hover 兔子显示暂停/播放遮罩。前三个动作完成发起后立即收起，结果确认后另行轻提示；不等待动画，不暂时取消常驻入口。主窗品牌图形使用 I4 图标；悬浮菜单文字15px、菜单贴近角色，原生命中同步实际圆角。悬浮保留主点击重点，菜单默认向上、顶部空间不足时向下展开，不复用顶部的暂停点击。正常状态不持续展示容量环、时长或耗电感提示。

[B4 / I4 素材](../design/rabbit/b4-i4-v1/index.html)已由用户确认。常驻仅倾听/睡眠两个低频循环；其他回应单次，睡眠中的回应保持闭眼。APP 图标使用完整方形无边框母图，按平台另行裁切；不把圆角、阴影或外留白烘焙进母图。

顶部展开从屏幕顶边形成完整黑色表面；悬浮菜单使用克制的深绿色表面；它不扩大主窗口深色主题范围。生产 UI 的面板/文字/焦点/提示色仍通过语义 token 管理，新增角色表面等 token；像素图片的固定调色板属于素材固有颜色。减少动态效果和隐藏时停动画。生产入口已接入原生窗口，素材和 HTML 预览不能替代尚未关闭的真机验收。

悬浮球的菜单默认隐去，鼠标悬停或键盘聚焦出现；按钮具备可访问名称和清晰焦点。按住兔子移动超过 7pt 即拖动，松手吸附当前显示器可用区域最近的四边并记住位置；拖动不标记重点。收起时原生窗口只占角色目标，菜单根据落点朝屏内展开，兔子位置不跳动；透明区域不能截获其它窗口点击。可操作小字与图标要有足够命中区。减少动态效果选项下去掉非必要动画。

顶部评论沿用 Enter 提交、Shift+Enter 换行；中文组合输入期间 Enter 不提交，空白不操作。取消、Escape、外部点击或切换形态只收起输入，保留草稿与原始时间锚点；确认成功后才清除对应草稿。悬浮入口的主窗口评论保持独立会话，不复制顶部草稿。详细长度、确认与恢复规则沿用上述 RFC。

入口 hover、截图、重点及后台保存回调不抢占其他应用焦点；评论输入按用户意图获得焦点。提交 / 取消后仅在用户尚未选择其他目标时恢复原焦点；用户已切到别处就尊重当前目标。常驻输入的焦点恢复不能直接套用主窗口 Modal 的 DOM 恢复逻辑。

#### 时间线录音控件

时间线首页的日期与兔子状态模块左右同排，不增加一条全局状态栏，也不采用声音柱或胶囊外框。右侧72px角色旁常显明确录音状态与当前来源。兔子和右侧文案共同组成一个原生按钮热区；悬停任意位置或键盘聚焦时，深色遮罩覆盖整块内容，居中显示暂停/继续图标与操作名称。点击兔子、间隙或文案调用同一个录音操作，没有独立文案下方按钮。处理中与待确认时遮罩文字持续可见，准备阻断/未知时提供设置/重试，按钮保留可访问名称、禁用行为与焦点。

首页、notch、悬浮球统一复用Rabbit及同一v2 atlas/clip；录音使用双竖耳姿态，暂停使用生图模型生成并经用户确认的趴睡姿态、闭眼与4.8秒低频呼吸。正常呼吸采用3档像素位移（在48px显示下0/1/2px），每约3秒一轮、6秒眨眼一次；睡觉3档背部起伏，闭眼与前爪保持静止。首页不再保留私有SVG或睡眠播放分支。清醒/趴睡的轮廓明显不同，等待和异常仍保持清醒。

正常绿色、暂停灰绿、异常暖色；准备条件和空间阻断进入既有设置，连接未知只允许重试。同一宿主快照驱动各处录音状态；单次桥接失败只显示本地错误，不改写宿主状态。减少动态效果和文档隐藏时由Rabbit统一停动画。模块随时间线页面挂载/卸载，控制请求与反馈保留在App会话，不因切页丢失待确认ID；控制回执不代替实际采集状态，不另起状态轮询。

### 6.2 时间线

#### 日期与概览

选中日期是唯一强视觉锚点，邻日只是轻量导航；顶部保留选中日期作为锚点，并显示所选月份相邻的有记录日期。同月切日不清空月导航；首次加载、跨月加载及空日也保留选中日期，不在导航里显示「暂无记录」。日期复用同一元素，以约300ms连续过渡字号、宽度与位置，快速连点从当前动画尺寸继续；系统偏好减少动态效果时直接切换。日历入口直接打开标准月视图，支持前后切月，空日和未来日期置灰。可选日期来自core CalendarDays按客户端本地自然日边界对实际素材、可见事件/精转范围及现场记录的只读查询，不把缺口作为有记录依据。

概览与“当天记录”共享同一自然日；列表按最新在上展示。概览按麦克风/电脑声音分行，用浅绿色显示未整理素材，用稍深绿色显示事件/手动精转范围，用底部独立的中性斜纹表示该来源的已知未记录区间；内容范围不等于连续录音，通过图例及色块/缺口悬停详情表达；不再显示底部解释和缺口统计两行。区间裁剪到当天和当前已发生时间，今天显示现在标记，现场记录保留独立标记。

列表固定沿用原默认策略收起普通未整理历史素材；不提供“显示粗转/隐藏粗转”切换按钮。命名事件、手动精转范围、异常、本地失败及带现场记录的卡片继续保留；当前确认正在记录的条目及其实时摘录仍展示，停止记录后恢复普通筛选规则。该投影只影响列表，不改变概览事实。

#### 卡片内容与层级

卡片顶行统一展示时间、内容类型及声音来源、现场记录数量和处理状态。命名事件下方展示标题及最多两行内容摘要，元信息标注“内容摘要”；摘要缺失时显示“暂无内容摘要，打开查看转录”，不以原文摘句冒充摘要。实时/未整理素材与手动精转范围保留粗转/精转标签及最多两行真实摘录，避免把局部精转描述成整卡完成。core 的 timeline 投影提供可选 preview（text/source/is_precise），优先当前有效精转及人工修正，否则粗转；最多160个Unicode字符加省略号，完整转录数组仍为空，详情保留既有分页。没有文字时显示诚实空态，纯现场记录可用笔记/截图文字作为线索。隐藏粗转后保留的现场记录不显示被隐藏的转录。事件和概览色块点击打开原有详情，编辑边界后回到新的时间范围。

时间线采用紧凑的内容优先层级：常规侧栏184px，日期32px（`--type-date`），日历入口40px；记录分布、列表标题与页面左右边界对齐。兔子尺寸由 `--layout-capture-rabbit` 控制。时间线最大宽度、左侧时间栏与轴线、概览来源栏分别由 `--layout-timeline-max/gutter/rail` 与 `--layout-map-label` 控制；不影响详情抽屉的宽度。卡片标题16px、摘录14px、元信息12px；状态使用独立文字标识，录制为浅绿、失败为柔和暖色。普通历史卡片不依靠加重边框争夺注意力。当天记录旁仅保留新建事件浅绿操作按钮。概览的当前时间放在图例所在行，与轨道标记分离；中间时刻标签严格落在25%/50%/75%的位置。导航采用统一线宽的矢量图标，窄窗隐藏文字后仍保留可访问名称。

#### 概览指针反馈

概览轨道悬停时显示贯穿所有来源与现场记录行的细竖线，上方同步显示该横向位置的本地时间 `HH:mm`。装饰层按显示帧跟随指针，不驱动整页状态更新；标签在轨道两端保持完整，最右端显示 `24:00`。离开轨道、切日、布局缩放、滚动或失焦后隐藏，触摸不模拟悬停。光标不拦截既有色块点击和键盘焦点；系统减少动态效果时取消淡入淡出。

#### 实时记录卡片

最新卡片仅当core的当前活跃来源、open recording session最近确认尾部与卡片范围一致，且主窗口最新EntrySnapshot仍确认该来源正在记录时，显示“正在记录”、静态浅绿底与状态点，不使用持续扫光。正在记录的未命名卡片标题为“实时记录内容”，卡片时间显示“开始时间 — 至今”；已有事件标题保留。“正在记录”复用卡片顶行最右的主状态位置，替代“待整理”“整理中”等普通处理进度，不重复占位；整理/精转/本地分析异常仍独立显示在主状态之前，手动任务提示保持。历史日期、暂停、来源停止或状态不可用时恢复实际处理状态、结束时刻和原有标题规则；系统偏好减少动态时关闭非必要过渡，仍保留真实状态文字与静态反馈。recording_sources是TimelineItem上的可选瞬时投影，不持久化、不改变录音生命周期。事件拟合失败显示“事件整理失败”，与录音和精转失败区分；处理队列继续显示具体原因和重试入口。

### 6.3 详情、播放与转录

主窗口的详情抽屉宽度由 `--layout-drawer-width` 控制；支持的窄桌面窗口仍保留左右分栏，850px 及以下抽屉占满窗口并在顶部避让 macOS 原生窗口按钮。左栏播放器和标签/转录操作工具栏固定，正文独立滚动；右栏笔记流独立滚动，输入区固定在底部。笔记区使用一致的内边距，保存按钮放在完整输入框内右下角，不再为外置悬浮入口固定预留大块空白。时间、说话人、转录正文、动作的视觉顺序应与阅读顺序一致。

播放器以紧凑的浅绿底放在详情左栏顶部，播放按钮、当前位置、来源切换保持同一区域。进度条使用实心轨道、已播放填充和圆形滑块，不使用线框轨道。当前句段按真实时间区间和所选声音来源显示浅绿底色与加重时间，不使用左侧深色竖线。

概览色块点击携带对应绝对时刻，详情播放器夹紧到该记录范围并保持暂停；首次加载按需翻页到目标附近，将包含该时刻或最近的转录块滚动至可见位置。暂停时，定位到的最近文本也复用浅绿底色与加重时间，包含句间空隙；定位按当前播放来源筛选，不改变播放器的精确时间。播放期间只高亮真实时间区间内的句段。正文后续刷新和播放不强制滚动；列表卡片与键盘打开色块仍从记录起点开始。

已完成但未识别出文字的精转，显示完成状态及空段数量；音频信息按真实来源和秒级范围提供回听入口，只有用户点击后才读取并播放。边界裁剪与空结果分开说明，统计来自 Core 当前有效引用。

5 秒分块的实现不显露给用户；拖动和点击句段应定位到真实时刻。精转句段优先，未覆盖部分可以显示本地粗转，来源标签必须清晰；命名人物还要区分自动匹配和人工确认。人工修正的文字作为显示、搜索和导出的有效版本；原识别结果仍可查看。句段操作跟随句段本身，不用长段操作说明占据正文。

未整理块的“选择范围精转”进入音频信息页，直接选择真实起止时间与可用声源；提交只为所选局部创建 ASR 待办，不把整块改写为已精转。已命名事件仍按整场精转。

### 6.4 现场记录与图片理解

右栏「现场记录」将笔记、重点和截图按原始时刻正序排列，采用等宽左对齐卡片；类型与可回听的时间放在同一行，重点保持紧凑单行。截图按需打开原图，识别文字默认折叠、展开后完整显示并随记录列表滚动，识别失败与未识别到文字不影响查看图片。底部输入区显示当前选择的笔记时间，动作为「保存笔记」，不使用聊天气泡和「发送」语义。

输入区使用一个完整白色色块包住文字输入和右下角保存按钮，常态无描边、聚焦时显示整体焦点环，不另加顶部横线。笔记按原有选定时刻或事件起点保存，保存成功后出现在记录列表中；失败保留草稿。笔记与重点不自动生成摘要，也不将现场动作伪装成音频转录内容。

#### 新截图的图片理解

配置 LLM 后，仅新截图自动发送给已配置的 DeepSeek，后台生成简短中文图片摘要与忠实 Markdown 文字转录；不回填历史，不增加开关或历史重新识别入口。卡片默认显示摘要，完整转录折叠并可复制 Markdown。没有文字时明确提示，无法辨认的部分标记而不猜测。原图仍独立打开。

未配置 Key 继续本地 OCR。云处理等待、进行中、暂停和失败从既有队列显示；失败仍保留原图与本地文字，可使用队列现有重试。LLM 队列标为“事件与图片理解”，设置说明新截图会发送给 DeepSeek。

### 6.5 人物与说话人

人物库以纯信息列表展示头像、姓名和声纹数量，整行进入人物详情。详情名称可点击行内编辑，Enter 保存、Escape 取消，另有明确保存/取消按钮；新建人物使用聚焦姓名输入的模态表单，删除人物及声纹均经确认。

声纹列表展示日期、来源、实际取样时长与组合片段数，播放仅包含真实取样片段；一次只播放一份，返回、切人或移除时停止。原音不可用时禁用播放，但仍展示可用于识别的声纹。加载失败显示重试，不伪装为空列表。

#### 说话人选择与绑定

说话人入口使用依附标签的紧凑浮层，不挤动逐句正文；统一搜索已有全局人物，输入不存在的姓名时显式选择创建。每次打开重置草稿，选择已有与创建新人互斥；应用范围明确区分“仅这句话”和“本场中该说话人的全部发言”（默认整组），由核心解析真实分组。人物列表独立滚动，浮层根据空间向上或向下展开；支持 Esc、点击外部关闭，并按 4.5 的关闭原因规则处理焦点恢复。保存期间禁用更改和重复提交，错误在面板内反馈，版本冲突刷新后重试。新建并绑定仍是一次可恢复的用户动作。未识别身份用会话内可读序号。

### 6.6 设置

设置按「通用、录制、识别与整理、存储与数据」分组。设置项统一采用「主标题 + 弱化状态标签」同一标题行，下一行放功能说明；状态不再单独占第三行，长状态在窄窗口自然换行，不截断。登录启动、声音来源、定时规则使用右侧即时开关；状态来自已确认配置，应用中禁用重复操作并显示反馈。来源启用与系统权限分别表达，未授权明确尚不能录制；只突出当前需要的授权动作，系统设置/重新验证收进授权帮助。

#### 定时与容量

定时主面板只显示开关、已保存时间摘要、下一次动作与「编辑时间」。开关直接提交，停用保留时间，启停规则不改变当前录音；两项时间在独立弹窗共同校验/保存，关闭规则时保存时间不启用。

音频上限主页面显示已保存上限和用量，通过「修改上限」弹窗提交；触顶暂停且提高上限后仍需手动继续，修改不会删除已有音频。弹窗草稿取消不提交，失败保留，修订冲突提示后由用户明确重试；定时/来源/容量结果未知沿用原请求确认，不假装失败或成功。

#### 云服务与密钥

两个云服务以「内容整理 · DeepSeek」「语音精转 · 火山引擎」并列展示配置状态，各自进入密钥编辑弹窗。设置页只在点击「验证并保存」或回车时提交，失焦/取消不发送；密钥只显示固定掩码，真实密钥不读回，掩码不提交。验证失败保留输入及原配置，未知结果只查既有回执，不自动重复付费验证。首次准备页 compact 输入保留原有回车/失焦验证。

### 6.7 处理队列与统计

队列分开显示 LLM 和 ASR 的配置、暂停与失败状态；本地录制状态不被云队列状态覆盖。失败动作提供明确的重试/继续入口，不自动吞掉错误。

处理队列内用「队列 / 统计数据」切换。确定无法使用的识别结果显示「重新识别」，同行说明将用保留原声产生新的识别用量；网络/凭据等不确定失败保留「重试」。操作处理中禁用按钮，原声缺失时明确提示并保留失败。

#### 用量统计

统计数据只有 7/30/90 天选择和两张完整白色图表卡片，沿用 C 的表面分组。转录图展示次数与成本；LLM 图展示输入、输出、缓存 Token 与成本，缓存是输入子集，不用堆叠表示总量。点击图例独立隐藏/恢复序列，切换日期保留选择；成本使用独立右轴，键盘日期滑块可查看每日数值。首次采集之前留空、覆盖期无调用显示零、缺失用量明确提示部分数据。页面说明成本是记录单价估算而非账户实际扣款。

### 6.8 单页首次设置

新用户进入「准备 Hear」极简页面，无副标题或白色大卡片。左侧依次为「① 下载本地模型」「② 授权声音访问」「③ 配置云服务」，右侧分别为一个安装/进度状态、两个授权按钮、两个密钥框；编号引导阅读，三项可并行准备。来源选择和授权恢复收进「调整」，帮助与数据外发详情折叠，常显「云端处理 · 按量付费」。正常状态只保留简短文字，错误在对应项目展开。完成按钮保持键盘可聚焦，未满足条件时以 aria-disabled 与操作守卫阻止提交，并在焦点/悬停时显示原因。最小 760×540 正常状态尽量一屏显示，展开后可纵向滚动，页脚在文档流中。准备状态与设置共用，设置页保留完整说明；不新增业务状态或操作路径。

「完成设置」新鲜核验并保存完成标记后进入时间线，不自动开始记录。「稍后设置」当次进入时间线并保留继续设置入口，下次冷启动继续准备。已使用用户升级跳过首次页；后续失效留在设置/队列修复。权限拒绝提供系统设置和返回复查；Tap 显示「已完成授权准备」而非永远可用。云验证回执不明先确认上次结果，不自动重复付费验证。

### 7.2 公共组件 API 目标

以下为现有公共组件的调用摘要，完整类型以 `Controls.tsx` 为准。原生控件属性与 ref 按需透传；组件不承担业务请求。

```ts
type ControlSize = "compact" | "default" | "comfortable";
type ButtonTone = "primary" | "secondary" | "quiet" | "danger";
type CloseReason = "close-button" | "escape" | "backdrop";

// Button：原生 button 属性 + tone / size / busy / busyLabel。
// IconButton：在 Button 基础上强制提供可访问名称。
// Field：组合 label、输入、description、error，统一 id 关联；不保存业务数据。
// Tabs：id、label、value、items、onChange；TabPanel：tabsId、value、selected。
// Modal：title、description、initialFocusRef、busy、feedback、onClose。
// Dialog：closeDisabled、initialFocusRef、returnFocusRef、onClose(reason)，供抽屉和图片复用。
// Drawer：复用模态生命周期，单独提供双栏、标题与滚动布局。
// SettingRow：title、status、description、action；不发起请求。
```

公共组件可以持有悬停、焦点、展开位置等短暂展示状态；不能持有一份独立的“录音已开始”“设置已保存”“云请求已完成”。选择值、busy、错误与已保存结果由现有业务 owner 传入。Dialog 的 closeDisabled / Modal 的 busy 由业务解释，不能把任意后台读取都视作禁止离开。

例如设置开关的收敛继续沿用现有接法：`checked` 取已确认配置，`disabled` 取当前操作是否处理中，`onChange` 发出修改意图；收到未知结果进入原请求确认，而不是由 Switch 内部先切换再倒计时恢复。

### 7.3 样式边界与迁移顺序

1. **先修公共基础**：定义缺失 token、功能文字与焦点配对，修正最小窗口高度冲突，补 Modal 生命周期和 Tabs 行为。
2. **按组件迁移调用方**：普通弹窗先复用 Modal；再处理详情和图片预览。逐项验证开 / 关、焦点恢复、busy 和嵌套关系，不一次改动全部业务逻辑。
3. **再收拢文件**：公共控件可进入 `src/ui/`，控件与弹层样式分别归属 controls / overlays；页面布局可进入 `src/styles/`。这些是迁移目标目录，当前无需为了目录形式批量搬迁。
4. **迁移期间只有一个权威实现**：`Controls.tsx` 可暂时转导出已迁移组件；同一组件不能长期保留两套样式。引用全部迁完才删除旧选择器。
5. **固定级联关系**：token → 基础元素 → 公共组件 → 页面组合。页面通过组件参数或有限局部变量调整，不用更深选择器、`!important` 或文件尾部补丁反复压过公共规则。
6. **保持请求与资源归属**：不新增录音轮询，不重写密钥验证、ASR 或人物绑定流程；公共组件卸载不能丢失仍需确认的会话级请求 ID。

收敛与美化分开提交，避免焦点修复和大幅调色互相遮蔽回归。每批完成所涉及场景的检查后再扩展，不以“新组件已创建”作为迁移完成标准。

## 8. 基于规范的审美打磨方案

### 8.1 方向与边界

目标是让现有灰绿系统更清澈、阅读节奏更稳定、操作更精致。保留 C 方向、兔子资产和信息架构，先统一层级与细节，再评估局部视觉变化。

[隔离预览](research/evidence/2026-10-22-design-system/preview.html)中的 polish 样式仅为候选，包含更轻的页面 / 侧栏表面、较深焦点、长转录字号试验及减少卡片扫光。它没有完成弹层、Tabs 等交互修复，不能直接作为生产补丁合入。候选色值留在[研究报告](research/2026-10-22-design-system-review.md)和预览中；本文不把它们升级为第二份正式色板。

### 8.2 先做两个样板场景

| 场景 | 打磨重点 | 比较标准 |
| --- | --- | --- |
| 时间线 | 日期锚点与邻日关系、兔子与日期的视觉平衡、概览 / 列表边界对齐、时间与卡片内容层级 | 第一眼能看出当前日期与录音状态；第二眼能区分事件、未整理素材及失败；主要动作可找到，卡片不互相争抢。 |
| 详情 | 播放器密度、转录行距与句间距、说话人 / 时间 / 正文顺序、现场记录与输入的边界 | 长文本可连续阅读；播放位置与文字来源明确；操作不挤压正文；760px 双栏仍可用。 |

同一组数据、同一窗口比较当前与候选。先做对齐、排版和空间，再评估表面色与动效，避免同时改变所有变量后无法判断收益。2026-10-23 已采纳下表规则，生产值仍由 tokens.css 与所属组件样式维护；候选中不合格的更浅辅助文字未采纳。

| 已采用规则 | 生产实现与边界 |
| --- | --- |
| 清晰而安静的表面 | canvas / sidebar 轻微提亮；品牌、正文与 muted 保留已验证配对，不用低对比度文字换取轻盈感。 |
| 时间线阅读节奏 | 常规卡片 16 / 20px 内边距、16px 间隔；≤850px 为 12 / 16px 与 12px 间隔。时间与圆点按首行元信息对齐，标题 16px / 600，摘录 14px / 1.75。 |
| 稳定的交互位置 | 卡片 hover 仅改变表面，不上移；移除持续录音扫光，保留真实录音文字、静态底色、状态点与共享兔子动效。reduced-motion 关闭卡片过渡及既有非必要动态。 |
| 长文阅读层 | 详情正文 15px / 1.75，时间与来源 12px；人物 / 来源 / 修正标记组成可换行信息组，修正入口保持右侧独立位置。长人名允许换行，不挤出正文。 |
| 标题与播放器 | 日期、选中导航、详情标题采用 600；普通导航 500。详情中文标题保持正常字距，播放器间距 12px，操作组 8px，来源选择器使用 control 圆角。 |
| 焦点的视觉表达 | 按钮、表单、原生 summary 保留清晰焦点环；仅程序聚焦且不进入 Tab 序列的静态弹层标题不绘制浏览器默认外框。 |

[实施证据](research/2026-10-22-design-system-implementation.md)包含同数据前后截图、长中文 / 长姓名 / 跨日场景、三尺寸与断点结果。未把这次两个样板的完成宣称为所有页面审美与全应用无障碍认证。

### 10.2 可执行检查

- **类型与代码**：前端实现变更运行 `npm run typecheck`、`npm run lint`、`npm run build`，以及对应行为回归。不要为纯颜色或间距修改编写只断言 CSS 字面值的测试。
- **交互**：完成一条真实任务路径，并检查键盘焦点、表单草稿、busy / 未知结果、关闭恢复及滚动。弹层不能只做打开后的静态截图检查。
- **对比度与 token**：检查未定义变量、裸色 / 字号的新增及实际前景背景配对；可使用[审阅计算脚本](research/evidence/2026-10-22-design-system/audit.py)辅助，不把其静态扫描当作完整无障碍审计。
- **视觉**：同一数据、窗口、缩放和状态下比较前后；检查主锚点、对齐、行长、功能文字、命中区、焦点、浮层和长内容。减少动态效果下单独检查静态反馈。
- **原生**：在签名版 macOS 中用 computer use / 真机完成相关任务。浏览器 mock 无法证明系统权限、真实录音、支付调用、窗口命中或像素素材在真实屏幕上的行为。
- **文档**：纯规范变更检查链接、token / 组件名称、已确认行为保留与目标 / 现状区分；不把未执行的前端或原生测试列为已通过。

已有 `scripts/test_settings_interactions.html` 可用于设置回归；`scripts/test_date_navigation.html` 已修复 F8；`scripts/test_design_suite.html` 可串行运行隔离界面回归。`scripts/verify.py` 的现有自动检查不包含完整浏览器视觉验收，不能仅凭其成功省略上面的相关场景。

### 10.3 证据与完成定义

每份视觉或交互证据至少记录提交 / 工作区状态、组件入口、模拟或真实数据、窗口尺寸、平台、缩放 / DPR、操作步骤与结果。历史截图保留历史身份，不把旧分支的“当前样式”作为今天的基线。

一个设计改动完成，需要同时满足：

1. 规则已落在 token、公共组件或明确的场景契约中，没有重复的临时真相来源。
2. 相关调用方已迁移，旧选择器 / 重复行为已清理；现有数据与请求流程没有被视觉层接管。
3. 相关窗口、内容状态和键盘路径通过检查，失败与未知结果仍能恢复。
4. 适用的浏览器及原生证据已记录；未验收的部分明确保留状态，不写成全部完成。
5. 实施后更新第 9 节条目并链接验证依据；审美候选采纳后更新第 3 / 6 节，研究预览继续作为历史对比。

评审时应能具体回答：用户先看到什么、下一步怎么操作、键盘如何完成、失败后保留什么、最小窗口如何滚动。不能只用“更高级”“更简洁”作为通过理由。
