# Hear 设计系统深度审阅与视觉打磨方案

日期：2026-10-22。代码基线：`0666e02` 及当时工作树。性质：**现状审阅与下一步方案，尚未替代正式设计规范**。

正式规范仍为 [`specs/DESIGN.md`](../DESIGN.md)，生产数值仍以 [`src/tokens.css`](../../src/tokens.css) 为准。本次仅新增研究报告、审阅证据与隔离预览，未修改生产代码。

## 1. 判断与方向

Hear 已有可辨认的设计语言，也有相当具体的业务交互规范。灰绿背景、白色内容表面、深绿色操作、像素兔子，以及围绕真实时间组织声音和现场记录，彼此是协调的。继续沿用已经选定的 C「无描边色块」方向是合理的。

当前更接近**有设计语言和部分公共控件的产品界面**。距离完整设计系统，还缺少三件事：

1. **统一的组件契约**：外观类似的弹窗、按钮、标签页，应该有同样的尺寸、焦点、键盘、忙碌和错误行为。
2. **完整的语义映射**：颜色和字号不仅集中存放，还要明确何时用、何时不能用，以及实际背景上的可读性。
3. **可以反复检查的样例与验收**：真实组件、稳定模拟数据、窗口尺寸与异常状态共同构成基线。

后续审美方向建议定义为：**安静、可信、带一点生命感的声音手账**。视觉重心依次是日期、事件内容、正在记录的事实，最后才是处理工具。精致感来自对齐、文字节奏、稳定反馈和少量品牌细节，不需要全面更换界面风格。

## 4. 需要优先解决的实现问题

以下 P1 表示建议在大范围视觉打磨前处理；P2 表示应纳入设计系统收敛。它们是本次设计审阅优先级，不是安全漏洞等级。

### F1 · P1：弹层外观已经统一，交互行为仍分成两套

**证据**：[`Controls.tsx:103`](../../src/Controls.tsx#L103) 的 Modal 使用 `dialog.showModal()`，处理 Escape、busy 和关闭后焦点恢复。设置与人物的新弹窗已经复用它。

但 [`App.tsx:965`](../../src/App.tsx#L965) 的评论、1016 行的事件编辑、1092 行的事件工具，以及 [`WorkspaceViews.tsx:780`](../../src/WorkspaceViews.tsx#L780) 的导出/清理仍使用 `div.modal-layer`。它们没有同等的模态焦点管理。详情采用 [`DetailDrawer.tsx:722`](../../src/DetailDrawer.tsx#L722) 的遮罩加 section；截图预览虽声明 dialog，也没有配套的完整焦点生命周期。

**实测**：在设置测试页打开「导出」，焦点仍停在背景「导出」按钮；按 Tab 后进入背景「清理」按钮；按 Escape 弹窗仍然存在。此行为不受窗口尺寸影响。

**影响**：鼠标用户看到模态遮罩，键盘用户却仍在背景操作，视觉与交互含义不一致。现在的设计规范不能由公共组件保证。

**实施路径**：把普通表单迁移到现有 Modal。迁移前为 Modal 补充显式初始焦点、说明区域、关闭原因和 busy 策略；textarea 表单不能继续只查找第一个 input。危险确认优先聚焦取消或说明。详情与图片预览共用模态基础行为，但保留各自布局与滚动。嵌套浮层只允许最上层消费 Escape。

**验收**：打开后焦点在弹层内；Tab/Shift-Tab 不进入背景；Escape 遵循 busy 契约；关闭回到触发控件或合理替代位置；模态具有可读标题。这与 [W3C 模态对话框模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) 一致。

### F2 · P1：焦点与部分提示文字没有达到所需对比度

计算直接基于 [`tokens.css`](../../src/tokens.css)，不取截图上的抗锯齿像素。

| 前景 token | 白色 surface | 灰绿 canvas | 判断 |
| --- | ---: | ---: | --- |
| text `#25352e` | 12.90:1 | 11.53:1 | 正文充足 |
| text-secondary `#556b5d` | 5.76:1 | 5.14:1 | 辅助正文可用 |
| text-muted `#586a5d` | 5.78:1 | 5.16:1 | 可读，但与 secondary 明度几乎相同 |
| text-faint `#819286` | 3.29:1 | 2.94:1 | 不适合普通信息文字 |
| focus `#81aa8f` | 2.60:1 | 2.32:1 | 自定义焦点轮廓偏浅 |
| warning `#a96d4d` | 4.22:1 | 3.77:1 | 不适合普通字号的警告正文 |
| danger `#a85e58` | 4.77:1 | 4.26:1 | 白底可用，不能推定所有背景都合格 |

实际问题包括：全局 `button:focus-visible` 和输入焦点使用 focus；[`App.css:1419`](../../src/App.css#L1419) 的原文操作按钮与 2032 行的弹窗警告文字使用 warning；2276 行的说话人搜索占位提示和 799 行的内容缺失提示使用 faint。

**修正方向**：将“状态标记色”“状态文字色”“状态背景色”分开。warning 正文可先复用现有 warning-strong；焦点建议采用更深的绿；有信息含义的占位提示使用 muted。保留灰绿浅表面，不必为所有卡片重新加边框。

普通文本的参考要求为 4.5:1；识别控件状态所需的非文本信息通常为 3:1。无描边按钮本身并不自动违规，足够清晰的文字或图标也可以识别操作。[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

### F3 · P2：有一个实际未定义的 token

[`usage-statistics.css:146`](../../src/usage-statistics.css#L146) 引用了 `--weight-medium`，而当前生产 CSS、TS、TSX 没有定义它。该声明在计算值阶段失效，tooltip 数字不能得到一个有保证的 medium 字重。

修复应在设计上选定 500 或已有 600，然后定义或替换。不要为所有缺失值统一加 fallback 掩盖问题。扫描中发现的 `--entry-band`、`--entry-rabbit-*` 等变量由 `entry-api.ts` / `FloatingWidget.tsx` 动态注入，**不是缺失 token**。

### F4 · P2：功能文字使用了只适合附属标识的 11px

正式规范要求 12px 以下只用于附属标识，但 [`App.css:1396`](../../src/App.css#L1396) 的 text-action、1441 行的行内编辑按钮、1808 行的保存笔记按钮均使用 `--type-micro: 11px`。说话人浮层的若干操作也使用该字号。

这不是“所有桌面文字都应放大”的结论。建议时间刻度等低频附属信息可以保留 11px；用户要读懂并点击的动作至少 12px，常规操作 13–14px；桌面紧凑操作目标建议至少 28px 高。字号、命中区和行距应分别定义。

### F5 · P2：标签页有视觉规则，但语义与键盘契约不完整

[`DetailDrawer.tsx:851`](../../src/DetailDrawer.tsx#L851) 使用 tablist/tab/aria-selected，但没有对应 panel 关联、选中项的 roving tab stop 或方向键切换。队列页则使用外观相同的按钮与 aria-pressed。`SegmentedOptions` 的 radio 组具有另一种明确语义，不能简单合并为万能切换器。

建议建立两个公共模式：**Tabs 切换内容面板；SegmentedControl 选择一个值**。Tabs 统一 id、aria-controls、tabpanel、键盘和焦点规则。队列 / 统计与转录 / 音频信息按 Tabs 迁移；兔子位置继续保留 radio 选择。

### F6 · P2：最小窗口高度存在两个事实源

[`tauri.conf.json`](../../src-tauri/tauri.conf.json) 允许最小 760 × 540；[`App.css:82`](../../src/App.css#L82) 却把 app-shell 的最小高度设为 600px。

在 760 × 540 隔离窗口测得根页面为 760 × 600，app-shell 高度为 600。这会额外产生页面级溢出，破坏“主区域独立滚动”的预期；不据此推断所有底部控件都不可达。

建议继续尊重 540px 的现有窗口契约，让 shell 服从 viewport，给实际滚动区域设置 `min-height: 0`；长内容在所属区域滚动。详情窄窗保留双栏是现有明确产品选择，无需趁机改成移动端单栏。修复后检查 760 × 540、850px 附近和 1120 × 760。

### F7 · P2：token 集中化仍有可见的例外和不明确的角色

- `usage-statistics.css:2–5` 自行定义 4 个色值，尚未进入统一 token 文件。它们属于数据系列色，应该有稳定的系列语义与文字/线型补充。
- `entry.css` 有 8 处裸字号，统计图另有 1 处。常驻菜单的 15px 是明确设计要求，应命名为对应角色，而非强行改成 14px。
- `--color-text-secondary` 与 muted 明度近乎相同；strong 比普通正文更浅。它们并非自动构成缺陷，但当前命名容易让实现者误以为层级会自然成立。
- 字号 token 共 13 个，间距阶梯 14 个。问题不在数量，而在页面仍靠局部 padding、字体与选择器覆盖形成实际样式。

建议保留已有语义 token，补用途与禁用场景。把重复控件尺寸、正文排版和反馈配色变成组件规则。时间轴比例、原生屏幕几何、像素素材固有调色板不要机械 token 化。

### F8 · P2：现有浏览器验证入口已出现陈旧样例

直接打开 `scripts/test_date_navigation.html`，当前 App 停在首次设置错误态：`Cannot read properties of null (reading 'completed')`。原因是该样例没有模拟 App 新增的 `onboarding_status`，尚未进入日期回归流程。**这是测试夹具陈旧，不是已证明的生产首次设置故障**。

`scripts/verify.py` 会运行 `.mjs` 回归，但明确将 browser visual acceptance 列为排除项。原有样式对比 README 还把历史基线 `7825429` 的 A 称为“当前”，详情是简化原型，设置和人物不在范围。它可以保留为历史决策材料，不能充当今天完整设计系统的验收证据。

建议建立共享 mock 契约，并把常用交互样例加入可执行入口。每份视觉基线记录提交、组件、数据、窗口和运行环境。先修复已有样例，再决定是否需要额外工具。

## 5. 下一版设计规范建议

### 5.1 设计原则及视觉预算

| 原则 | 可执行规则 |
| --- | --- |
| 内容先被读到 | 页面只保留一个主视觉锚点；事件标题与正文强于来源、状态和工具 |
| 绿色承担意义 | 大面积用低饱和表面；深绿用于操作、选择和必要强调；暖色留给需注意的状态 |
| 表面表达分组 | canvas、sidebar、surface 三层为主；嵌套内容优先留白和信息分隔线，不再叠白卡 |
| 状态表达真实 | 录音、云任务、保存操作分别呈现；处理中/未确认不能画成已完成 |
| 品牌集中出现 | 兔子承担生命感；正文、图表和设置保持清楚稳定 |
| 操作可被预期 | 同一种动作尺寸和反馈一致；悬停不改变布局；关闭后能继续原任务 |

浅色是当前产品范围。常驻入口的深色表面属于特定场景，不应据此把主窗口改成深色，也不需要在本轮增加主题切换。

### 5.2 色彩与材质

继续使用现有三层表面和品牌色。建议试验的数值已经单独放入预览 `polish.css`，以下是**候选值而非已批准替换**：

| 角色 | 当前 | 候选 / 规则 |
| --- | --- | --- |
| 页面 | `#f0f3ee` | `#f3f5f1`，稍减整页绿色浓度 |
| 侧栏 | `#e7ede3` | `#e9eee5`，保留与内容区的区分 |
| 内容表面 | `#ffffff` | 保留 |
| 品牌主操作 | `#215d50` | 保留 |
| 正文 | `#25352e` | 可试 `#29382f`，不以变浅为目标 |
| 功能辅助文字 | secondary / muted | 对实际表面满足可读性；通过字号、位置和字重区分角色 |
| 焦点 | `#81aa8f` | 预览使用 `#39745a`，最终逐背景验证 |
| 警告文字 | 混用 warning | 优先复用 warning-strong；不要借截图类别色表达错误 |
| 图表 | 组件内 4 个色值 | 移到 tokens，定义次数、输入、输出、缓存、成本的稳定映射 |

普通卡片维持无装饰边框；信息分隔线、输入焦点和选中指示仍然存在。阴影限定给浮层、抽屉和原生入口；背景与文字对比度按实际相邻色验证。

### 5.3 排版

字体继续采用现有系统字体栈，中文使用系统中文字体。用固定用途约束字号；短标签、时间数字、大段中文不共享同一种字距。

| 文本角色 | 建议起点 | 使用范围 |
| --- | --- | --- |
| 日期锚点 | 32px / 600 | 时间线当前日期，保留现有特色 |
| 页面标题 | 22px / 600 | 设置、队列、人物 |
| 区域或事件标题 | 16px / 600 | 卡片标题、设置分组、现场记录 |
| 操作文字 | 13–14px / 500–600 | 按钮、选择器、标签页 |
| 列表正文 | 14px / 400，行高 1.6–1.75 | 卡片摘要与说明 |
| 长转录正文 | 15px / 400，行高 1.75，作为候选 | 详情主阅读区，先验证窄窗密度 |
| 元信息 | 12px / 400–500 | 来源、时间、状态、说明 |
| 附属刻度 | 11px | 非关键时间刻度等，不用于保存/修改操作 |

时间、容量、成本使用 tabular-nums。中文正文不使用紧缩字距；页面标题至多轻微收紧。当前 `--tracking-tight: -0.055em` 适用于英文品牌等局部角色，不应泛化到中文。

### 5.4 空间、形状和窗口

- 保留现有间距 token，不重新编号。组件常用节奏优先 4/8/12/16/20/24/32；2/6px 留给图标、标签等光学校正。
- 常规卡片内边距 16–20px；窄窗可降到 12–16px。相邻记录间隔 12–16px，跨分组 24–32px。先维护内容密度，再局部扩大呼吸空间。
- 常规按钮 32–36px 高，紧凑按钮 28px 起；图标自身约 16–18px，与命中区分开。特殊原生入口遵循现有几何规则。
- 圆角角色固定：8px 小控件、10px 标准控件、12px 内容卡、16px 浮层/大分组；药丸只用于确有必要的标签或选择器。
- 保留侧栏 184 / 104px，详情宽度与窄窗双栏契约；本轮不改变信息架构。
- 最小 760 × 540 的 UI 必须通过实际滚动和控件可达性验证。主页面、详情正文、现场记录的滚动归属各自清晰。

### 5.5 控件与状态

| 组件/模式 | 必须明确的契约 | 现有起点 |
| --- | --- | --- |
| Button / IconButton | 语义、尺寸、icon、hover、pressed、focus、disabled、busy；图标按钮强制可访问名称 | 当前各 button class 与 Controls.Icon |
| Field | 可见 label、提示、error、描述关联、disabled、草稿、提交方式 | CloudKeyInput、设置表单 |
| Switch | 已确认值、busy、操作失败；即时保存不等同于乐观成功 | Controls.Switch + useSettingMutation |
| SegmentedControl | 单值选择，radio 原生键盘；与 Tabs 分开 | SegmentedOptions |
| Tabs | panel 关联、方向键、选中项焦点、内容加载规则 | 详情与队列现有 tabs |
| Modal / Drawer / Popover | 初始焦点、关闭方式、恢复焦点、背景阻断、嵌套层级与滚动 | 原生 Modal；SpeakerPicker 的部分行为 |
| SettingRow | 标题、状态、描述、右侧操作、换行；不由行组件保存配置 | 设置页已有 setting-heading |
| StatusLabel | neutral / recording / processing / warning / error；文字与颜色配对 | CaptureStatus、任务状态、事件状态 |
| Empty / Error / Loading | 首次加载不显示空；错误不伪装空；刷新保留已有内容 | LoadBoundary、详情骨架 |
| Feedback | 成功短反馈、错误就地、结果未知待确认；避免全部塞 toast | 当前业务 owner 与回执流程 |

必须保留已有产品例外：首次设置的 compact 密钥框使用回车/失焦验证，设置页则显式「验证并保存」。这是现有明确契约，不应被统一组件擅自抹平。设计系统需记录例外、原因和适用场景。

### 5.6 动效与图标

120ms 用于 hover/pressed；180ms 用于轻量弹层；300ms 用于日期布局过渡。各处引用现有 token。动态数字不抖动；保存成功不使按钮宽度来回变化；减少动态效果时保留可读静态状态。

日期动画和兔子共享实现已经较成熟。可以试验降低实时记录卡的持续扫光，让兔子承担主要常驻动效；这是对现有规范的**审美调整提案**，不是现有实现违规。预览为此关闭了卡片扫光，生产未改。

继续扩展当前线性 SVG 图标系统即可。统一常用图标的 viewBox、1.6–1.8px 线宽及视觉尺寸；清理局部 `×`、`＋`、`···` 字符图标与 SVG 混用。无需为这一点更换整个图标库。兔子素材与 UI 图标分属两套资产规范，保持已确认角色外观。

### 6.3 Button 的边界示意

```tsx
import type { ComponentPropsWithoutRef } from "react";

type ButtonProps = ComponentPropsWithoutRef<"button"> & {
  tone?: "primary" | "quiet" | "ghost" | "danger";
  size?: "compact" | "default";
  busy?: boolean;
};

export function Button({
  tone = "quiet", size = "default", busy = false,
  disabled, type = "button", className = "", children, ...props
}: ButtonProps) {
  return (
    <button
      {...props}
      type={type}
      className={`ui-button ${className}`}
      data-tone={tone}
      data-size={size}
      disabled={disabled || busy}
      aria-busy={busy || undefined}
    >
      {children}
    </button>
  );
}
```

这是最小接口示意，不是完整库实现。busy、提示文案、提交请求和重试仍由调用方提供；Button 不启动异步任务，不建立计时器，也不猜测业务完成。`IconButton` 再用类型约束要求 `aria-label`。已有“结果未知，确认上次结果”等流程继续由其业务 owner 管理。

## 8. 交付顺序与验收门槛

### 批次 A：补齐系统基线

处理 F1/F2/F3：统一普通 Modal，修焦点与提示文字，补 token；修复陈旧样例的启动契约。先完成无样式变化的行为迁移，再调整颜色。

完成条件：所有普通模态通过打开/Tab/Shift-Tab/Escape/恢复焦点/busy 检查；已使用的普通文本色对通过实际背景校验；未定义 token 为零；既有设置 32 项回归继续通过。危险操作不因统一组件减少确认或丢失草稿。

### 批次 B：收敛公共控件与布局

Button、IconButton、Tabs、Field 的第一轮迁移；拆分相关 CSS；修复 540/600 高度冲突；统一小字操作与常用命中区。

完成条件：四种按钮语义在各页面一致；所有 tab 有明确内容关联；最小窗口不因 shell 固定最小高度产生额外根页面溢出；普通页面与浮层滚动符合各自契约。

### 批次 C：完成一个真正精致的纵向样板

先打磨“时间线 → 打开事件 → 阅读转录 → 写现场笔记 → 返回”的完整路径。用本次隔离对比验证颜色、文字与卡片节奏，然后把选定值写回正式 token / 组件。

完成条件：常规、长标题、多说话人、跨天、空、首次加载、读取失败、保存失败、后台刷新、减少动态效果都有可复查场景；1120 × 760 和 760 × 540 通过视觉检查。没有新增截图-only 的假组件替代真实实现。

### 批次 D：推广与固化

将样板推广至人物、设置、队列/统计和首次设置；对常驻入口做安装版验证；整理正式 DESIGN 文档。

完成条件：每个公共组件有用途、变体、状态、键盘、代码入口和至少一个真实示例。截图记录基线提交与尺寸；组件变更同时更新例子和相关规范。PR 验收能够说明“在哪个状态、哪个尺寸、哪个真实组件上验证过”。

### 建议的固定场景集

| 类别 | 最少覆盖 |
| --- | --- |
| 数据 | 正常、空、长文本、中文英文混排、多说话人、跨天 |
| 读取 | 首次加载、独立区域完成、刷新保留、读取失败、范围切换 |
| 操作 | 默认、hover、focus-visible、pressed、disabled、busy、失败、结果未知 |
| 键盘 | 主路径全程可达；弹层焦点与恢复；Tabs；日历；图表日值读取 |
| 尺寸 | 760 × 540、1120 × 760、1440 × 900，额外检查断点附近 |
| 原生 | 标题栏拖动/红绿灯、入口命中区、1×/2×、减少动态效果、隐藏窗口 |

对焦点、状态和窗口尺寸建立行为断言；视觉快照负责捕获意外变化。审美验收仍需看真实内容，不能只以截图像素一致替代设计判断。
