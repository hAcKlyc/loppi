# 事件 Prompt 的真实数据回放评估

先看[评测报告](REPORT.md)：16版、19轮、216次调用，目前未达到稳定通过；完整12例结果与逐窗JSON在报告中链接。

本目录记录一次隔离评估，不替换生产 `FIT_SYSTEM`。候选按任务、完整 JSON Schema、通用约束和示例组织；Schema 是文本提示并由离线审计器严格验证，不冒称供应商开启了强制结构输出。

## 固定方法

- 12 个真实选定时间段，跨度约 0.5–81 分钟。3 个长于 15 分钟，含口述、对谈、上门服务、混合录音和分享会。原有自动事件标题只用于找到素材，原粗转才是语义依据。
- 模型输出前冻结输入与每例必保事实、禁错项；2 例首次在候选冻结后调用。若用于进一步调整，则不再称其为未见样本。
- 每个样本从空隔离库开始，复用生产窗口规划、输入映射、模型适配、增量合并及发布事务。只拷贝选定范围的粗转和音频块元数据，不执行录音、ASR 或回写活跃库。
- 同一配置模型 `deepseek-flash`、生产基线 low thinking（显式 high 仅为隔离对照，单独记录）、单窗单次调用，默认60秒请求预算。因长窗多次在60秒中断，可显式指定 `--deadline-seconds 120` 分离内容质量评估；审计独立报告生产60秒预算是否通过，不能据此宣称已适配生产时限。初始回放无自动重试；失败原样保留。
- 最终同一候选需连续两轮全量结构和质量通过；不要求随机模型逐字相同。仅证明样本内复验，不估计普遍成功率。

## 两层验收

结构检查包含：原始响应是否存在重复键；Schema；活动范围和音源；发布是否丢弃模型事件/条目；引用归属；替换编号及当前窗证据；未修改旧条目的内容与引用是否完整保留；最终导出与 SQLite 是否一致；单次调用及时间预算。

质量必须人工逐项看原文与结果，不能用关键词命中或 JSON 合法代替：

1. 各主要话题的关键事实与后续安排是否可查。
2. 时间、数量、否定、假设、已完成/待办状态是否保真。
3. 是否把未知主体、猜测、转述补成确定事实。
4. 同一连续活动是否被按话题错误拆开；不同活动是否被误合并。
5. 多窗摘要是否从整场内容取舍，而非只描述最近一窗；未变更要点是否保留。
6. 摘要是否有辨识细节且不过度重复；约 500 字是上限指导，不为短材料凑长度。

粗转本身的错漏、人名品牌识别及外部事实真伪，不通过凭空补全解决。无法确认的部分应省略或保留不确定性。

## 文件与运行方式

- `prompt-v*.txt`：不可覆写的候选版本，保留失败版本。
- `output.schema.json`：与候选提示一致的结构契约。
- `private/cases/`：冻结粗转、来源、事实标准。
- `private/runs/<round>/`：本轮 prompt/schema/二进制指纹、每窗输入、供应商原始响应、模型 JSON、入库快照、耗时、用量、结构审计与人工核对材料。
- `private/iteration-notes.md`：逐轮问题和修改理由。
- `private/auditor-selfcheck.json`：故意破坏重复键、引用、存储/导出等输入，确认审计会拒绝。

可选 `--deadline-seconds 120` 和 `--reasoning-effort high` 仅改变本次隔离调用；默认仍60秒/low。high结果不得宣称为生产low的通过证据。

使用安装了 `jsonschema` 的 Python 环境。Core 的忽略测试入口须构建为已有正确签名的隔离测试包，使其沿用 Keychain 访问；不要导出密钥或改变权限。

```sh
python scripts/evaluate_event_prompt.py run \
  --root specs/research/2026-10-24-event-prompt-evaluation \
  --round <new-round> --prompt <candidate-file> \
  --binary <signed-test-binary> --workers 2 --allow-paid

python scripts/evaluate_event_prompt.py audit \
  --root specs/research/2026-10-24-event-prompt-evaluation \
  --round <existing-round>
```

`run` 必须显式带 `--allow-paid`，轮次目录不得已存在。`audit` 只读隔离库，不调用模型；产生 `quality-review.md` 供人工复核，绝不自动把质量标成通过。

真实记录及完整评测输出均在 Git 忽略的 private 目录；公开版本仅保留通用提示、工具和方法。
