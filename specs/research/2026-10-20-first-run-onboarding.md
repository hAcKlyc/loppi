# Hear onboarding：双云必配的简洁方案

日期：2026-10-20。状态：页面与流程讨论方案，尚非可直接开发的 PRD。

讨论已收口为[单页首次设置 PRD 草稿](../prd/prd_0.1_onboarding.md)。本报告保留现状审计和设计演进；交付范围、默认行为与架构边界以该 PRD 为准。

用户已确认：「那就保留这两个云服务的配置门槛，先不做统一云服务。按这个思路，把 onboarding 的页面和流程重新梳理一下，尽量简洁干净。」

用户进一步明确：「试一下这个页面都不用吧…」。本文改为单页准备，取消独立试录及其引导流程，替代此前多页方案。现状依据当前工作树，未执行全新安装、系统授权或真实录音；底层可用性仍需签名安装版验证。

## 1. 当前方案

**一个页面：准备 Hear → 首页 → 用户点击开始记录。**

保留本地语音模型与两个云服务的首次启用门槛，至少一个用户选择的声音来源可用。不提供可跳过云配置的长期本地模式，不建设统一云服务、账号或收费后台。

取消独立欢迎页、试录页、成功页和必经功能教学。模型准备、来源权限、两个 API Key 集中在同一页；完成后进入正常首页，用户通过已有入口明确开始记录。用户中途离开时保留进度，下次只补未完成项。

“简洁”通过减少页面、提供默认值和折叠帮助达成，不通过隐瞒必需条件或承诺尚未完成的能力达成。

## 2. 当前真实路径与缺口

```text
下载 DMG → 拖入 Applications → 启动 → 时间线
  → 看到「尚未就绪 / 在设置中完成准备」
  → 自行进入设置，处理权限、模型、两项云凭据、登录启动
  → 返回时间线，明确开始记录
  → 等待数据、粗转和云端结果
```

这是一条根据代码拼接的操作路径，不是一套已实现的向导。

| 环节 | 已有实现 | 主要缺口 |
| --- | --- | --- |
| 安装包 | macOS DMG 包含应用与 Applications 入口；有签名、公证、装订、检查脚本；配置最低 macOS 13.0 | README 报告测试 DMG 已完成公证，但全新 Mac 安装验收仍待完成；缺少运行位置检查与安装不完整的用户恢复流程 |
| 初次启动 | `App.tsx` 初始页面是时间线；创建数据库与后台核心；首次 `enabled_intent=0`，不会仅因全新启动就开始持续录音 | 没有首次引导页面、可恢复进度、完成定义或欢迎后的首个任务 |
| 模型 | 设置页「准备模型」触发后台下载；语音与声纹状态分开 | 需要用户自己找到；没有完整体积、空间、失败原因、下载取消、断点续传及安装后的运行自检体验 |
| 麦克风 | 前台请求系统权限；能读到授权状态；授权后展示来源开关 | 拒绝/受限制等状态主要归为「需要系统授权」；再次点请求不会必然再次弹窗，缺少明确的系统设置引路 |
| 电脑声音 | 按系统版本选择前台 Tap 探测或屏幕采集授权；可重新验证 | 用户须理解为什么录声音可能要屏幕相关权限；已完成设置不是当前采集必然可用 |
| 云端 | DeepSeek 与火山 ASR 分别验证并写入 Keychain；验证失败不替换旧凭据 | 首次开始强制两项都配置，普通用户须先理解 API Key、开通服务和付费关系 |
| 试录 | Core/CLI 有 Probe、RecordTest，能探测声音/保存短录音 | 已有诊断能力可继续保留；按本轮决定不新增面向新用户的试录流程 |
| 后台运行 | 设置里可注册登录项；主窗关闭隐藏；完全退出发送 Quit | 没有在第一次使用时解释关窗、暂停、完全退出、登录启动之间的差别 |
| 数据与空间 | 数据目录在用户 Application Support；音频默认上限 10 GiB；接近上限/磁盘不足会提示或暂停 | 用户在第一次开始前不知道保存位置、容量边界、如何清理及哪些内容会外发 |
| 首条内容 | 有时间线、真实音频和本地粗转 | 默认 `hideCoarse=true`；纯本地未命名条目在停止实时记录后可能被隐藏，影响首次价值闭环 |
| 恢复设置 | 设置里有部分重试/重新验证；回到前台会刷新权限等状态 | 缺少统一「继续设置 / 修复这一项」入口，也没有可区分的首次设置中断与日常故障体验 |

### 应保留的基础

- 新安装不会擅自开始持续录音，来源开关与开始意图是不同状态。
- Core 是业务事实与任务的 owner，GUI 通过统一命令使用它。
- 本地模型固定哈希验证、暂存后发布，不把半个模型当就绪。
- 云凭据先验证、再保存于 Keychain；已有密钥不读回 GUI。
- 正常采集监督不依赖网络成功，已启用后的云端故障不会直接截断本地采集。
- 两路声音独立；设置、主窗与兔子已有共享状态基础。

### 必须澄清的现状细节

1. 「两项云服务就绪」在开始动作上实际检查持久的配置与凭据引用，不是每次开始都联网验证其当前余额、网络或可用性。首次保存时确实会发起验证请求。
2. 当前模型状态主要是文件/哈希就绪，不等于目标机器已成功加载模型并完成一次推理。
3. 麦克风/系统声来源默认开启，但首次持续记录意图关闭，不能将来源开关的开启误报为正在采集。
4. 当前主窗关闭始终隐藏，没有首次设置的专用恢复流程。
5. 工作树已有记录计划的 Core 改动，不能把它推定为完整发布的设置 UI，更不应让新手流程悄悄启用计划。

## 3. 唯一引导页：准备 Hear

标题：**准备 Hear**。

说明：**完成下面的准备，Hear 就能记录声音、转成文字并自动整理。**

单列布局，只有三个分组。固定显示两家云服务，不用 LLM/ASR 切换标签隐藏另一项待办。

| 分组 | 常显内容 | 操作与反馈 |
| --- | --- | --- |
| 本地组件 | 用于在这台电脑上识别人声与生成初步文字 | 一次点击「下载并安装」，自动完成下载、校验、安装；显示阶段/进度，失败就地重试 |
| 声音来源 | 麦克风：你和身边的声音；电脑声音：会议、课程和电脑播放的声音 | 双来源推荐，可分别取消；所选来源逐项授权，至少保留一个可用来源 |
| 云服务 | 自动整理 · DeepSeek；准确转录 · 火山引擎 | 两行 API Key 输入，各自有「获取 Key」帮助、验证中/已配置/失败状态；两项必配 |

本地组件沿用现有准备入口，自动选择资源，不给用户模型列表。必要语音组件与声纹状态在后台区分；声纹不作为新增的首次录音硬门槛，异常在设置中可见。精确下载量、空间预算来自核实后的资源清单，不能把下载上限当实际大小。

权限按钮只在用户主动操作时触发，两个系统弹窗不叠发。未选择的来源不索权；某一路授权失败时可明确取消该来源、使用另一条。由系统返回后自动复查。已授权但设备不可用单独说明，不能当作未授权或静音。

API Key 沿用现有「回车或离开输入框后验证并保存」行为，验证成功存入 Keychain；失败保留输入，不覆盖旧凭据。输入框旁只显示短状态，错误才展开恢复动作。获取 Key 帮助按供应商说明开通服务、获取密钥、用量和费用，不另造必经教学页，也不让用户填写模型 ID、接口地址或资源参数。

云服务下常显两句说明：

> 整理时会发送相关文字，精转时会发送相关音频；截图理解会发送你主动保存的新截图。服务费用由对应服务商收取，连接验证也可能产生少量用量。

具体服务对应关系及详细数据范围可展开查看：DeepSeek 接收待整理文字、时间/来源及新截图原图；火山接收待精转音频；本地人物库与声纹特征不因此外发。文案不承诺全部数据只在本机。

页脚主按钮 **「完成设置」**，次操作 **「稍后设置」**。可保留一个紧凑的「登录时启动」开关，建议遵循既有 PRD 默认、允许关闭，注册结果如实展示；它不是首次使用的阻断条件。

- 「完成设置」仅在必要本地组件就绪、两项云配置已验证保存、所选来源可用且空间满足要求时可用。若保留两个来源，两者都需完成必要授权；用户可主动取消暂不可用的一路。
- 尚未就绪时显示简短剩余项，例如「还差：火山引擎配置」。已配置指成功验证并保存的事实，不承诺未来网络、余额永远可用。
- 下载与填 Key 可并行，前台授权与后台网络工作可并行，正式采集只有用户在首页主动开始记录才进行。授权所必需的短时探测须与用户触发的来源授权操作绑定，不产生试录内容，也不伪装成已完整验证录音。
- 「稍后设置」保留进度，下次继续；若进入主界面，只能浏览与继续设置，不绕过首次记录门槛。

## 4. 完成后直接进入首页

点击「完成设置」返回正常时间线，不展示庆祝页、录音教程、试录倒计时或示例内容。首页显示「尚未开始」，用户通过现有兔子/开始入口主动开始记录；完成设置本身不写入持续记录意图。

保留一句简短说明：「点击兔子开始或暂停记录，关闭窗口后仍可继续记录。」首次实际录音、文字、云整理与回放都使用正常产品界面，不另建首条试录或特殊测试数据。

准备阶段仍完成必要校验：模型文件校验/加载检查、所选来源的系统授权与可用性检查、两家云服务的凭据验证。没有人声、未实际录制或暂未产生事件时，不声称已验证端到端效果；真实采集失败在首页与设置中按现有状态体系反馈。

开始前复查模型、来源和空间等当前条件。登录启动与持续录音意图独立：即使注册登录项，只要从未明确开始，下次登录也不应擅自采集。登录项待批准/失败不阻止当前手动使用，但不能显示为已生效。

## 5. 按需处理与恢复

不增加新的必经页面：

| 事项 | 放在哪里 |
| --- | --- |
| 截图说明与权限 | 第一次点击截图时；不能成为声音记录的额外门槛，旧音频采集路径共享权限时说明原因 |
| 声纹介绍 | 第一次命名说话人时，不要求首次录自我介绍 |
| 记录计划、兔子位置、空间上限 | 设置中；沿用既有默认，不在引导里新增偏好问卷 |
| 下载/授权/Key 失败 | 原项目下面就地恢复，已完成项保持 |
| 稍后设置/中断 | 保存进度，下一次回到未完成项 |
| 老用户权限或模型失效 | 设置中只修复对应项，不重走欢迎与教学 |
| 首次完成后云端断网、凭据失效 | 本地记录与粗转继续；云任务单独等待或提示修复，不重置 onboarding |

首次双云配置门槛不应扩大为每次恢复录音都要联网成功；已有产品对完成设置后的离线/供应商故障处理继续成立。

设置与 onboarding 复用同一套真实能力状态和操作。系统版本不同的电脑声音授权说明沿用当前采集路径判断；Tap 历史成功标记不作为永久授权。下载退出/恢复、权限拒绝后系统设置路径、系统要求重开的进度保存均纳入初始化流程。

引导进度、能力就绪、持续录音意图、首次价值验证是不同事实。没有历史或清空记录都不等于重新安装。Core 沿用既有采集与数据 owner，不新建第二套录音链路或后台服务。

## 6. 视觉与完成定义

视觉沿用现有浅灰绿底、白色内容区、绿色主按钮。页面不展示常规侧栏或步骤导航，一页完成准备。页面只有一个当前主动作，已完成项目缩成简短确认状态，详细说明与诊断按需展开。错误留在对应项目，不重复使用弹窗和全局提示。键盘焦点、可访问名称和减少动态效果规则保持。

验收重点：

1. 全新用户在一页完成模型、所选来源和双云准备，无命令行操作、无试录任务。
2. 缺任一云配置时不能开始正式记录，稍后设置不绕过门槛。
3. 两家 Key 的失败、验证、保存独立；不会因填另一项丢失已成功的配置。
4. 一路来源明确关闭时不影响另一条可用来源；未验证不误报成功。
5. 完成设置直接进入首页且不自动录音；用户主动开始后沿用真实记录、转录与回放，云状态如实呈现。
6. 中断/关窗/重启不重复已完成项目，不因恢复设置而开始采集。
7. 登录启动与开始记录意图分开，完全退出及暂停沿用已有规则。
8. 已完成设置后云端故障不停止可用的本地采集。
9. 签名新安装覆盖实际支持的系统/架构及两种系统声采集路径，不使用开发机已有权限替代测试。

## 7. 决策与范围

已确认：保留双云首次配置门槛；不做统一云服务；去掉独立试录页。

本轮收敛：一个准备页、三个分组，完成后直接进入首页，正式开始复用现有入口。不把试录改成弹窗或隐藏必经步骤。具体交互仍为讨论方案，不作为已批准的执行 PRD。

保留现状审计与代码证据，撤销之前“云增强可选 / 本地长期模式 / 后补云配置历史范围”的新产品建议。本次不增加账号、计费平台、模型市场或全新本地模式。登录项默认建议遵循原 PRD；模型分发可达性、准确空间预算、安装自检需在正式 PRD/实施验证中落实；不再建设专用试录的寿命、内容保存与清理机制。

平台依据仍为 Apple 的交互教学、按需授权与登录项真实状态原则：[Onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding)、[Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy)、[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice)。
