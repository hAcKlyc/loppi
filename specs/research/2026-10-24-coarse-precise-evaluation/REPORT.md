# 同模型 high：粗转与精转三遍配对实验

**结论：这批样本中，精转改善了部分信息提炼，但本次没有出现“换成精转，问题就解决”的结果。** 预选事实的逐案例平均覆盖几乎相同；在双方输入都明确给出的事实中，精转提炼更完整。但两组仍有约四分之一的输出出现至少一处明确语义问题，精转也没有消除重复 JSON 字段、空摘要和长会议摘要遗漏。

下一步优先处理输出到保存的可靠性，再处理条件、主体、状态和整场摘要覆盖；本次不据此切换默认输入来源或模型。实验已完成，候选分析流程尚未达到稳定可用的验收标准。

## 4. Case 分析：问题到底从哪来

### A. 文本更清楚，长会的结构化细节确实更稳：c11，81.26 分钟

精转三遍的 8 项预选事实都保留了；粗转分别保留 5/8、8/8、7/8。精转有助于提炼职业规划/求职陪跑、报告看板的具体字段、增长指标和 Agent 记忆讨论。

但这不等于精转解除了误读：

- 精转第 1 遍：原文先说按人区分“记忆和人格”，紧接着纠正“人格其实一样，主要是 memory 的区分”；输出要点仍写按用户区分记忆与人格，没有吸收后一句纠正。
- 精转第 2 遍：对象描述把“长尾问法”写成“长期问法”。
- 精转第 3 遍：原文用“如果”设想进入微信群，并说目前支持私聊、加群不支持；要点却写“目前可以进微信群、任何人可私聊”。

粗转也有跨窗误更新：第 1 遍在第 4 窗将早期某参与者的分身项目改归给后文另一个名字，错误同时进入摘要、要点和对象；第 3 遍把“作者提出日报面向 Agent”与接收者说“他们的日报我拿过来……不再给 Agent 看”合成同一个人的后来转变。这些不是旧条目被数据库随机删除，而是 LLM 对旧内容作了错误替换或合并。

### B. 旧要点能保住，summary 仍会越写越偏后半场：c11

精转第 3 遍前窗 summary 曾完整保留报告看板的画像、标签、问答和资料，以及订单增长斜率；从第 4 窗开始，摘要丢掉这些细节，但结构化要点仍在。第 5 窗摘要还含“日报塞给 Agent 的反方意见”和群聊三种响应策略，第 6 窗又将它们删掉，只留下话题概括。

这说明 **“结构化增量保留”和“整场摘要覆盖”是两个不同的验收项**。当前程序保留旧要点能解决一部分遗忘；模型每窗重写 summary 时，仍可能丢早期细节或不同观点。精转并不自动解决这个问题。

### C. 模型写了内容，实际保存却丢了：c06，7.40 分钟

粗转第 3 遍原始响应有两个事件，也写出了后半段的工作要求。但第二事件开始时间被写成 `179229629176`，少一位、落在候选时间范围之外，保存前规范化把整个事件丢掉。实际保存仅剩开头 1/4 个预选事实。

因此这一例不是“粗转太差导致模型没理解后半段”，而是 **时间字段错误被局部过滤，整次任务却仍返回成功**。下一步应先阻止这种静默部分成功；不能靠延长 prompt 要求“别漏要点”解决。

### D. JSON 字段重复，可以把有内容的摘要变成空：c03 / c04 / c12

精转这三次原始输出里，先有一份非空 `summary`，随后同一个对象又出现 `summary: null`。解析采用后值，实际数据库因此保存为空。

全部 8 次严格结构失败分为：

| 原因 | 粗转 | 精转 | 实际影响 |
|---|---:|---:|---|
| 重复键 | 1 | 5 | 精转 3 次非空摘要被 null 覆盖；其余 3 次重复值相同，未损坏最终值 |
| 非法事件时间范围 | 1 | 0 | 丢弃一个事件，后半内容未保存 |
| 多余顶层 `type` 字段 | 1 | 0 | Schema 不合格，但本次内容仍保存 |

重复键本身由模型输出造成；保存链路没有把它挡成明确失败，才使部分情况变成静默内容损失。精转组这次出现更多重复键，样本不足以断言“精转导致更容易格式错”。

### E. 数字读得清楚，含义还是可能错：c09，34.42 分钟

粗转第 2、3 遍把身高对照中的“12 个月/一岁”写成孩子实际年龄；这属于比较对象与真实属性混淆。精转第 2 遍则补出了“头顶 73”的测量位置；原文能找到 73 的读数，但没有支持把它定义成该测量位置。

精转第 3 遍能完整保留最初约 73、脚后跟约 72、脚尖约 78，以及最终按脚后跟读数的关系。也就是说，精转有帮助，但同一份明确文本、同一 prompt、同一 high，三遍仍不同。不能把所有数字问题都归给 ASR。

### F. 精转也会少信息，甚至与粗转有否定差异：c10 / c08

c10 的精转英文部分缺失粗转中可见的披萨厚薄比较；三遍都没能完整提炼这一预选事实。这不是 LLM 应该补齐的任务。两组还出现不同事件拆分，说明语义内容以外，混录分场也需要独立评价。

c08 两组原始文本在广告收益讨论中出现“靠广告/不靠广告”的否定差异；模型各自沿用了自己的输入。没有听原声，不能判哪组说对，也不能把一组忠实复述其输入算成 LLM 错误。这类问题属于输入质量，应回到音频核验。

### G. 短记录也会出现无依据的身份和确定性：c05 / c12

c05 第二遍中，两组各有一次把未明确的说话人或亲属关系具体化。c12 精转第一遍将连续的“保修多少年／一两年吧／是吧”概括为“服务人员称保修期约一到两年”，补了身份并强化了确认程度。转录变清楚，并不等于可以把问句和猜测写成结论。

其余 c01、c02、c03、c04、c07 的明确核心信息整体较稳定；其中 c02/c03/c04 的精转仍各出现一次结构失败。c03 关于当前配置方案与未来自动适配设想有原话歧义，复核后统一撤销过严的“条件矛盾”判罚，没有拿精转反推粗转真值。全部裁决及原始评分保留。

## 6. 下一步方案与验收方式

按影响优先级建议如下，均是后续方案，本次没有修改生产行为。

1. **先消除静默保存损失。** 对原始 JSON 重复键、必需结构、时间范围、引用和替换关系做发布前完整验证。发现不合格时，不把部分结果或被重复键覆盖的 null 当成成功新版本；保留已有有效版本并沿用明确失败状态。需要选定“整窗拒绝”的具体契约，不猜测修复时间、不静默重试。验收先用本次 8 个真实失败响应做离线回归，做到 8/8 都可检测、无静默内容损失，不用再付费才能复现。
2. **继续沿用窗口增量，单独解决 summary 覆盖。** 用已经累积的旧要点、旧摘要和本窗纠正作为整场摘要依据，明确早期主线、后续主要议题和仍成立的分歧；避免只压缩上一版摘要。提示词先收敛成通用更新原则，再用这 3 段长记录检查每一窗前后事实变化。不要靠数据库截断或硬塞更长摘要解决。验收分别看“结构化旧事实保留”“误替换”“整场摘要主要议题/细节覆盖”，不能合成一个通过率。
3. **针对通用语义关系修正，而不是继续补样本词条。** 重点是条件/假设、问句/确认、计划/已完成、比较值/真实属性、不同人的观点/同一人的转变；同一事实在 summary、key_points、对象中不能出现不同确定程度。保留本次真实反例，下一轮仍固定模型 high、各三遍，新增未参与 prompt 调整的记录作验证，分别报告遗漏和添错。
4. **把精转作为待验证的输入策略，不直接全面替换。** 对专业词多、粗转明显损坏的长会，精转值得进一步验证；是否优先使用精转，还要核对音频中的缺词、否定以及分场效果。下一轮若要分清“文字质量”和“句段长度”影响，需另做固定分段的对照。不能用现有 12 段下结论说所有场景都应等待精转。
5. **质量改进后再决定 high 的生产预算。** 先明确允许的分析延迟和 token 用量，再用同一评测核验；本次不换模型，也不把提高 deadline 当作语义质量的修复。

建议下一轮展示同一张指标表，并增加少量人工听音核验的输入歧义样本，以及独立的“主要议题覆盖”和“纠正是否正确生效”标注。预选事实覆盖高而仍添错的情况必须继续算未稳定，不能通过调整平均权重掩盖。

## 7. 如何理解这些结论的边界

- 12 个来源案例才是配对单位，三遍是稳定性观察，不是 72 个独立人群样本。没有做显著性推断。
