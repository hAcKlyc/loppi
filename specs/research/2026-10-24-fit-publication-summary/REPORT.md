# 粗转窗口发布与摘要修复：三遍实测结果

本轮完成重复字段与非法时间的静默丢失防护，并把 summary 改为窗口内增量更新。严格结构通过由 33/36 提升至 36/36，早期已写入摘要的细节保留由 14/18 提升至 18/18；但明确语义错误由 9/36 变成 10/36，没有改善。保存和跨窗保留目标达到，整体分析仍未达到稳定正确，不能把代码验收通过说成内容质量全面通过。

## 1. 同一批数据，三遍全计入

沿用上一轮 12 段真实粗转，0.52–81.26 分钟，共 206.37 分钟；固定相同的 21 个窗口。修复前使用已冻结的 coarse 三遍，修复后每例再独立跑三遍，共 36 次、计划 63 窗。两组均 deepseek-flash / high / 120 秒；不切精转、不切模型、不修改原文、不挑最好一遍。新增机制只有原始 JSON 唯一键校验、事务前时间校验、同次调用中的摘要句子增量。

实验没有隐式重试。生产仍用既有最多三次格式重试，默认 low / 60 秒未变，本轮 high 的质量和时延不能直接视为生产默认表现。实际调用记录、响应 ID、输入/提示哈希及最终 SQLite 均核验；原始私有材料不提交 Git。

## 4. 两个保存问题怎样被堵住

**重复字段：** 之前先把原始 JSON 解析成普通对象，后一个同名字段会覆盖前一个；现在在这个转换发生前递归拒绝重复键，包括嵌套、同值和转义等价键。原始调用用量照常保留，诊断不打印正文或键名。

**非法时间：** 之前逐事件跳过坏时间，可能丢掉后半内容后仍宣布成功；现在缺失/类型错、倒序、越界和同响应同源重叠，均在写任何事件前拒绝整窗，保留旧结果。复用原格式错误的有界重试，未增加新队列或恢复器。其它可选字段/来源错误没有扩大成全 schema 生产硬拒绝。

新一轮 63 次调用没有再次出现重复键或非法时间，因此没有实际触发安全拒绝；这不能代替拒绝路径的验证。专项证据：把上轮 126 份真实原始响应送入新解析/时间校验，6 份重复字段和 1 份非法时间全部被拒绝，119 份通过这一专项检查。事务无部分写入及任务不被误标 complete 由生产发布入口回归测试覆盖。这个离线结果不代表重新调用模型 126 次。

## 5. 摘要：保住旧内容的收益和代价

模型不再每窗重写整场全文，而是返回新句或明确修订：未替换旧句保留；新句追加；替换需指向实际旧句并附本窗证据。数据库仍保存一个完整字符串，没有新持久分段、第二次总结调用或字数截断。

本批实际摘要共追加 275 项，显式替换为 0 项。真实回放证明的是默认保留与追加，不能据此宣称测出了真实纠正成功率；三窗明确更正、非法替换不删旧句的路径由生产入口回归测试单独验证。

81 分钟长会第一遍最终摘要仍完整写出早期的职业规划/求职陪跑分身、看板的画像/标签/问答/资料链接，以及收入波动转向订单数和增长斜率；随后也覆盖秘书与看板争论、日报和群内响应、空间记忆。原来后窗重写造成的早期具体字段丢失，在此例得到改善。全部三遍早期事实的逐窗评分见私有评分与汇总表，未只选这一遍。

但“旧句留下”不等于“新信息必然提炼”：第二遍摘要没有写出精灵曾撤下电脑、后来重配云电脑，结构化要点仍有这项。它不是先写出再被后窗抹掉，而是摘要从未完整表达。

还有明显长度代价：长会三遍分别 2523、2545、2301 字符，近似逐窗累加详细纪要；第一窗的“最后”等衔接词在后续追加后也可能不再顺畅。当前遵守不硬截断的范围，但不能把这当作约 500 字的成熟快速定位体验。下一步如要压缩，应另定义保留哪些辨认细节及如何衡量压缩损失，而非恢复每窗随意重写旧句。

## 6. 尚未解决的语义案例

- c11 第一遍：把“日报作者想将内容 agent 化”和另一位参与者“更重视自己的第一大脑、不盲目塞上下文”的回应接成同一人的想法。不同观点仍被错误归属，事实 F6 扣分。第二遍另有要点把分身承担的“替代本人咨询”角色写给了看板。
- c09：比较读数对应的“12 个月/一岁”仍可能写成孩子实际年龄；第二遍把“十一之后”误写成“11日之后”，且初始 73 没进入提炼结果。后两项属于误读/首次遗漏，不是跨窗删除。
- c10：原文 if 现场表演的设想被写成实际经历；有一遍详细句保留了条件，但总起句仍写“经历”，按与基线一致的尺度计错。
- c05 第二遍：把所在楼栋的一个居民群扩大成“小区只有一个居民群”，并漏掉加入群的动作。

这些问题需要对条件、主体、时间范围作更好的通用理解。本轮没有加入样本中的日期、人物或业务名规则；也没有因为坏输出被安全拒绝就把它算作正确结果。
