# Design renewal Review Contract

1. **Mode:** repair, staged fresh-context review. Reviewers are read-only and do not spawn agents. The main agent adjudicates and repairs.
2. **Requirement:** `specs/prd/devplan_261031_design-system-renewal.md`, historical discussion D8–D10 in `specs/prd/_drafts/loppi-design-identity.md`, and core `specs/DESIGN.md`. User authorized completing all six design packs, applying the design across the existing product, producing a new package and restarting the installed app. Latest explicit correction: preserve the original one-folded-ear/one-upright-ear, tilted-head product ICON exactly; the two-upright-ear listening animation is independent.
3. **Target/baseline:** final working-tree candidate against `18a3f77681f36597ba26d03adeffed27b13f11b4` on `codex/loppi-design-system`. Rename was already committed at baseline. No business-backend changes.
4. **Exact scope:** tracked diff plus new files listed in sibling `review-scope.txt`. Includes design history, normative docs, formal resources, shared tokens, frontend presentation changes, version 0.1.15, asset/preview exports and affected regression fixtures. Generated raster/inline preview files can be assessed through their sources, hashes and representative visual inspection rather than mechanically reading minified bundles.
5. **Out of scope:** no known concurrent edits. Ignored build outputs, signing configuration, credentials, user records, installed app and temporary test logs are outside the code diff. Do not modify or expose them.
6. **Guarantees:** approved paper/ink, completed green, live coral, simple dark rust i dot; existing ICON preserved byte-for-byte; coherent existing pages/entry, readable text and keyboard focus, supported 1120×760 and 760×540; editable vector wordmark, reusable role/icon/token exports, truthful concise docs, offline synthetic preview and privacy-safe release materials. Preserve existing behavior, data, credentials, paused/source preferences and Core ownership. **Non-goals:** new IA/top navigation, new features, new dark main theme, audio/ASR/data policy refactoring, website, public release/license selection, extra reliability guarantees or long-duration platform certification.
7. **Owned defects:** introduced or materially exposed issues under these guarantees, plus explicit design/document/asset requirements. Unchanged adjacent behavior is non-blocking unless materially exposed. Distinguish concrete defects, required evidence gaps and optional coverage.
8. **Allowed architecture additions:** none in production. Reuse Controls/Rabbit, existing timeline/live projections, capture status, details, existing pages and FloatingWidget. New build-time exports and isolated mocks are allowed; no new runtime owner/store/protocol/retry/fallback/dependency.
9. **Required lenses:** requirements + adversarial on fixed candidate; main adjudication/repair and affected verification; final fresh architecture on the complete repaired diff with prior reports/decisions.
10. **Acceptance evidence:** sibling browser-regressions.txt (11 suites), layout-boundaries.txt (9 widths), visual-scenes.txt (18 scenes + reduced motion), keyboard-and-pages.txt, static-checks.txt; node suite 70/70, lint/typecheck/build, locked workspace cargo check. Formal asset checks cover actual text/surface contrast, source/export agreement, preserved ICON fingerprints and all manifest hashes. Re-run affected checks after relevant repairs; unchanged checks remain valid. **Post-commit mandatory gate:** build scripts require clean committed source, so signed Universal2 build, notarization, model/identity/package checks, install/restart, preference comparison and native-window/entry proof occur after the source commit. They are still pending and block final `implemented`/completion; the pre-commit review must assess source readiness without pretending these native checks already happened.

Reports must cite concrete source lines, trigger, violated requirement, whether introduced/exposed, and the smallest affected verification. No edits during phase-1 review. No final completion claim until packaging/install proof is recorded.
