# GitHub updater Review Contract

- Mode: repair. Fresh-context, read-only reviewers; main agent adjudicates and edits.
- Requirement source: specs/prd/devplan_261102_github-updater.md, including the user's latest simplification: startup silently checks/downloads/verifies; only a green bottom-left sidebar「重启更新」button appears when ready; click installs/restarts directly, no modal and no network. Settings manual check remains.
- Baseline: eeef7110aa6d43051975b0da02f8f51eaacdc0a9 plus the pre-existing working-tree content saved in /tmp/loppi-updater-baseline. **Use /tmp/loppi-updater-review.diff for the task-only diff, not the entire git diff.** Exact in-scope files/hashes: /tmp/loppi-updater-review-files.json. New evidence documents are administrative.
- Out of scope: the many existing open-source/license/README/Windows/docs changes, including original edits already present in Cargo manifests and gui_lifecycle example. Do not read .env or any private key.
- Required guarantees: supported Mac ARM64/Intel and Windows x64; fixed HTTPS GitHub feed and release URLs; only newer versions; verification before readiness and shutdown; same verified version/bytes on click, no additional network; serialized operations; normal capture tail/Core shutdown and owner-lock wait before install; no force-kill, business DB writes, or recording-intent/config changes; shutdown failure never installs; install failure reopens GUI barrier and retains the ready update for retry. Windows installer keeps the existing prepare-install hooks. Published artifacts remain immutable. Final Mac App is signed/notarized/stapled before updater archive/signature generation. All three targets must validate before latest.json can be uploaded to an existing draft.
- Non-goals: silent installation, periodic polling, resumable download, durable pending-update store or cross-launch cache, delta updates, prerelease channels, private repository access, publishing or replacing current 0.1.18 or modifying the user's live installation/recording library.
- In-scope defects: introduced/materially amplified by updater integration and explicit guarantees above. Do not turn pre-existing unrelated issues or hypothetical stronger guarantees into blockers.
- Allowed mechanisms: Tauri updater plugin; single-flight native Update slot paired with a verified anonymous temporary file scoped to process lifetime (no idle installer buffer, no persistent store); reopen existing SESSION barrier after aborted installation; React presentation state; repository packaging/manifest/upload scripts. Reuse existing lifecycle owner and installer hooks.
- Required lenses: requirements + adversarial in parallel, then fresh final architecture after repairs.
- Evidence: updated Node interactive/signing/token tests pass (11); initial all Rust tests pass (426 total, existing opt-in ignored); final all verify + ARM development bundle running after the last UX revision; real browser shows exactly the green bottom-left button and direct busy state. Logs /tmp/loppi-updater-verify-sidebar.log and /tmp/loppi-updater-sidebar-build.log. Final lifecycle smoke will rebuild driver/Core with a common epoch (a prior independently built driver mismatched identity and is not claimed as a pass).
- Known required evidence gaps, to report accurately rather than fixing with production machinery: no Windows host available in this chat; no actual signed two-version Mac/Windows upgrade / production GitHub latest.json exercise yet. Devplan must remain in-progress and no implementation commit/release until mandatory platform evidence closes under start-dev. Architecture may judge the implementation while preserving that completion gate.
- Revalidation impact: UI -> type/lint/UI/token checks; native/lifecycle -> Rust/static + lifecycle smoke; packaging/manifests -> script/signature tests and affected bundle; only docs -> links/fact checks. Do not demand repeated unrelated costly checks.
