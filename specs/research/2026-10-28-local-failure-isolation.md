另有 1 次凌晨 orphan worker 崩溃：主线程非法访问时，另一线程在 exit/C++ 全局析构中。代码确认父进程看门狗在线程内调用 `std::process::exit`，存在可达并发析构风险。改为 `_exit`；同类采集/探测强制终止路径同步修正，正常收尾路径保持原语义。此项是基于栈和代码的根因判断；合成退出回归验证不再执行 atexit，不声称重演了历史内存损坏的每一步。

## 放大故障的调度 bug

`asr::settling_state` 把 failed 与 pending/processing 一起当成忙碌。总共 134 ms 的粗转尾段失败，阻塞了约 226 分钟的两场事件；截图中 17:49～21:16 的事件已有 949 条粗转、44,962 字，2,108 个保留原声文件均存在，却没有任何精转任务。

修复在现有 owner 内完成：worker 适配模型输入；Core 只等待可推进的工作；已有 ASR planner 使用保留原声；界面按范围与来源派生局部失败数。没有新队列、状态表、重试框架或采集后端。独立审查补出一个组合边界：第三次 VAD 被 Core 退出打断后恢复为 pending/3，仍会经前一块未决保留状态间接卡住事件；现有保留维护与领取条件对齐，只等待仍可推进的工作。生产恢复→维护→精转回归同时覆盖第二次仍等待、第三次解阻。历史失败记录继续保留，不通过清空失败或重传已付费任务制造成功。

- 合成调度回归：失败与耗尽尝试解阻；仍在处理/可重试待办继续等待；来源和下一事件边界隔离；无原声不能伪造转录成功；旧协议缺少新增字段可读取。
- 原生受控回调运行：NSError 整数透传、空来源 -3815、权限预检 stage 7；不启动采集。IPC 使用真实隔离 Core 验证读取超时、JSON、执行和写回故障及原请求 ID；日志无合成私密正文。

## 适用边界

本 PR 不安装/重启生产客户端，不修改活跃数据库，不自动补发云请求。升级后的现有自动队列会对已解阻且尚未规划的事件按原有配置继续处理；暂停和凭据限制仍有效。

系统睡眠无法持续采样，已有录音缺口不能补造；macOS 15 SCK 关屏/无显示器的可用性没有被本 PR 消除。上线前仍需在候选安装包执行权限、关屏/唤醒、正常停止封块检查；这是发行验收，不属于本次 PR 的安装授权。界面自动验证覆盖 React 渲染和状态语义，未进行安装版视觉验收。
