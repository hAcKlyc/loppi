调研 · 09-30 / 兔子概念 · 10-01

Mac：默认刘海，随时切换悬浮兔子

刘海模式仅在一侧出现兔子，另一侧留空。hover 后顶部兔子隐去，面板左侧是一只兔子，右侧按截图、重点、评论排列。hover 兔子出现暂停 / 播放遮罩。悬浮模式保留原交互：菜单向上展开，兔子点击标记重点、拖动移动。

Windows：只提供悬浮兔子

兔子本身就是入口，不加圆球、黑色底盘或录音灯。暂停时兔子睡着，入口仍在；悬浮位置不随状态变化。无刘海 Mac 在本原型中自动使用悬浮兔子。

状态兔子的样子操作板变化规则
正常倾听彩色兔子原地坐着，偶尔眨眼、耳朵轻动。notch 右侧为截图、重点、评论，暂停在兔子遮罩中；悬浮菜单保留原顺序。没有时长、波形或运行文案。安静 / 没人说话时仍是倾听，不跟随音量跳动。
主动暂停 / 尚未开始闭眼、耳朵放松，安静睡着；不飘 Z，不打呼动画。notch 的兔子遮罩变为播放；悬浮菜单顶部为继续 / 开始。暂停成功后才睡着。唤醒前不能假装正在听。
正在唤醒眼睛睁开，耳朵还没立起来。唤醒按钮短暂不可操作，其余现场动作仍可用。实际声源就绪后回到倾听；失败转到中断。
短暂重新连接睁眼等待，耳朵放低，停下正常微动作。轻量说明“正在重新连接”；可暂停。恢复后回到倾听；无法恢复时明确显示中断，不无限等待。
部分声源不可用仍醒着，一只耳朵低下来；一个静态小提示。写明哪路声音不可用，提供主窗口入口。只要部分仍工作，就不画成完全睡着；恢复后耳朵立起。
空间预警，尚未停止继续倾听；不反复闪烁、不弹出计量仪表。展开时显示“空间即将不足”，可打开主窗口清理。只有状态发生变化时提醒一次；因空间停止后转中断。
意外中断 / 空间耗尽醒着但耳朵垂下，静态小叹号；明显不同于主动睡觉。明确原因与处理动作；不能用正常倾听姿态报平安。故障消除后按现有服务规则恢复；容量暂停由用户明确继续。
重点 / 截图 / 评论成功notch 隐去并提示，随后恢复收起兔子；悬浮兔子耳朵短暂动一下，回到原姿态。notch 动作结束；悬浮菜单保留原交互。失败时说明原因并允许重试。临时反馈不改运行状态；云转录或整理队列也不改变兔子的倾听状态。
应用退出兔子随入口消失。没有操作板；应用重新启动后依据真实状态恢复。不留下仍在倾听的假象；此网页不模拟退出浏览器。

状态优先表达实际采集能力：意外中断、等待、部分可用、正常倾听和主动暂停应可区分。减少动态效果时使用静态姿态；notch 展開后只有左侧一只兔子，顶部兔子不同时出现；动画不加快。右侧选择器是设计试验控件，不属于产品界面。

本质是一个原生悬浮窗口

MacBook 的刘海是一块物理遮挡，无法显示文字。常见产品用透明、无边框的置顶窗口在周围绘制黑色形状，收起时露出两侧状态，展开时向下生长。内容避开摄像头区域，所以看起来像刘海变成了一块面板。

我核对了 Boring Notch、Atoll 和 DynamicNotchKit 的窗口源码：它们使用 AppKit 的 NSPanel，内容与形状由 SwiftUI 绘制。圆角、宽高与内容透明度随状态一起动画；系统事件和应用数据决定显示什么。

建议先保留 loppi 的 Tauri + React

现有悬浮球已有透明置顶窗口、悬停展开和四个动作，可以复用。两种模式复用同一组角色状态和操作；Mac 的刘海定位与自由悬浮分别适配窗口位置。无需重写主应用。

  1. 原生层提供屏幕、刘海、安全区域和缩放信息。
  2. React 绘制收起、展开、反馈和异常状态。
  3. 沿用现有标记 / 截屏 / 暂停命令；评论可先打开现有主窗口。
  4. 补窗口焦点、命中区域和显示器变化处理。

推荐的交互约定

收起时仅出现一只彩色像素兔子，不显示时长、波形或“正在记录”。正常微动表达运行中的含义。notch 悬停 180 ms 展开，兔子移到左侧，右侧按截图、重点、评论排列；截图 / 重点完成后隐去并反馈，评论直接切输入框、聚焦、回车提交后隐去。悬浮菜单向上展开，从上到下暂停/继续、评论、截屏；点击兔子标记重点、拖动移动。移出或键盘焦点离开后延迟收起，Esc 收起。眨眼和耳朵轻动采用低频节奏，不跟随声音大小跳动；暂停与故障不能继续使用正常姿态。

Mac 默认使用刘海单侧兔子，面板沿顶部中心向下展开；可切到悬浮兔子。Windows 仅使用悬浮兔子，无刘海 Mac 在原型中同样使用悬浮兔子；位置避开任务栏并可拖动。

上线前必须验证的原生行为

① 用 NSScreen.safeAreaInsets 与左右辅助区域获取刘海尺寸，处理多屏、显示器断开和缩放。② 常驻窗口不抢前台应用焦点；只有文字输入进入可聚焦状态。③ 收起时原生窗口缩到可见区域，圆角与透明边缘另做命中处理。

④ 全屏应用与自动隐藏菜单栏采用明确策略并实机测试。⑤ 标记与截图成功才反馈；截图时避开 loppi 自身窗口。⑥ 容量暂停不能显示为正常记录，空间恢复后由用户明确继续。

现有代码对应关系，以及这个演示的边界

src-tauri/src/lib.rs 创建了 68 × 68 的透明置顶窗口；src/FloatingWidget.tsx 在展开时调整为 132 × 246，按缩放因子改变位置，并调用现有核心命令。改成顶部入口时应把“右下角锚点”改成“顶部中心锚点”，不能直接搬用原来的坐标增量。

当前悬浮球每 5 秒读取状态。实际灵动岛可通过事件推送加动作后的刷新缩短状态延迟；角色动画节奏与音量、录制时长分开；真实运行状态决定角色姿态。先以 Tauri 做窗口原型；若菜单栏 / 全屏 / 非激活窗口行为不足，再由 macOS 的 NSPanel 适配层承载 WebView，或用原生 SwiftUI 画岛。

本页只验证外观、状态和网页内交互。截屏、记录、打开主窗口均为模拟，未连接音频服务。主动暂停时睡着已确认；部分声源、重新连接与异常时的姿态是本轮状态设计提案。notch 评论已确定为直接切输入框并回车提交；悬浮评论仍模拟打开主窗口现场笔记。全屏选项是视觉场景，不能证明系统全屏窗口兼容。当前 loppi 原生音频、权限和构建链路以 macOS 为主，Windows 悬浮兔子展示不代表整套录制服务已经跨平台。
